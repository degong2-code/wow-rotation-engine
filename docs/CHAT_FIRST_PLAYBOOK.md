## 0. 모든 작업의 방향 점검 — 교본 제품 중심 (2026-11-13 사용자 확정)

**최상위 정본:** [QUALITY_FIRST_POLICY §0](QUALITY_FIRST_POLICY.md). 새 채팅과 후속 개발은 **개별 결함의 상세 검사보다 어떤 전문화에도 반복 적용되는 완성 교본 제작 흐름**에 먼저 연결한다.

작업 시작 시 **한 문장으로** “최종 교본에서 어떤 누락·잘못된 판단·설명·UX가 개선되는가?”를 설명한다. 이어 **기존 자산으로 해결 가능한가**, **다른 전문화에도 발생하는 동일한 근본 원인인가**, **이번 변경으로 실제 교본 제작 단계가 전진하는가**를 판단한다. 중요 조건의 정확성을 검증하는 조사라면 진행하되, 답이 REVIEW이거나 한 전문화에 국한된 사례이면 새 엔진·검사기·스키마를 자동 증설하지 않는다.

**기본 경로:** 원문 완전 수집 → 게임 판단의 상태·조건·행동·예외 추출 → V11 이상 한국어 단일 HTML **실제 집필/수정** → Q0–Q4·다전문화 정상/실패 대조 → 사용자 전달·피드백. **검사기 개발만 계속하며 결과 교본을 제작하지 않는 작업 흐름을 정상 완료로 취급하지 않는다.** 단, 게임플레이 핵심 근거가 없어 Q0/Q1 REVIEW라면 추측해 HTML을 확정하는 대신 검증된 범위만 전달한다.

**성과 판단:** CI/테스트 수·도구량·원문 마커 수·서류 분량 대신, **독자가 실제로 언제/왜 어떤 기술을 쓸지 정확히 판단할 수 있는가, 신규 전문화에서도 반복할 수 있는가**를 증거로 삼는다.

## B.1. 작성 순서의 정본 — 원문 판정 규칙부터 추출

**실패한 교본의 재제작 — 잘못된 기준본을 계승하지 않기 (2026-11-13):** 신규 전문화의 UI·독해 품질이 V11보다 낮다고 사용자가 평가한 경우, 기존 실패 파일의 본문·CSS·선택 UI를 **재배치해서 회복하려는 방식은 기본 경로로 사용하지 않는다**. **해당 패치 기준 원문을 재취득하고 원문 상태·조건·우선순위·오프너를 새로 집필**한 뒤, 성공을 확인한 **다른 V11 정상 전문화의 시각적 문법**(첫 화면 2열 요약, 상세 3열 우선순위, 공개 이유/선택적 `?`, 시간순 오프너)을 표현 기준으로 적용한다. 종전 산출물은 결과 비교 및 회귀 반례로만 쓰며 데이터 추출 정본으로 쓰지 않는다. **원문 미확보 선택형 분기를 기존 HTML에서 그대로 복사해 충당하지 않는다.** 실제 [고양 제로베이스 재집필 실증](ENHANCEMENT_ZERO_BASE_CREATE_REVIEW_20261113.md)에서 기존 V3.13·후속 Cross-spec HTML을 내용 입력으로 사용하지 않고 Wowhead 12.1.5 색인에서 43개 우선순위 및 4개 확인 가능한 오프너를 새로 집필, 비전/V11 동일 표 문법으로 비공개 8전문화 HTML 제작(7/7 바이트 보존, PC·모바일 기능 PASS). 숨김 옵션/개별 도구 설명의 원본 검증은 별개 Q0/Q1 REVIEW. **사용자 만족도 Q3는 승인 전임**.


**[EDITORIAL_QUALITY_PROTOCOL](EDITORIAL_QUALITY_PROTOCOL.md)**의 Gate A~G는 필요한 품질 관점을 제공한다. **모든 작업에 같은 양의 조사·표·테스트·문서를 생산한다는 뜻이 아니다.** CREATE/대규모 UPDATE에서는 전체에 적용하고, 단일 설명·근거 확인은 관련 게이트만 깊게 적용한다. 기존 7개 V11은 정상 대조군으로 참고하되 형태를 베끼지 않는다.

**우선 고정할 것:** 기준 패치·기준 자료 1개(사용자 지정 우선, 없으면 Wowhead)·특성 빌드·영웅 특성·단일/광역 상황. 그 뒤 반드시 `상태 → 수치/발동 조건 → 다음 행동 → 이유 → 예외 → 실제 출처`를 추출한다. 이 목록을 만들기 전에는 HTML 표·장 수를 설계하지 않는다.

우선순위는 기본적으로 **순위 / 행동 / 사용 조건**을 별개 열로 둔다. 모호한 `상황에 따라` 문장은 어떤 스택·특성·초·거리·자원에서 어떤 행동으로 바뀌는지 설명하지 못하면 삭제 또는 보류한다. 오프너/지속 딜과 선택 특성 ON/OFF의 **반례 테스트**도 먼저 수행한다.

기준 원문에서 게임 조건의 핵심이 설명되지 않았다면 *기존 부실한 초안*에 의지하거나 다른 버전의 설명을 조합해 미확인 로직을 만들어서는 안 된다. **우선 Wowhead 같은 페이지의 인접 설명을 확인하고, 해결되지 않으면 그 쟁점에 한해서 보조 공략을 대조한다.** 끝내 불확실하면 해당 판단만 보류한다.


**선택 상태 누락 감사 보조:** [SOURCE_COVERAGE_AUDIT](SOURCE_COVERAGE_AUDIT.md)의 공통 오프라인 검사기는 신규 전문화에도 적용되는 **선택 경로/본문 누락 후보** 검증 도구다. 교본 집필을 고정 JSON 생성기에 종속시키지 않으며, 실제 원문의 모든 UI를 발견했다고 자동으로 선언하지 않는다. **본문 확보 Gate A, 게임 의미 Q0/Q1, HTML 동작 Q4는 구분**한다. 고양에서 발견한 실패는 다른 전문화에서도 재현하는 합성 반례로 전이하고, 의미가 다른 기술 운용 규칙은 복사하지 않는다.

### B.1.1. 원문 판단 규칙 → ST/AoE·영웅별 출력표 의미 보존 (2026-11-13)

**현재 구조적 대책:** [SOURCE_TO_GUIDE_PROJECTION_CONTRACT_20261113](SOURCE_TO_GUIDE_PROJECTION_CONTRACT_20261113.md). 비전 12.1.5 사례에서 원문 통합 규칙을 4개 우선순위표로 AI가 재기술해 **충전물 3개 미만→0, 특정 특성 행 누락, 대상 조건 축약, 중복**을 일으켰다. **원문에 근거한 단일 규칙 집합(고유 ID·원래 순위·적용 범위·조건식·행동·이유·예외·증거)**을 먼저 만들고, 같은 ID와 조건을 **재작성하지 않고 그대로 투영**해 각 표의 행을 생성하는 것이 재발 방지의 핵심이다.

- **현재 구현:** 기존 `engine/gameplay_decision_qa.py`의 `project_priority_view`·`audit_priority_view`가 영웅/대상 수 범위에 대한 보수적 추출, 임계값·행동·순서·출처 ID 무단 변경/누락/중복 대조를 지원. 기존 6개 합성 회귀에서 비전 실패형과 다른 전문화 정상형을 구분. 검증 함수의 통과 ≠ 원문 추출의 사실 정확성, HTML 실제 사용성, 전체 게임 Q0/Q1 승인.
- **실제 생성 경로 연결(2026-11-13):** [SOURCE_TO_GUIDE_PROJECTION_CONTRACT_20261113 §0](SOURCE_TO_GUIDE_PROJECTION_CONTRACT_20261113.md). 기존 `engine/v2/create_guide.py`의 선택적 `canonical_priority_rules` 입력이 `project_priority_view` 출력 자체를 실제 4개 표의 행으로 사용하도록 수정. `when_any`는 OR(AND 조건들) 구조를 그대로 보존하고 원문 행 ID·순위·조건·이유·참고를 전달한다. 규칙을 바꾸는 경우 재생성 비교에서 실패하며 **예전 수기 행 번호에 묶인 `?`를 새 표에 그대로 붙이지 않는다**. 이 신규 경로를 쓰지 않는 옛 비전 34행 데이터는 여전히 미승인 legacy 초안이다. 실제 12.1.5 색인 10+9 통합 규칙을 가지고 만든 **새 비공개 8전문화 HTML**에서 4표 36행·12개 상태 판단·기존 V11 7/7 보존·PC/모바일 UI를 확인. 다만 직접 열람 12.0.7과 검색 색인 12.1.5의 차이·원시 WHML 모든 숨김 조건 미확정으로 **Q0/Q1 REVIEW**. 실제 교본 생성 완료를 원문 게임 사실 전체 승인으로 격상하지 않는다.
- **출처 혼합 방지:** 비전 CREATE 코드에서 최소 2개 출처를 강제하던 과거 제약을 **최소 1개 기준 출처**로 바로잡음. 타 사이트는 패치/빌드/문맥이 맞는지 해당 쟁점에 필요한 경우만 활용; 단순 출처 개수 채우기 금지.

## B.2. 작업 규모에 따른 품질 검증 — 기본 경로와 예외 경로

**기본 경로(CREATE 또는 실제 필요한 UPDATE):** Wowhead의 모든 유효 분기(영웅/전투·오프너(물약 사용 슬롯 포함)/쿨다운·Notes/접힘·관련 `?`)의 **실제 본문을 전수 수집**하고, 표시되는 탭·섹션·표·행·옆 기술·주변 문맥을 가능한 만큼 기록한다 → ChatGPT가 상태·조건·행동·이유·예외를 의미 분석한다 → 적용 대상이 모호하거나 판단이 달라지는 경우에만 정확한 원본 관계를 재검증한다 → 교본 구성 → Q0/Q1 의미 QA → HTML 변경 시 Q4 비대상 보존·UI QA. **본문 누락 Gate A와 의미 미확정 Q0/Q1을 구별한다.**

**예외 경로(작은 사실·문장·특정 규칙 확인):** 실제 쟁점의 범위만 확인한다. 원문 문맥 → 필요한 경우 다른 공략 해당 부분 → 적용 패치/영웅/빌드 구분 → 수정 또는 검토 보류. 새 스키마·전체 전문화 재작성·고정 개수 반례를 만들지 않는다. **의미가 바뀐 경우** 요약·상세·오프너/팁 등 관련 표현만 연쇄 확인한다.

**공통 실패 원인 경로:** 생존 V1/V2처럼 정보 추출 방식 자체가 조건을 지우거나 오류가 여러 장에 반복된다면, 그때만 원인 단계와 영향을 받는 범위를 확대 감사한다. 모든 작은 이슈를 동일한 대규모 감사로 격상하지 않는다.

**범용성 판단은 항상 하지만 작업은 비례시킨다:** 일회성인지, 기존 절차로 해결되는지, 다른 전문화에 전이되는 원인인지, 일반화할 때 정상 V11을 오탐하는지 짧게 평가한다. 일반화 가치가 없으면 **새 개발물 없이 끝내는 것도 성공**이다. 반복되는 근본 원인에 대해서만 [범용 사례집](QUALITY_GENERALIZATION_CASEBOOK.md)에 검증 근거를 축적한다. **합격표/절차 이행 자체가 품질 성과는 아니다.**

**동적 렌더링 원문 접근 가능 시:** [LIVE_DOM_CAPTURE](LIVE_DOM_CAPTURE.md)의 범용 브라우저 어댑터로 상위 선택 전환 뒤 새 하위 UI와 tooltip 본문을 확보한다. 별도 사용자 설치가 기본 조건이 아니며, 실제 접근 가능한 실행 환경에서만 보조로 사용한다. 수집 경로 제한·버전 충돌·미방문 경로를 숨기지 않는다.

**구조 후보 → 수집 기록 대조(범용):** 실제 HTML을 확보했다면 `engine.source_structure`로 숨김 패널/팁 후보를 발견하고, `engine.source_reconcile`로 `engine.source_coverage` 관측 기록과 대조한다. **발견된 후보를 빠뜨렸다면 본문 수집 후보로 복구**, 관련 없는 UI라면 이유를 기록해 제외한다. 동일한 설명의 숨김 DOM 본문·트리거를 중복 계수하지 않으며 `tooltip2`처럼 한 트리거에 설명이 여러 개인 경우는 독립 확인한다. 이 단계의 코드 성공은 사이트 전수 확보나 의미 정확성을 증명하지 않는다.

**범용 실증(2026-11-12):** [냉기 마법사·생존 사냥꾼·징벌 성기사의 원문 선택 구조 대조](CROSS_SPEC_SOURCE_VALIDATION_20261112.md)를 신규 전문화 검증 반례로 추가했다. `source_structure.source_sha256`과 관측 기록의 `html_sha256`, URL·패치·수정본 일치 없이 후보 연결을 승인하지 않는다. 검색 색인만 확보한 경우 원본 DOM·툴팁 전수 증명이라고 승격하지 않는다. 공개 출력에는 섹션 문구·선택항목을 해시/DOM 좌표로 보존한다.

## C. 소스 조사 — 한번의 전문화 명령 이후 자동 처리

1. 요청 날짜와 게임 버전, 전문화/영웅 특성/난이도를 확인. 현재 패치가 특정 문서의 옛 패치와 같다고 가정하지 않는다.
2. 사용자가 공략 URL/원문을 제공하면 우선하고, 아니면 최신 버전의 Wowhead 단일 기준 공략을 사용한다. [SOURCE_ACQUISITION](SOURCE_ACQUISITION.md)에 따라 모든 유효한 관련 선택형·접힘·hover·타임라인 **본문**을 확보한다. 모든 관련 `?`의 내용과 가능한 위치·주변 맥락을 기록하며 정확한 행 ID 연결을 일괄 강제하지 않는다. 해석이 모호해 중요한 행동이 달라질 때만 관련 관계를 재확인한다.
3. **다른 사이트는 필수 아님.** 기준 원문의 특정 조건이 불명확·누락·상충하거나 최신 변경에 의문이 있을 때 **그 쟁점만** 보조 확인한다. 사이트 수를 채우기 위해 여러 로테이션을 섞지 않는다. 서로 다른 URL이 독립 근거라는 보장도 없다. 공식 패치/주문 데이터로 기술 유효성을 별도 점검한다.
4. 기계적인 최신성만으로 순위 확정 금지: 일부 문서는 '쉬운 회전/간편판'과 '상세 우선순위', 시즌 세트·특성·광역 상황이 서로 다를 수 있다. 각 조건이 어떤 빌드에 해당하는지 직접 확인한다.
5. 주문/버프·영웅 특성 식별: 게임 공식/신뢰 소스의 ID·한국어 명칭·이미지 및 발동 조건을 검증. **ID를 추측하지 않는다**.
6. 복제 가능한 외부 자료의 이용 권한을 확인. 저장소에는 **공략 제목/URL/확인 일자/검토 지표**만 보관하고, 장문 원문·번역문은 공개하지 않는다.

## D. ChatGPT 집필 기준 — 기존 7개 V11을 교본 품질 기준으로 삼는다

단순 우선순위 표 출력은 **불합격**. 해당 전문화에서 실제로 필요한 항목을 충분히 다룬다.

- 특성 선택/빌드 분기, 영웅 특성 차이와 스펙의 핵심 메커니즘을 원인→발동→행동→예외 흐름으로 설명.
- 입문자용 요약/심화 차이를 구분하고, 중요한 주문과 버프의 역할·활성 조건·상호작용, 단일/광역 우선순위를 이해 가능한 표로 작성.
- 쿨다운·오프너·자원/중첩 운용, 사용 전후 판단, 예외 처리, 구간·대상 수·세트 효과에 따른 조건 변화.
- 기존 V11의 장/헤더, 기술 아이콘·툴팁, 문맥별 내부 기술 링크, `?` 추가 원리, `!` 주의사항, 비교표·흐름도·용어집을 **내용상 필요한 위치**에 재사용.
- 장 개수·총 글자 수를 맞추기 위해 단순 반복/불필요한 빈 항목을 추가하지 않는다. V11의 맥락·설명 밀도를 따라가는 것이 기준.
- 확인되지 않은 실전 조건은 위험성이 드러나게 표시. 임의로 거짓 확신의 문장을 쓰지 않는다.

**비전 필수 교훈:** 자동 생성 초안의 스타일·설명량을 복사하면 V11의 원본 7개보다 품질이 떨어질 수 있다. 비전 기존 JSON은 기초·검토 목록으로만 사용하고, V11 품질과 실제 출처를 재대조하며 **실질적으로 재집필할 수 있다**.

## E. HTML 생성/수정

**제작 기준본 선택을 먼저 확정 (2026-11-13 사용자 재평가):** 신규 CREATE 또는 기존 결과의 구조·가독성 반려 후 재작성에서는 **이전 실패 교본을 기초로 보완하지 않는다**. (a) **콘텐츠 기준 = 현 패치의 단일 최신 원문**, (b) **화면 기준 = 정상 V11 + 비전/제로베이스 고양에서 실제 긍정 평가를 받은 정보 위계**, (c) **실패본 = 전후 비교·반례만**으로 역할 분리. 이미 승인된 정상 교본의 UPDATE는 예외로 기존 제품을 보존하고 원문 변화만 반영한다. 이전 미승인 HTML·JSON의 존재, 테스트 PASS 또는 최신 파일명만으로 콘텐츠/디자인 기준본이 될 수 없다. 세부 정본은 [QUALITY_FIRST_POLICY §5.1](QUALITY_FIRST_POLICY.md).

**실행 경로의 안전 장치:** `engine.v2.create_guide` 실행은 더 이상 과거 `content/new_guides/arcane.json`을 기본값으로 쓰지 않고 `--draft`를 명시해야 한다. **이 Arcane 시범 생성기 경로로 제작할 때** `canonical_priority_rules`가 있는 근거 기반 초안만 허용한다(모든 전문화를 JSON 생성기에 종속시키는 규정이 아님). 종전 수기 초안은 **`--legacy-review-only`를 명시한 역사적 비교용**이며 이 모드의 결과는 제품 승인·기준본 승격 금지. 내부 합성 테스트에서 과거 draft 입력을 허용하는 것은 제품 제작 경로의 사용 허가가 아니다. 이 검증은 원문 의미의 진실성(Q0/Q1)을 대체하지 않는다.


CREATE:
- V11의 기존 `manual-view` 7개를 변경하지 않고 신규 전문화만 확장. UI 메뉴/장 탐색, 영웅 특성 전환, 우선순위, tooltip, `?`/`!` 기능 재사용.

## E.1. 왼쪽 메뉴 접기/펼치기 — 재사용 UI 원칙

2026-11-11 생존 사냥꾼 CREATE 과정에서 원래 V11 왼쪽 목록을 2단으로 개선했다. 이후 교본에서 **직업 상위 메뉴를 클릭하면 전문화 목록**, **전문화를 클릭하면 영웅 특성 버튼 목록**을 각각 접거나 펼칠 수 있어야 한다. 구현은 진짜 `button`과 `aria-expanded`/`aria-controls`, `hidden`을 사용하고 포커스·Enter/Space·선택된 전문화 자동 펼침 및 URL 목차 복원을 지원한다.

기본 화면은 첫 선택 교본이 있는 마법사/화염 목록만 열린 상태이며, 다른 직업은 접어 공간을 절약한다. 사용자는 언제든 임의의 직업이나 전문화만 펼칠 수 있다. 신규 전문화는 기존 직업 그룹 내부에 추가해야 한다. 직업/전문화 토글은 한국어명과 짧은 영문명을 같은 줄에 표시하고 모바일에서는 필요하면 영문명을 숨긴다. 불필요한 세로 패딩·block 자식 스타일을 제거해 직업 추가 시에도 읽기 쉬운 메뉴 밀도를 유지한다. 징벌 V2에서 PC 직업 토글 높이 약 72.7px→30px, 모바일 35px→30px 확인(이 숫자 자체는 고정 규격이 아님). 기존 7개 전문화의 실제 교본 `manual-view` 본문을 재직렬화·덮어쓰기 하지 않는다.

테스트·근거·개인 출력 해시: [생존 제작 실작업 기록](CHAT_FIRST_RUN_SURVIVAL_20261111.md).

## E.2. ‘한눈에 보는 딜사이클’ — 실전형 요약과 유연한 정보 설계

**오프너/물약 최신 공통 원칙(실물 HTML 대조 2026-11-12):** 물약 선택을 **무조건 무시하거나 모든 전문화에서 무조건 분기하지 않는다**. 실제 원본의 `display-option` 및 `display-options` 조건을 분석해 물약 선택이 **시전 순서·사용 시점·선시전 여부**를 바꿀 때만 해당 오프너를 분기한다. 고양 12.1.5에서는 실제로 4개 영웅×전투 오프너 × 물약 3개 = 12개 유효 선택을 구별한다. 다른 전문화에 일괄 적용하지 않는다. 물약 3개를 하나의 오프너에서 연이어 사용하게 만드는 오류는 계속 방지한다. 근거: [고양 사용자 저장 원문 감사](ENHANCEMENT_SAVED_HTML_EVIDENCE_20261112.md).

기존 V11의 목표는 `단일 지속 딜 / 광역 지속 딜 / 단일 오프너 / 광역 오프너 / 가장 중요한 예외`를 보고 **다음 스킬을 선택할 수 있는 것**이다. 그 아래에는 짧은 **핵심 운용 원칙**을 배치한다. 영웅 특성이 다른 운용을 요구하면 각각 따로 보여준다.

**형식은 유연하다.** 5행 표는 유용한 예시일 뿐 고정 스키마/행 수가 아니다. 실제 메커니즘을 더 이해하기 쉽게 만드는 흐름도, 임계값 비교표, 양쪽 특성 비교, 팁 레이어를 제안할 수 있다. 고정 장 수·텍스트 길이·표 개수 때문에 실제 조건을 줄이거나 일반화하면 실패다.

표 안에 사용자 결정을 바꾸는 조건과 정확한 숫자를 반드시 넣는다. **기본 판단 이유는 조건 바로 아래 상시 표시**하고, `?`에는 특수 상황·드문 예외·심화 운용 팁만 **필요할 때** 추가한다. `!`에는 특성·패치 차이에 따른 실제 주의사항을 넣되 다음 행동을 결정하는 필수 조건을 숨기지 않는다. 지속 딜 우선순위와 시전 순서가 정해진 오프너는 구분하고, 오프너의 조건이 본 우선순위와 모순되지 않는지 검사한다.

### 콘텐츠 품질 확인

**표 내용 자체의 독해 역할 검사:** 단순히 `?`에서 뺀다고 기본 이유가 되는 것은 아니다. `특성 없으면 생략`은 조건, `충전물 4개 권장`은 참고, `괄호 내 OR`는 논리식 해설이다. 설명을 조건/목적·인과/주의·전제/선택적 심화로 분류하여 역할이 맞는 곳에 배치한다. **게임 원인 근거가 없으면 채우기 위해 창작하지 않고 REVIEW**. 실제 예시는 [V11_FIDELITY](V11_FIDELITY.md)의 `우선순위표의 정보 역할`에 기록.

**우선순위표의 `?` 의미(2026-11-13 사용자 피드백):** [V11_FIDELITY](V11_FIDELITY.md)의 **우선순위표 정보 역할** 적용. 순위/행동/조건을 보면서 **기본 판단 이유도 바로 보여준다**(조건 아래 짧은 보조 텍스트 등). `?`는 모든 행의 '왜 사용하는가'를 보관하는 곳이 아니라 실제로 필요한 **특수 상황·드문 예외·고급 팁의 선택적 추가 설명**이다. 기술 자체의 용어 설명 툴팁과 구별한다. **다음 GCD를 바꾸는 필수 예외는 `?` 안에만 숨기지 않는다.** 추가 열/툴팁 수를 고정하지 않으며 모바일 표 밀도를 실제로 비교한다.

**시각·구조 품질 상위 규칙(2026-11-13 사용자 직접 화면 비교):** [V11_FIDELITY — 시각적 의미 계약](V11_FIDELITY.md#시각적-의미-계약--생성-시-결과물의-디자인-회귀-방지-2026-11-13-사용자-피드백) 적용. **조건부터 추출하는 내용 설계와, 실제 화면을 읽기 좋게 만드는 표현 설계를 별개 단계로 분리**한다. 고양 한 개 표를 V11처럼 덧칠하는 게 목표가 아니다. 새 전문화 전체에서 **요약/오프너/우선순위/심화의 시각 문법과 정보 위계**가 V11 정상 전문화 3종 이상과 동등하거나 더 나은지 확인한다. 카드·문장·선택 패널로 바꾼다면 실제 판단·비교가 개선되는 근거가 있어야 한다. Q3 화면 평가를 DOM 클래스·CSS 재사용 수·JS PASS·바이트 보존 검사로 대체하지 않는다. **원문 조건에 맞춰 형식을 유연하게 선택하되, 시각적 일관성과 조건 보존은 항상 유지**한다. 사용자 스크린샷은 공개 GitHub에 보관하지 않는다.

**실제 교본 V3.14 재검증에서 확인한 공통 원칙:** 서로 다른 물약·빌드 오프너처럼 **서로 동시에 선택할 수 없는 행동 경로는 UI도 하나만 펼쳐지도록** 한다. 선택지를 모두 보여 주는 것만으로 Q3 PASS가 아니다. 또한 짧게 재집필할 때 **중첩당 수치·지속시간·중첩 상한·행동이 바뀌는 조건의 삭제**를 금지한다. 축약 전 원문·이전 정상 교본과 대조해 단순 설명으로 대체된 판단 변수를 복원한다. 이 두 검토는 [고양 V3.12→V3.14 실제 HTML 수리](END_TO_END_ENHANCEMENT_REAUTHOR_V312_20261113.md)의 재발 방지 **편집 지침**이며, 전문화별 새 검사기나 일률적인 표 개수 강제가 아니다.

**실제 V11↔고양 V3.11 교본 감사(2026-11-13):** [독자용 편집 감사](END_TO_END_READER_EDITORIAL_AUDIT_20261113.md). **교본 본문과 개발 검증 기록을 분리한다.** 독자용 단일 HTML에는 실제 다음 기술 결정에 필요한 임계값·조건·기술 순서·원리·예외와 간결한 근거/미확정 주의만 배치한다. 원문 취득 경위, 실패한 과거 초안, 내부 QA 사례 ID, 15개씩 늘어선 편집자 상태 테스트, CI PASS 근거 등은 **개발 감사 문서**에 보존한다. **개발 정보의 분리는 게임의 중요한 조건·숫자·미해결 예외를 삭제하는 것이 아니다.** 변경 후 요약·4개 우선순위·실제 오프너 조건 보존 여부와 기존 V11 바이트 동등성을 별도로 확인한다. 테스트 수가 많아졌다는 이유로 플레이어 본문을 늘리지 않는다.

검증 범위는 [B.2](#b2-작업-규모에-따른-품질-검증--기본-경로와-예외-경로)와 [EDITORIAL_QUALITY_PROTOCOL](EDITORIAL_QUALITY_PROTOCOL.md)의 Q0~Q4 기준을 따른다. 요약·상세·오프너·심화의 **조건 손실만 실제 관련 범위에서** 추적하고, 내용의 의미 정확성과 HTML 기능 PASS를 혼동하지 않는다.

사례: [생존 V3 재작성 및 7개 전문화 비교](CHAT_FIRST_RUN_SURVIVAL_V3_20261111.md). 후속 **V3.1 별도 개인 검토본은 정본 미승인**이며, V2의 첫 장만 고친 버전과 구분한다.
