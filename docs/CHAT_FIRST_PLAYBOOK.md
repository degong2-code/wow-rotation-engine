> **현행 운영 지침 | 2026-11-17 구조 정비.** 본 문서는 *실제로 따라야 하는 작업 순서*만 기록한다. 동일 이슈의 버전별 해설은 여기에 계속 추가하지 않는다.
> 원본 상세 절차·실패 사례는 [정비 이전 이력](https://github.com/degong2-code/wow-rotation-engine/blob/e3416fc9643f2108187648c356d776115e5cda82/docs/CHAT_FIRST_PLAYBOOK.md)과 [사례집](QUALITY_GENERALIZATION_CASEBOOK.md)에 보존. **옛 문구가 현행 규칙보다 우선하지 않는다.**

## 0. 시작: 현재 제품과 기준 확보

1. [PROJECT_CANON](PROJECT_CANON.md)의 제품 정의, [QUALITY_FIRST_POLICY](QUALITY_FIRST_POLICY.md)의 최상위 원칙, [CURRENT_STATE](CURRENT_STATE.md)의 **현재 제품·REVIEW·다음 우선과제** 확인.
2. GitHub 실제 **PR/head/base/CI**를 조회. 사용하려는 개인 HTML의 Library ID·크기·SHA-256을 실제 파일로 검증. **파일명/과거 메모만으로 실물 접근을 주장하지 않는다.**
3. 요청이 **CREATE**, 기존 전문화 **UPDATE**, 기존 V11 내용과 독립 비교하는 **제로베이스 실험**, 또는 **읽기 전용 복원**인지 구분. 읽기 전용이면 변경하지 않고 보고. 전문화명만 주어지면 제작을 진행한다.
4. 이번 작업으로 개선할 **실제 독자의 다음 기술 선택 또는 사용성**을 한 문장으로 명시. 도구·문서·검사기 자체를 성과로 삼지 않는다.

## 1. 콘텐츠: 원문 확보 → 게임 판단 → 집필

**Gate A — 기준 공략 확보**
- 사용자 지정 원문 우선. 없으면 해당 패치·전문화·빌드의 와우헤드 공략 **하나를 편집 기준**으로 삼는다. 다른 공략은 필요한 쟁점만 교차 확인하며 우선순위를 섞지 않는다.
- 패치·업데이트일, 영웅 특성·대상 수·빌드/선택 특성·물약/소비재, 접힌 설명·전환 탭·관련 `?`/hover 본문, 지속 딜/오프너의 실제 분기를 확보한다. 추가 선택 후 생기는 하위 항목도 확인한다.
- 물약/장신구의 사용 순서·시점이 **실제로 달라질 때만** 오프너를 분기하며, 연달아 서로 다른 물약을 쓰는 허구의 순서를 만들지 않는다. 자동 수집이 403/429면 우회하지 않고 정상 접근·저장 HTML·사용자 제공 경로를 활용한다. 확보가 불완전하면 범위를 한정해 REVIEW.
- 상세 수집법: [SOURCE_ACQUISITION](SOURCE_ACQUISITION.md).

**Q0/Q1 — 의미 관계를 먼저 확정**
- HTML 표나 장 수를 정하기 전에 **상태 → 실제 다음 행동을 바꾸는 조건(AND/OR·수치·예외) → 우선순위 행동 → 이유**를 독립적으로 추출한다.
- 같은 기술이 두 행에서 나타나도 조건이 각각 다르면 무조건 합치지 않는다. 서로 인접하고 동일한 행동일 때에만 OR로 정확하게 병합할 수 있다. 상위 기술이 처리하는 전제나 기술 자체로 증명되는 발동·선택 조건은 반복하지 않는다.
- `사용 가능할 때`, `상위 조건 없음`, 미정의 `강화 창` 같은 문구는 제거. 그러나 실제 결정을 바꾸는 2명↑/3중첩/≤4.5초/특성 분기/쿨 정렬·보류는 보존. 동시 충족은 `/` 또는 `그리고`, 대안은 `또는`; 사용자 화면에서 `∧`/`∨`/내부 영어 키 금지.
- 기준 원문에 근거하지 않은 수치·행동·공식 명칭·아이콘은 창작하지 않는다. 해석 귀속이 모호한 특정 부분만 REVIEW로 둔다. 게임 상태 반례로 우선순위 충돌·경계값·영웅 선택을 내부 점검한다.

**Q2 — 실제 교본 원고**
- **한눈에 보는 딜사이클**만 읽고도 단일/광역 지속 딜, 해당 오프너 시전 순서, 핵심 자원·쿨다운 및 실제 선택을 바꾸는 심화 예외를 판단할 수 있어야 한다. 빠른 참조는 **상세 우선순위 집필 후** 같은 조건과 순서에서 구성한다.
- 전체 장을 쓴 **마지막에 역방향 검수**: 상세·심화·발동·쿨다운 설명에서 다음 기술이 달라지는 조건을 빠른 참조의 해당 행동 또는 핵심 원리에 반영했는가? 모든 고급 팁을 첫 화면에 옮기지는 않는다.
- 지속 딜의 `→`는 **우선순위**, 오프너의 `→`는 **실제 시전 순서**. 공식 한국어 기술/효과명과 확인된 아이콘·툴팁을 사용. 조건은 `(괄호 + 작은 글씨 + 낮은 명도)`, 기술은 `아이콘 + 굵은 기술명`으로 구분.
- 간결하고 중복 없는 이유를 본문에 배치. `?`는 예외·심화용. 과도한 박스·장식·일반 경고·메타데이터·가상 실전 사례 독립 장 금지. 표/장 수·영웅 분기의 수는 고정하지 않는다.

## 2. UI: 처음부터 통합할 수 있는 독립 교본

- **게임 내용을 제로베이스로 집필하는 것과 UI를 매번 새로 설계하는 것을 혼동하지 않는다.**
- 독립 CREATE는 최신 통합 REVIEW에서 **사용자에게 긍정 평가된 화면 문법**(섹션 번호·전투 유형별 표·기술/조건·메뉴/영웅 전환·툴팁·모바일)을 실제 HTML/CSS 구조로 재사용하는 것을 기본으로 한다. 새 UI 구성은 **의도된 비교 실험**으로 표시하고 사용자 승인 전 확정하지 않는다.
- 화면은 기존 통합 독해 폭 **약 850px**에서 먼저 확인. 우선순위는 `전투 | 조건별 기술 우선순위` 형태의 전폭 행을 기본 고려하며, 전투 유형을 좁은 2열에 과밀 배치하지 않는다. **필요 시 다른 표 구조도 허용**하되 Q3 비교 근거가 있어야 한다.
- `→ + 아이콘 + 기술명`은 분리되지 않게 하되, **긴 괄호 조건은 독립적으로 자연 줄바꿈**한다. 빠른 흐름을 무조건 한 줄에 고정하지 않는다. 실제 기술·버프·발동을 표시하는 모든 위치에 확인된 해당 아이콘 연결. 누락은 임의 이미지로 대체하지 않는다.
- 독립 화면은 스코프된 전문화 모듈로 구성하고 통합 시 기존 `body/main/nav` CSS·동명 ID·스크립트가 타 전문화에 오염되지 않도록 한다. 통합 시 메뉴·현재 교본 목차·영웅 선택·툴팁·키보드 포커스·모바일 동작 확인. **개인 HTML 본문/저장 원문은 공개 GitHub에 절대 올리지 않는다.**
- **재사용 자산의 실물·경계:** 기존 `rotation_shared_ui_shell_v0_REVIEW.html`(개인 Library)은 **독립 시연용**이며 V83에 CSS 전체를 그대로 넣으면 Q3가 퇴보하고 냉기 독립 v3 전면 이식은 내용·툴팁·목차가 손실되므로 직접 통합용으로 사용하지 않는다. **현재 제한적 통합 시범**은 개인 Library `/ROTATION TEXTBOOK/rotation_shared_ui_bridge_v1.css` (`libfile_955399743bec8191a761d082bf689e26`, 1,441B, SHA `075e66d3d77093bd6bd2506cb7dc3b8b826ee1e3661f9e6a3b396e6518e7fba1`)와 `wow_rotation_v83_ui_bridge_v84_REVIEW.html` (`libfile_b5bd6a2d32388191b023496edac6b674`)이다. **원본 V83 콘텐츠·기존 JS/CSS 보존 + 공통 스타일 한 벌을 냉기·분노에 연결**한 UI REVIEW일 뿐, 사용자 Q3 또는 다른 전문화에 대한 채택은 아니다. 실제 파일·해시 재조회 후 필요할 때만 재사용한다.
- **검증된 스타일은 재사용하고, 개선은 교차 전문화 비교 후에만 승격한다.** 고통 V82의 시각적 성공은 사용자 가독성 호평이지 최종 전 제품 승인 아님. 냉기 독립 v1→v2는 기능 Q4가 통과했지만 고통 대비 Q3가 반려된 **음성 사례**. CSS 값 하나·가로 넘침 0건으로 Q3를 합격 처리하지 않는다. [기존 상세 반례](https://github.com/degong2-code/wow-rotation-engine/blob/e3416fc9643f2108187648c356d776115e5cda82/docs/CHAT_FIRST_PLAYBOOK.md).

## 3. 종료 게이트 — Q3와 Q4를 혼동하지 않는다

| 게이트 | 실제 확인 |
|---|---|
| Gate A | 패치/원문 선택·접힘·관련 hover·오프너 자료 범위와 누락 |
| Q0 | 공식 기술명·수치·원문 조건·출처 적합성 |
| Q1 | 상태→다음 기술, 우선순위·AND/OR·타이밍·예외, 요약↔상세 정합성 |
| Q2 | 원리·판단 이유와 심화 내용을 이해·응용 가능한가 |
| **Q3** | **기존 호평 교본과 같은 폭에서 첫 화면을 시각 비교**, 기술 흐름·정보 위계·행간·표의 읽기 순서, 모바일 정보 접근; 사용자 평가는 별도로 기록 |
| Q4 | 메뉴·영웅 전환·표/툴팁/아이콘 링크·JS·가로 넘침·PC/모바일·비대상 DOM/스크립트 보존 |

- Q3 비교는 **동일 PC 폭 및 320/390px** 실제 렌더링을 포함하고, 단지 표가 화면에 들어오는지만 확인하지 않는다. 실제 외부 아이콘 HTTP와 로컬 `file://`는 네트워크 차단 브라우저 시험으로 검증했다고 주장하지 않는다.
- Q4 CI/테스트 PASS, 사용자 일부 디자인 호평, 게임 Q0/Q1 정확성 및 전체 제품 승인은 **각각 별개**다.
- UPDATE는 게임 내용이 달라진 곳과 영향받는 첫 화면·툴팁만 수정하고 비대상 기존 전문화는 보존. UI-only 교정이라면 기존 판단·오프너·링크 변경 0을 확인한다.

## 4. 저장 및 유지보수 — 새 지침을 계속 덧붙이지 않는다

1. 실제 HTML을 단일 파일로 완성 → Library **새 버전** 저장 → 파일 크기·SHA-256·Library ID 재검증 → 변경 범위·Gate A/Q0~Q4·남은 REVIEW 보고. 공개 GitHub/원문 게시 금지.
2. [CURRENT_STATE](CURRENT_STATE.md)는 **최신 통합 제품, 별도 활성 시범, 승인 경계, 미해결 핵심, 다음 1~3개만** 표시하고 *교체*한다. 상세 버전별 로그를 누적 추가하지 않는다.
3. 재발 오류가 **기존 규칙 미적용**이면 규칙 추가 대신 실제 적용 단계·UI 재사용·검증 누락을 고친다. **잘못된 규칙**이면 해당 문장 교체. **새 범용 원칙**이면 다른 전문화 정상·실패 대조 후 이 문서의 해당 섹션을 수정한다. 하나의 실패를 이유로 검사기/스키마 신설 금지.
4. 과거 사례는 [QUALITY_GENERALIZATION_CASEBOOK](QUALITY_GENERALIZATION_CASEBOOK.md), 관련 당시 인계/커밋에서 **필요할 때만** 조회한다. 이 Playbook에 세부 날짜별 결과를 다시 복사하지 않는다. 승인/비승인 사용자 결정은 지키되 미승인 시범은 채택되지 않은 예시로 표시한다.
5. GitHub 문서는 ChatGPT 프로젝트 설정을 자동 변경하지 않는다. 사용자 설정에 [최소 진입 지침](CHAT_FIRST_PROJECT_INSTRUCTIONS.md)만 등록한다. 별도 API/Work 전환 강제 금지.
