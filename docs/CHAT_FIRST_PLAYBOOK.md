1. **상황·조건별 표:** 빠른 참조는 `상황 | 우선순위(핵심 흐름과 조건)`의 평범한 V11 스타일 표. 영웅/전투 유형/버프 창을 구분하며 선택하지 않은 분기는 숨긴다. 각 스킬은 **아이콘 + 한국어 기술명 + `tip-trigger` 설명을 한 요소로 묶고**, 없는 아이콘을 임의 생성하지 않는다. 승인되지 않은 주문 ID 또는 기술 효과는 별도 REVIEW.
2. **`→`의 의미를 구분:** 지속 딜 표에서는 **왼쪽부터 조건이 유효한 기술을 검사하는 우선순위**, 오프너에서만 **원문에 명시된 실제 시전 순서**. 같은 화면에 둘 다 있을 경우 각각의 의미를 짧게 표기한다. **단일 우선순위를 화면 너비 때문에 여러 줄로 나누어도 `①·②` 등 가짜 순위·그룹 번호를 붙이지 않고, 다음 줄이 앞의 우선순위에 이어진다는 것을 `→`로 표현**한다. **짧은 조건에서는 앞선 `→`·기술 아이콘·기술명·괄호 조건을 한 행동 단위로 읽히게 유지**한다. **긴 조건까지 통째로 묶어 가로의 남은 공간을 버리거나 기술 하나만 이전 줄에 남기는 경우**, 반드시 붙여 둘 최소 단위를 **`앞선 → + 기술 아이콘 + 기술명`**으로 줄이고, **전체 조건 텍스트는 같은 행동에 귀속된 괄호를 유지한 채 자연스럽게 다음 줄로 이어지도록** 한다. 단, 기술명/아이콘과 화살표가 서로 다른 줄로 갈라져서는 안 된다. `발동)`·`생성)`만 고립되거나 시각적으로 다음 기술의 조건처럼 보이지 않도록 실제 화면을 확인한다. 전체 로테이션 한 줄 고정/가로 넘침도 금지한다. 긴 조건을 줄일 때는 같은 게임 상태와 행동을 보존하는 동의 표현만 사용하고, 조건 삭제 대신 우선순위 항목 사이에서 자연스럽게 다음 줄로 넘긴다. 게임 상태를 실제로 구분하는 분기 라벨과 실제 시전 순서 단계 번호·핵심 원리의 번호 목록만 유지한다. 실제 원문 단계 GCD와 `rt-step-group` 보조 표식을 혼동하지 않는다.
   - **기술명과 조건의 시각적 위계(2026-11-16 사용자 최종 선택):** `한눈에 보는 딜사이클`의 기술명·아이콘을 **주 정보**로 유지하고, 그 기술의 실제 판단 조건은 **괄호 `(…)`로 묶은 작은 글씨·더 낮은 명도**로 표시한다. 조건 안의 효과 아이콘도 기술 아이콘보다 약간 작게 두되 정체성을 확인할 수 있는 크기를 유지한다. 냉기 마법사 독립 v2 / 통합 **V46(괄호 있음)**을 기본 디자인 참고본으로 삼는다. 괄호만 제거한 독립 v3 / 통합 V47은 **비채택 비교본**이다. **기존 전문화에 자동 CSS 일괄 덮어쓰기하지 말고** 신규 CREATE/해당 UPDATE의 첫 화면에 적용하고 PC·모바일 줄바꿈/가독성을 검증한다. 괄호가 조건의 실제 의미나 우선순위 관계를 바꾸지 않아야 한다.

3. **요약과 상세 동기화·완전성:** 빠른 참조의 기술명·아이콘·조건·순위는 독립적으로 다시 추측하지 않고 **편집이 완료된 상세 우선순위표 및 선택형 원문 오프너**에서 가져온다. **해당 영웅·전투 유형·강화 창에 속하는 실행 우선순위의 첫 행동부터 기본 생성기·마무리까지, 조건이 실제 다음 기술을 바꾸는 항목은 빠뜨리지 않는다.** 줄이기 위해 행을 병합할 때도 순위·조건의 배타 관계를 보존하며, 단지 상위 기술 몇 개를 보여 주고 나머지를 '상세 참고'로 넘기는 요약은 첫 화면 단독 운용 목표에 부적합하다. 영웅/빌드/선택 특성이 바뀌면 첫 화면도 같은 분기를 보여야 한다. 원문에서 확인되지 않은 수치·순서·툴팁은 추가하지 않는다.
   **원문의 두 별도 우선순위가 같은 기술을 사용하더라도 그 조건을 자동으로 AND로 결합하지 않는다.** 같은 기술이 반복되는 이유가 서로 배타적/독립적인 상태인지 먼저 확인하고, 각 순위와 원문 조건을 기록한다. 원문 안의 예외 불릿 중에는 현재 버프가 **없어도** 기술을 쓰는 상태가 있으므로, 일반 상태에 흡수하거나 생략하지 않고 실제 다음 행동의 조건으로 추출해 첫 화면까지 연결한다. 각 수정을 최소 1개 상태 반례로 검증한다.
   **서로 연속된 상세 우선순위가 정확히 같은 기술**을 선택하고 그 사이에 다른 행동이 없을 때, 첫 화면의 기술명·아이콘 반복은 **명시적 '또는' 조건**으로 한 항목에 합칠 수 있다. 이때 각 원래 조건의 논리적 참/거짓과 하위 우선순위의 상대 순서를 유지하고, 상세표 원문은 분리 보존한다. 예: 불태우기(일렁이는 열기 또는 대상 체력 <30%)는 바로 이 인접 두 상태의 합집합이다. 조건의 선행 전제(예: 강화 효과 소모 직후)가 상위 우선순위 충족으로 보장되지 않는다면 이를 삭제하지 않는다. **동일 기술 반복이 아니라면 단순히 짧게 만들기 위해 합치지 않는다.**

5. **표현 범용화 ≠ 로테이션 범용화:** 직업별 고정 표 수, 영웅 이름, 스킬 수, 특정 우선순위, 단계별 묶음은 규격으로 만들지 않는다. 원본 화염/냉기/죽기/사냥꾼/도적의 퀵 레퍼런스 차이를 허용한다. 공통 UI 개선이 실제 게임 판단(Q0/Q1)을 검증했다는 뜻은 아니다.
6. **반례 검증은 내부에만 둔다 — 가정형 실전 사례 장 금지(2026-11-16 사용자 확정):** 전문화 제작·수정 과정에는 상태→우선순위→다음 행동, 상위 조건 우선·충돌, 영웅 특성·선택 특성 ON/OFF, 경계 수치의 **반례 검증을 계속 수행**한다. 그러나 이를 **「상태별 다음 행동」, 「반례 점검」, 「실전 상황별 판단 예시」 같은 독립 사용자 교본 장으로 싣지 않는다.** 어떤 가상 상황이 실제 유저에게 혼란스러운지, 실전에서 권장할 조건인지 근거 없이 단정할 수 없고, 지나치게 상황 의존적인 가상 경험을 교본의 규칙처럼 제시하면 책임 있는 정확성 범위를 벗어난다. **검증 결과와 가정은 내부 QA·사례집에서만 보존**한다. 플레이어 화면에는 원문으로 확인된 단일·광역 우선순위, 특성·수치·버프·예외 조건, 실제 확인된 오프너 및 직접 근거 있는 설명만 수록한다. 원문 자체가 제공한 실행 예시가 중요하다면 가정형 독립 장을 만들지 않고 해당 우선순위/오프너 옆에 **근거와 전제가 명확한 짧은 설명**으로만 배치할 수 있다. 상세표를 반복하거나 실제 사용자 경험을 추정한 설명은 추가하지 않는다. 고정 검증 사례 수·사용자용 사례 수·독립 검증 장을 요구하지 않는다. **Q1 검증과 Q2/Q3 플레이어 콘텐츠는 완전히 별개**로 관리한다.

## 0.2 한국어 UI 용어·내부 식별자 비노출 규칙 (2026-11-14)

빠른 참조뿐 아니라 **해당 전문화의 모든 화면 텍스트**에 적용한다. 최상위 상세 규칙은 [QUALITY_FIRST_POLICY §0.1](QUALITY_FIRST_POLICY.md)을 따른다.

- 자원 `천공의 힘`은 첫 등장에 `천힘: 천공의 힘`으로 정의한 뒤 `천힘`; 재사용 대기시간은 `쿨`; 전역 재사용 대기시간은 `전역 쿨`; 공격 가능한 적 수는 `대상 수`; DoT는 `지속 피해`; ST/AoE는 `단일/광역`으로 표시한다. 전문화에 없는 용어는 추가하지 않는다.
- 영문 약어·영문 주문 별칭·`balance-keeper-st-in-2` 같은 내부 키·아이콘 파일명·원시 식별 번호는 화면·툴팁·목차·선택 메뉴에 출력하지 않는다. 숨겨진 원문 출처 JSON과 data-* 속성의 기술 연결은 보존한다.
- 공식 한국어 기술명은 그대로 쓰고 임의 번역·축약하지 않는다. 툴팁 제목도 한국어 기술명만 표시한다. 아이콘 이미지의 대체 텍스트와 접근성 레이블도 한국어로 작성한다.
- 수식의 논리 구조는 유지하되 변수를 한국어로 바꾼다: `대상 수 ≥ 4`, `천힘 ≥ 90`, `쿨 ≤ 15초`. 처음에 정의한 축약어 외에는 의미가 모호하면 전체 한국어를 사용한다.
- **영웅 특성 표현:** 성난태양·주문술사·서리불꽃처럼 영웅 특성의 분기를 뜻할 때는 모호한 **‘영웅별’ 대신 ‘영웅 특성별’**을 기본 표기로 쓴다. 이미 짧은 문맥에서 영웅 특성이 명백하더라도 제목·안내·설명에는 정확한 명칭을 우선한다.
- `REVIEW/PASS`, `Q0/Q1/Q4`, `API/UI`는 사용자 화면에서 각각 `확인 중/확인 완료`, `게임 판단 정확성/화면 기능`, `공식 데이터 조회/화면`으로 바꾼다. 와우헤드·블리자드는 한글로 표기한다.
- 검증 시 `<script>`·`<style>`·숨겨진 내부 JSON과 실제 화면 문자열을 구분한다. 화면에 표시되는 텍스트 노드, 툴팁 속성, 접근성 텍스트를 대상으로 영문·기계식 문자열 잔여가 0인지 확인한다. 기존 7개 V11 본문은 별도 UPDATE 요청이 없으면 보존한다.
## 0. 모든 작업의 방향 점검 — 교본 제품 중심 (2026-11-13 사용자 확정)

**최상위 정본:** [QUALITY_FIRST_POLICY §0](QUALITY_FIRST_POLICY.md). 새 채팅과 후속 개발은 **개별 결함의 상세 검사보다 어떤 전문화에도 반복 적용되는 완성 교본 제작 흐름**에 먼저 연결한다.

작업 시작 시 **한 문장으로** “최종 교본에서 어떤 누락·잘못된 판단·설명·UX가 개선되는가?”를 설명한다. 이어 **기존 자산으로 해결 가능한가**, **다른 전문화에도 발생하는 동일한 근본 원인인가**, **이번 변경으로 실제 교본 제작 단계가 전진하는가**를 판단한다. 중요 조건의 정확성을 검증하는 조사라면 진행하되, 답이 REVIEW이거나 한 전문화에 국한된 사례이면 새 엔진·검사기·스키마를 자동 증설하지 않는다.

**기본 경로:** 원문 완전 수집 → 게임 판단의 상태·조건·행동·예외 추출 → V11 이상 한국어 단일 HTML **실제 집필/수정** → Q0–Q4·다전문화 정상/실패 대조 → 사용자 전달·피드백. **검사기 개발만 계속하며 결과 교본을 제작하지 않는 작업 흐름을 정상 완료로 취급하지 않는다.** 단, 게임플레이 핵심 근거가 없어 Q0/Q1 REVIEW라면 추측해 HTML을 확정하는 대신 검증된 범위만 전달한다.

**성과 판단:** CI/테스트 수·도구량·원문 마커 수·서류 분량 대신, **독자가 실제로 언제/왜 어떤 기술을 쓸지 정확히 판단할 수 있는가, 신규 전문화에서도 반복할 수 있는가**를 증거로 삼는다.

**작업 결정 기준(2026-11-16):** 원본 V11 **7개 전문화는 역사적 비교 기준**이며, 이후 검토 통합본은 **10개 전문화**일 수 있다. 최신 범위는 [CURRENT_STATE](CURRENT_STATE.md)의 **실제로 검증한 개인 파일** 기준으로 결정한다. 기존 검토본은 승인 정본이 아니므로, 이름만 입력된 경우 기존 검토본의 상태를 먼저 알려주고 필요한 CREATE/UPDATE 범위를 판단한다. 명시적인 제로베이스 요청은 다른 기존 교본을 집필 소스로 쓰지 않는다. **이미 생성된 교본을 승인 정본으로 승격하려면 사용자 최종 승인이 필요하다.** 공개 GitHub의 비전 JSON 초안을 승인 실전 교본으로 간주하지 않는다.

## B. 원본/규칙 자동 복구

1. ChatGPT 현재 Project·대화 첨부 및 개인 Library에서 **V11 원본 파일 이름을 검색**. 접근 가능할 때만 파일 바이트와 SHA를 검증한다. 원본이 없다면 승인된 최신 비공개 교본을 찾아 SHA를 검증한다.
2. GitHub 연결로 `docs/PROJECT_CANON.md` → `docs/QUALITY_FIRST_POLICY.md` → `docs/CURRENT_STATE.md` → 이 문서를 먼저 확인한다. 필요 시 `docs/SOURCE_ACQUISITION.md`, `docs/EDITORIAL_QUALITY_PROTOCOL.md`, `docs/V11_FIDELITY.md`와 관련 사례, 기존 `engine/v2` 검증 도구를 추가 확인한다. 이전 날짜의 개별 전문화 기록은 현재 상태의 대체물이 아니다.
3. 이전 대화의 정적 로컬 `/mnt/data` 경로는 **새 실행에서 존재하지 않을 수도 있다**. Files/프로젝트 첨부를 실제로 확인하고 새 출력 경로를 생성한다.
4. **공개 저장소로 원본이나 결과 HTML을 업로드하지 않는다**. 실제 원본은 사용자 개인 Project/Library/대화 첨부 또는 허용된 비공개 소스에서만 읽는다.
5. 해당 파일·GitHub 연결·웹 자료에 접근할 수 없다면 오류를 명시하고 접근 가능한 범위만 진행. **없는 근거·원본을 AI가 복원했다고 주장하지 않는다**.

## B.1. 작성 순서의 정본 — 원문 판정 규칙부터 추출

**실패한 교본의 재제작 — 잘못된 기준본을 계승하지 않기 (2026-11-13):** 신규 전문화의 UI·독해 품질이 V11보다 낮다고 사용자가 평가한 경우, 기존 실패 파일의 본문·CSS·선택 UI를 **재배치해서 회복하려는 방식은 기본 경로로 사용하지 않는다**. **해당 패치 기준 원문을 재취득하고 원문 상태·조건·우선순위·오프너를 새로 집필**한 뒤, 성공을 확인한 **다른 V11 정상 전문화의 시각적 문법**(첫 화면 2열 요약, 상세 3열 우선순위, 공개 이유/선택적 `?`, 시간순 오프너)을 표현 기준으로 적용한다. 종전 산출물은 결과 비교 및 회귀 반례로만 쓰며 데이터 추출 정본으로 쓰지 않는다. **원문 미확보 선택형 분기를 기존 HTML에서 그대로 복사해 충당하지 않는다.** 실제 [고양 제로베이스 재집필 실증](ENHANCEMENT_ZERO_BASE_CREATE_REVIEW_20261113.md)에서 기존 V3.13·후속 Cross-spec HTML을 내용 입력으로 사용하지 않고 Wowhead 12.1.5 색인에서 43개 우선순위 및 4개 확인 가능한 오프너를 새로 집필, 비전/V11 동일 표 문법으로 비공개 8전문화 HTML 제작(7/7 바이트 보존, PC·모바일 기능 PASS). 숨김 옵션/개별 도구 설명의 원본 검증은 별개 Q0/Q1 REVIEW. **사용자 만족도 Q3는 승인 전임**.


**[EDITORIAL_QUALITY_PROTOCOL](EDITORIAL_QUALITY_PROTOCOL.md)**의 Gate A~G는 필요한 품질 관점을 제공한다. **모든 작업에 같은 양의 조사·표·테스트·문서를 생산한다는 뜻이 아니다.** CREATE/대규모 UPDATE에서는 전체에 적용하고, 단일 설명·근거 확인은 관련 게이트만 깊게 적용한다. 기존 7개 V11은 정상 대조군으로 참고하되 형태를 베끼지 않는다.

**우선 고정할 것:** 기준 패치·기준 자료 1개(사용자 지정 우선, 없으면 Wowhead)·특성 빌드·영웅 특성·단일/광역 상황. 그 뒤 반드시 `상태 → 수치/발동 조건 → 다음 행동 → 이유 → 예외 → 실제 출처`를 추출한다. 이 목록을 만들기 전에는 HTML 표·장 수를 설계하지 않는다.

**제작 시작 시 결정 판단 검증 범위에 원문 심화 Tips도 포함:** 게임 행동을 바꾸는 원문 본문·오프너·심화 팁을 먼저 훑어 [EDITORIAL_QUALITY_PROTOCOL — Gate C.1](EDITORIAL_QUALITY_PROTOCOL.md)의 `원문→교본` 누락 검사 대상으로 표시한다. 첫 화면/상세 규칙의 ID 일치가 심화 설명과 예외의 사실 검증을 대체하지 않는다는 점을 집필 전에 확인한다. 원문 출처 귀속 불명은 관련 부분만 REVIEW로 남기며, 별도 사용처가 없는 일반 설명을 첫 화면에 억지로 추가하지 않는다.

우선순위는 기본적으로 **순위 / 행동 / 사용 조건**을 별개 열로 둔다. 모호한 `상황에 따라` 문장은 어떤 스택·특성·초·거리·자원에서 어떤 행동으로 바뀌는지 설명하지 못하면 삭제 또는 보류한다. 오프너/지속 딜과 선택 특성 ON/OFF의 **반례 테스트**도 먼저 수행한다.

기준 원문에서 게임 조건의 핵심이 설명되지 않았다면 *기존 부실한 초안*에 의지하거나 다른 버전의 설명을 조합해 미확인 로직을 만들어서는 안 된다. **우선 Wowhead 같은 페이지의 인접 설명을 확인하고, 해결되지 않으면 그 쟁점에 한해서 보조 공략을 대조한다.** 끝내 불확실하면 해당 판단만 보류한다.


**선택 상태 누락 감사 보조:** [SOURCE_COVERAGE_AUDIT](SOURCE_COVERAGE_AUDIT.md)의 공통 오프라인 검사기는 신규 전문화에도 적용되는 **선택 경로/본문 누락 후보** 검증 도구다. 교본 집필을 고정 JSON 생성기에 종속시키지 않으며, 실제 원문의 모든 UI를 발견했다고 자동으로 선언하지 않는다. **본문 확보 Gate A, 게임 의미 Q0/Q1, HTML 동작 Q4는 구분**한다. 고양에서 발견한 실패는 다른 전문화에서도 재현하는 합성 반례로 전이하고, 의미가 다른 기술 운용 규칙은 복사하지 않는다.

### B.1.1. 원문 판단 규칙 → ST/AoE·영웅별 출력표 의미 보존 (2026-11-13)

**현재 구조적 대책:** [SOURCE_TO_GUIDE_PROJECTION_CONTRACT_20261113](SOURCE_TO_GUIDE_PROJECTION_CONTRACT_20261113.md). 비전 12.1.5 사례에서 원문 통합 규칙을 4개 우선순위표로 AI가 재기술해 **충전물 3개 미만→0, 특정 특성 행 누락, 대상 조건 축약, 중복**을 일으켰다. **원문에 근거한 단일 규칙 집합(고유 ID·원래 순위·적용 범위·조건식·행동·이유·예외·증거)**을 먼저 만들고, 같은 ID와 조건을 **재작성하지 않고 그대로 투영**해 각 표의 행을 생성하는 것이 재발 방지의 핵심이다.

- **현재 구현:** 기존 `engine/gameplay_decision_qa.py`의 `project_priority_view`·`audit_priority_view`가 영웅/대상 수 범위에 대한 보수적 추출, 임계값·행동·순서·출처 ID 무단 변경/누락/중복 대조를 지원. 기존 6개 합성 회귀에서 비전 실패형과 다른 전문화 정상형을 구분. 검증 함수의 통과 ≠ 원문 추출의 사실 정확성, HTML 실제 사용성, 전체 게임 Q0/Q1 승인.
- **실제 생성 경로 연결(2026-11-13):** [SOURCE_TO_GUIDE_PROJECTION_CONTRACT_20261113 §0](SOURCE_TO_GUIDE_PROJECTION_CONTRACT_20261113.md). 기존 `engine/v2/create_guide.py`의 선택적 `canonical_priority_rules` 입력이 `project_priority_view` 출력 자체를 실제 4개 표의 행으로 사용하도록 수정. `when_any`는 OR(AND 조건들) 구조를 그대로 보존하고 원문 행 ID·순위·조건·이유·참고를 전달한다. 규칙을 바꾸는 경우 재생성 비교에서 실패하며 **예전 수기 행 번호에 묶인 `?`를 새 표에 그대로 붙이지 않는다**. 이 신규 경로를 쓰지 않는 옛 비전 34행 데이터는 여전히 미승인 legacy 초안이다. 실제 12.1.5 색인 10+9 통합 규칙을 가지고 만든 **새 비공개 8전문화 HTML**에서 4표 36행·12개 상태 판단·기존 V11 7/7 보존·PC/모바일 UI를 확인. 다만 직접 열람 12.0.7과 검색 색인 12.1.5의 차이·원시 WHML 모든 숨김 조건 미확정으로 **Q0/Q1 REVIEW**. 실제 교본 생성 완료를 원문 게임 사실 전체 승인으로 격상하지 않는다.
- **출처 혼합 방지:** 비전 CREATE 코드에서 최소 2개 출처를 강제하던 과거 제약을 **최소 1개 기준 출처**로 바로잡음. 타 사이트는 패치/빌드/문맥이 맞는지 해당 쟁점에 필요한 경우만 활용; 단순 출처 개수 채우기 금지.

## B.2. 작업 규모에 따른 품질 검증 — 기본 경로와 예외 경로

**기본 경로(CREATE 또는 실제 필요한 UPDATE):** Wowhead의 모든 유효 분기(영웅/전투·오프너(물약 사용 슬롯 포함)/쿨다운·Notes/접힘·관련 `?`)의 **실제 본문을 전수 수집**하고, 표시되는 탭·섹션·표·행·옆 기술·주변 문맥을 가능한 만큼 기록한다 → ChatGPT가 상태·조건·행동·이유·예외를 의미 분석한다 → 적용 대상이 모호하거나 판단이 달라지는 경우에만 정확한 원본 관계를 재검증한다 → 교본 구성 → Q0/Q1 의미 QA → HTML 변경 시 Q4 비대상 보존·UI QA. **본문 누락 Gate A와 의미 미확정 Q0/Q1을 구별한다.**

**예외 경로(작은 사실·문장·특정 규칙 확인):** 실제 쟁점의 범위만 확인한다. 원문 문맥 → 필요한 경우 다른 공략 해당 부분 → 적용 패치/영웅/빌드 구분 → 수정 또는 검토 보류. 새 스키마·전체 전문화 재작성·고정 개수 반례를 만들지 않는다. **의미가 바뀐 경우** 요약·상세·오프너/팁 등 관련 표현만 연쇄 확인한다.

**공통 실패 원인 경로:** 생존 V1/V2처럼 정보 추출 방식 자체가 조건을 지우거나 오류가 여러 장에 반복된다면, 그때만 원인 단계와 영향을 받는 범위를 확대 감사한다. 모든 작은 이슈를 동일한 대규모 감사로 격상하지 않는다.

**범용성 판단은 항상 하지만 작업은 비례시킨다:** 일회성인지, 기존 절차로 해결되는지, 다른 전문화에 전이되는 원인인지, 일반화할 때 정상 V11을 오탐하는지 짧게 평가한다. 일반화 가치가 없으면 **새 개발물 없이 끝내는 것도 성공**이다. 반복되는 근본 원인에 대해서만 [범용 사례집](QUALITY_GENERALIZATION_CASEBOOK.md)에 검증 근거를 축적한다. **합격표/절차 이행 자체가 품질 성과는 아니다.**

**동적 렌더링 원문 접근 가능 시:** [LIVE_DOM_CAPTURE](LIVE_DOM_CAPTURE.md)의 범용 브라우저 어댑터로 상위 선택 전환 뒤 새 하위 UI와 tooltip 본문을 확보한다. 별도 사용자 설치가 기본 조건이 아니며, 실제 접근 가능한 실행 환경에서만 보조로 사용한다. 수집 경로 제한·버전 충돌·미방문 경로를 숨기지 않는다.

**구조 후보 → 수집 기록 대조(범용):** 실제 HTML을 확보했다면 `engine.source_structure`로 숨김 패널/팁 후보를 발견하고, `engine.source_reconcile`로 `engine.source_coverage` 관측 기록과 대조한다. **발견된 후보를 빠뜨렸다면 본문 수집 후보로 복구**, 관련 없는 UI라면 이유를 기록해 제외한다. 동일한 설명의 숨김 DOM 본문·트리거를 중복 계수하지 않으며 `tooltip2`처럼 한 트리거에 설명이 여러 개인 경우는 독립 확인한다. 이 단계의 코드 성공은 사이트 전수 확보나 의미 정확성을 증명하지 않는다.

**범용 실증(2026-11-12):** [냉기 마법사·생존 사냥꾼·징벌 성기사의 원문 선택 구조 대조](CROSS_SPEC_SOURCE_VALIDATION_20261112.md)를 신규 전문화 검증 반례로 추가했다. `source_structure.source_sha256`과 관측 기록의 `html_sha256`, URL·패치·수정본 일치 없이 후보 연결을 승인하지 않는다. 검색 색인만 확보한 경우 원본 DOM·툴팁 전수 증명이라고 승격하지 않는다. 공개 출력에는 섹션 문구·선택항목을 해시/DOM 좌표로 보존한다.

## C. 소스 조사 — 한번의 전문화 명령 이후 자동 처리

1. 요청 날짜와 게임 버전, 전문화/영웅 특성/난이도를 확인. 현재 패치가 특정 문서의 옛 패치와 같다고 가정하지 않는다.
2. 사용자가 공략 URL/원문을 제공하면 우선하고, 아니면 최신 버전의 Wowhead 단일 기준 공략을 사용한다. [SOURCE_ACQUISITION](SOURCE_ACQUISITION.md)에 따라 모든 유효한 관련 선택형·접힘·hover·타임라인 **본문**을 확보한다. 모든 관련 `?`의 내용과 가능한 위치·주변 맥락을 기록하며 정확한 행 ID 연결을 일괄 강제하지 않는다. 해석이 모호해 중요한 행동이 달라질 때만 관련 관계를 재확인한다.
3. **다른 사이트는 필수 아님.** 기준 원문의 특정 조건이 불명확·누락·상충하거나 최신 변경에 의문이 있을 때 **그 쟁점만** 보조 확인한다. 사이트 수를 채우기 위해 여러 로테이션을 섞지 않는다. 서로 다른 URL이 독립 근거라는 보장도 없다. 공식 패치/주문 데이터로 기술 유효성을 별도 점검한다.
4. 기계적인 최신성만으로 순위 확정 금지: 일부 문서는 '쉬운 회전/간편판'과 '상세 우선순위', 시즌 세트·특성·광역 상황이 서로 다를 수 있다. 각 조건이 어떤 빌드에 해당하는지 직접 확인한다.
5. 주문/버프·영웅 특성 식별: 게임 공식/신뢰 소스의 ID·한국어 명칭·이미지 및 발동 조건을 검증. **ID를 추측하지 않는다**.
6. 복제 가능한 외부 자료의 이용 권한을 확인. 저장소에는 **공략 제목/URL/확인 일자/검토 지표**만 보관하고, 장문 원문·번역문은 공개하지 않는다.

## D. ChatGPT 집필 기준 — 기존 7개 V11을 교본 품질 기준으로 삼는다

단순 우선순위 표 출력은 **불합격**. 해당 전문화에서 실제로 필요한 항목을 충분히 다룬다.

- 특성 선택/빌드 분기, 영웅 특성 차이와 스펙의 핵심 메커니즘을 원인→발동→행동→예외 흐름으로 설명.
- 입문자용 요약/심화 차이를 구분하고, 중요한 주문과 버프의 역할·활성 조건·상호작용, 단일/광역 우선순위를 이해 가능한 표로 작성.
- 쿨다운·오프너·자원/중첩 운용, 사용 전후 판단, 예외 처리, 구간·대상 수·세트 효과에 따른 조건 변화.
- 기존 V11의 장/헤더, 기술 아이콘·툴팁, 문맥별 내부 기술 링크, `?` 추가 원리, `!` 주의사항, 비교표·흐름도·용어집을 **내용상 필요한 위치**에 재사용.
- 장 개수·총 글자 수를 맞추기 위해 단순 반복/불필요한 빈 항목을 추가하지 않는다. V11의 맥락·설명 밀도를 따라가는 것이 기준.
- 확인되지 않은 실전 조건은 위험성이 드러나게 표시. 임의로 거짓 확신의 문장을 쓰지 않는다.

**비전 필수 교훈:** 자동 생성 초안의 스타일·설명량을 복사하면 V11의 원본 7개보다 품질이 떨어질 수 있다. 비전 기존 JSON은 기초·검토 목록으로만 사용하고, V11 품질과 실제 출처를 재대조하며 **실질적으로 재집필할 수 있다**.

## E. HTML 생성/수정

**제작 기준본 선택을 먼저 확정 (2026-11-13 사용자 재평가):** 신규 CREATE 또는 기존 결과의 구조·가독성 반려 후 재작성에서는 **이전 실패 교본을 기초로 보완하지 않는다**. (a) **콘텐츠 기준 = 현 패치의 단일 최신 원문**, (b) **화면 기준 = 정상 V11 + 비전/제로베이스 고양에서 실제 긍정 평가를 받은 정보 위계**, (c) **실패본 = 전후 비교·반례만**으로 역할 분리. 이미 승인된 정상 교본의 UPDATE는 예외로 기존 제품을 보존하고 원문 변화만 반영한다. 이전 미승인 HTML·JSON의 존재, 테스트 PASS 또는 최신 파일명만으로 콘텐츠/디자인 기준본이 될 수 없다. 세부 정본은 [QUALITY_FIRST_POLICY §5.1](QUALITY_FIRST_POLICY.md).

**실행 경로의 안전 장치:** `engine.v2.create_guide` 실행은 더 이상 과거 `content/new_guides/arcane.json`을 기본값으로 쓰지 않고 `--draft`를 명시해야 한다. **이 Arcane 시범 생성기 경로로 제작할 때** `canonical_priority_rules`가 있는 근거 기반 초안만 허용한다(모든 전문화를 JSON 생성기에 종속시키는 규정이 아님). 종전 수기 초안은 **`--legacy-review-only`를 명시한 역사적 비교용**이며 이 모드의 결과는 제품 승인·기준본 승격 금지. 내부 합성 테스트에서 과거 draft 입력을 허용하는 것은 제품 제작 경로의 사용 허가가 아니다. 이 검증은 원문 의미의 진실성(Q0/Q1)을 대체하지 않는다.


CREATE:
- V11의 기존 `manual-view` 7개를 변경하지 않고 신규 전문화만 확장. UI 메뉴/장 탐색, 영웅 특성 전환, 우선순위, tooltip, `?`/`!` 기능 재사용.
- 필요하면 기존 `engine.v2.create_guide`의 안전한 DOM/JS 확장 코드, `import_v11`·`parity`·`fidelity`·`annotations` 등을 가져와 재사용한다. 기존 생성기 구조가 더 나은 수작업 설명을 표현하는 데 방해되면 **생성기를 개선**하지 콘텐츠 품질을 낮추지 않는다.

UPDATE:
- 현재 사용자가 승인한 최종본의 각 전문화/행 ID·원본 지문을 대조. 의미가 실제로 바뀐 규칙만 수정하고 인접한 설명·툴팁의 영향도 확인.
- 내용만 다듬는 요청은 조건 변경과 분리. 관련 없는 전문화·장·아이콘·스크립트는 바이트 단위로 유지.
- `engine.v2.patch_v11`, `private_changes` 등을 참고하여 최소 패치를 적용.

## E.1. 왼쪽 메뉴 접기/펼치기 — 재사용 UI 원칙

2026-11-11 생존 사냥꾼 CREATE 과정에서 원래 V11 왼쪽 목록을 2단으로 개선했다. 이후 교본에서 **직업 상위 메뉴를 클릭하면 전문화 목록**, **전문화를 클릭하면 영웅 특성 버튼 목록**을 각각 접거나 펼칠 수 있어야 한다. 구현은 진짜 `button`과 `aria-expanded`/`aria-controls`, `hidden`을 사용하고 포커스·Enter/Space·선택된 전문화 자동 펼침 및 URL 목차 복원을 지원한다.

기본 화면은 첫 선택 교본이 있는 마법사/화염 목록만 열린 상태이며, 다른 직업은 접어 공간을 절약한다. 사용자는 언제든 임의의 직업이나 전문화만 펼칠 수 있다. 신규 전문화는 기존 직업 그룹 내부에 추가해야 한다. **2026-11-16 최신 UI 원칙:** 왼쪽 메뉴의 직업·전문화·영웅 특성 및 현재 교본 목차는 가능한 한 **항목별 1행**으로 표시한다. 화면에 꼭 필요하지 않은 영문 보조 표기는 숨기고 한국어명을 보존한다. 데스크톱에서는 메뉴 열 너비·본문 간격을 함께 조절하고, 들여쓰기·세로 패딩을 줄이되 글자나 선택 버튼을 과도하게 축소하지 않는다. 모바일에서는 접기/펼치기와 목차 밀도를 별도로 확인한다. 긴 항목이 잘려 보이지 않는지 실제 렌더링을 검사하고, 새 전문화가 추가돼도 같은 규칙을 재사용한다. 기존 본문과 토글 기능은 보호한다. 징벌 V2에서 PC 직업 토글 높이 약 72.7px→30px, 모바일 35px→30px 확인(이 숫자 자체는 고정 규격이 아님). 기존 7개 전문화의 실제 교본 `manual-view` 본문을 재직렬화·덮어쓰기 하지 않는다.

테스트·근거·개인 출력 해시: [생존 제작 실작업 기록](CHAT_FIRST_RUN_SURVIVAL_20261111.md).

## E.2. ‘한눈에 보는 딜사이클’ — 실전형 요약과 유연한 정보 설계

**오프너/물약 최신 공통 원칙(실물 HTML 대조 2026-11-12):** 물약 선택을 **무조건 무시하거나 모든 전문화에서 무조건 분기하지 않는다**. 실제 원본의 `display-option` 및 `display-options` 조건을 분석해 물약 선택이 **시전 순서·사용 시점·선시전 여부**를 바꿀 때만 해당 오프너를 분기한다. 고양 12.1.5에서는 실제로 4개 영웅×전투 오프너 × 물약 3개 = 12개 유효 선택을 구별한다. 다른 전문화에 일괄 적용하지 않는다. 물약 3개를 하나의 오프너에서 연이어 사용하게 만드는 오류는 계속 방지한다. 근거: [고양 사용자 저장 원문 감사](ENHANCEMENT_SAVED_HTML_EVIDENCE_20261112.md).

기존 V11의 목표는 `단일 지속 딜 / 광역 지속 딜 / 단일 오프너 / 광역 오프너 / 가장 중요한 예외`를 보고 **다음 스킬을 선택할 수 있는 것**이다. 그 아래에는 짧은 **핵심 운용 원칙**을 배치한다. 영웅 특성이 다른 운용을 요구하면 각각 따로 보여준다.

**형식은 유연하다.** 5행 표는 유용한 예시일 뿐 고정 스키마/행 수가 아니다. 실제 메커니즘을 더 이해하기 쉽게 만드는 흐름도, 임계값 비교표, 양쪽 특성 비교, 팁 레이어를 제안할 수 있다. 고정 장 수·텍스트 길이·표 개수 때문에 실제 조건을 줄이거나 일반화하면 실패다.

**우선순위표에서 암묵적으로 성립하는 조건은 제거한다(2026-11-16 사용자 확정).** 위에서 아래로 검사해 첫 번째로 조건을 만족하고 기술을 사용할 수 있는 항목을 선택하는 것이 '딜사이클 우선순위'다. 따라서 `사용 가능할 때`, `재사용 대기시간이 돌아왔을 때`, `상위 조건이 없고`, `앞 순위가 불충족이면` 같은 **상시 전제**를 각 행에 반복하지 않는다. 단, **실제 다음 행동을 바꾸는** 특성·발동·자원·대상 수·특정 기술과 정렬/보류 조건은 보존한다. 특성·발동·강화 상태라고 해서 무조건 표에 남기는 것은 아니다. 기술명 자체가 선택을 이미 전제하거나 기술이 그 발동 상태에만 활성화되는 경우(예: 승천의 '승천 특성 선택', 폭풍의 '폭풍 발동', 바람의 일격의 '승천 중')는 중복이다. 이미 높은 우선순위의 기술이 조건을 처리하는 경우에도 하위 기술에 부정 조건을 반복하지 않는다. 반면 광역 9중첩 연쇄 번개처럼 **폭풍 발동 중에는 10중첩까지 모아야 하므로 실제 선택이 바뀌는 예외**는 간결하고 명시적인 말로 남긴다. 기술이 쿨이더라도 기다리라는 **실제 정렬/보류 지침**은 단순 사용 가능 상태와 달라 명시한다. 동시 충족은 `소무 10중첩 / 대상 수 ≥ 2`처럼 `/`나 '그리고', 택일은 '또는'을 써서 논리를 보존한다. `∧`, `∨`는 새 교본의 사용자 표시 조건에 사용하지 않는다. 첫 화면과 상세 우선순위에 같은 규칙을 적용하고, 설명 목적으로만 첨가된 전제가 양쪽에 반복되지 않는지 검사한다. **`강화 창 밖`이라는 미정의 표현은 금지한다.** 특정 강화 효과인 `승천`·`파멸의 바람`의 활성 여부가 실제 행동을 바꾸면 그 이름과 구간을 명시한다. 상태→다음 행동의 내부 대조를 거쳐 삭제 전후가 다르다면 원문 근거로 표현을 복원한다. 원문에서 해당 상태를 입증할 수 없다면 REVIEW로 남긴다.

표 안에 사용자 결정을 바꾸는 조건과 정확한 숫자를 반드시 넣는다. **기본 판단 이유는 조건 바로 아래 상시 표시**하고, `?`에는 특수 상황·드문 예외·심화 운용 팁만 **필요할 때** 추가한다. `!`에는 특성·패치 차이에 따른 실제 주의사항을 넣되 다음 행동을 결정하는 필수 조건을 숨기지 않는다. 지속 딜 우선순위와 시전 순서가 정해진 오프너는 구분하고, 오프너의 조건이 본 우선순위와 모순되지 않는지 검사한다.

### 콘텐츠 품질 확인

**표 내용 자체의 독해 역할 검사:** 단순히 `?`에서 뺀다고 기본 이유가 되는 것은 아니다. `특성 없으면 생략`은 조건, `충전물 4개 권장`은 참고, `괄호 내 OR`는 논리식 해설이다. 설명을 조건/목적·인과/주의·전제/선택적 심화로 분류하여 역할이 맞는 곳에 배치한다. **게임 원인 근거가 없으면 채우기 위해 창작하지 않고 REVIEW**. 실제 예시는 [V11_FIDELITY](V11_FIDELITY.md)의 `우선순위표의 정보 역할`에 기록.

### E.2.1. 심화 판단의 첫 화면 승격 — 행동·시점이 바뀌면 요약에도 제공 (2026-11-17 사용자 피드백)

- **독자의 다음 선택을 바꾸는 심화 팁은 상세 장에만 묻지 않는다.** `상태·임계값/영웅 특성 → 다음 행동 또는 보류 → 간결한 이유`의 형태로 **첫 화면 핵심 운용 원칙에 통합하거나, 첫 화면 바로 아래의 짧은 '심화 운용 요약'**에 표시한다. 특정 장/박스/행 수를 강제하지 않고, 이미 첫 화면에 똑같은 판단식이 있으면 반복하지 않는다.
- **원문 소개 문장 ≠ 실전 지침:** `원문에서 선택 사항으로 언급합니다`, `상황에 맞게 활용`, `준비를 권장`처럼 **무엇을 실제로 하라는지 알 수 없는 표현**은 그대로 남기지 않는다. 정확한 **준비 순서, 사용 전제, 얻는 이익, 해당하지 않는 때**를 직접 확보한 원문 범위 안에서 간결하게 집필한다. 확인되지 않은 재사용 대기시간/중첩/시점을 상상하지 않고 REVIEW로 둔다.
- **심화 요약으로 올릴 주요 후보:** 자원·발동 **사전 준비**, 강화 마무리의 **소비 순서·후속 사용**, 쿨다운 **보류·동기화 임계값**, 특정 적 수의 **예외**, 대상 전환·효과 소실 시 **복구 행동**, 게임 버그로 인해 바뀌는 **기술 입력**. '고급'이라는 제목만으로 모두 싣지 말고, **해당 문장을 뺐을 때 잘못된 다음 기술·타이밍을 고를 가능성**으로 선별한다.
- **원문 조건 보존:** 숫자(예: 5중첩·10초), 영웅 분기, 발동의 부정, 연속 시전이 아닌 **우선순위** 관계를 정확히 유지한다. 일반 이유는 공개 텍스트로, 진짜 특수·희귀 예외만 `?`에 둔다. 오프너의 `→`와 지속 딜의 `→` 의미를 바꾸지 않는다.
- **영웅 특성별 팁 표시:** 핵심 원칙·심화 요약·상세 심화 중 **선택한 영웅 특성에서만 성립하는 문장과 매크로**는 해당 영웅이 선택되었을 때만 표시하고, 공통 원칙은 양쪽에 유지한다. 각 팁의 게임 전제는 기준 원문과 상세를 확인한 뒤 구분하고, 현재 HTML에 이미 있는 영웅 전환/표시 메커니즘을 재사용한다. 보이지 않는 다른 영웅 팁이 독자에게 노출되는지, 선택 전환 시 목록 번호와 제목/본문이 함께 바뀌는지 PC·모바일에서 확인한다.
- **전투 전 준비는 실행 순서대로 짧은 체크리스트:** 기름/소모품·독·선택형 사전 충전·최종 은신 등의 **실제 행동**을 나열한다. 이미 은신 상태에서는 사용할 수 없는 기술이 있으면, 사용자가 제시한 항목 순서보다 **게임상 선후관계**를 우선한다. 자원·조건·효과 소멸 같은 선택의 핵심 예외는 유지하며 원문 소개나 불필요한 장문은 제거한다.
- **반복 제작 검증:** 새 전문화·UPDATE마다 첫 화면 ↔ 상세 우선순위 ↔ 쿨다운/심화 장을 **내용 측면**에서 대조한다. 같은 문제가 다른 전문화에도 있는지는 실물과 기준 원문으로 확인한 뒤 확장 수정한다. 새 검사기/전용 레이아웃 생성은 필수가 아니다. 예시: **잠행 V69**에서 전투 전 초자력 충전기 준비의 `어둠의 춤 1회 → 보존되는 첫 두 강화 충전`을 구체화하고, 5중첩 준비·강화 마무리·10초 정렬·죽음추적자 복구 판단을 첫 화면으로 승격. 상세 내용과 비대상 11개 전문화 보존.

### E.2.2. 기술 우선순위의 대상·'window' 해석·간결한 문체 (2026-11-17 사용자 피드백)

1. **지속 딜/쿨다운 '우선순위' = 게임 내 기술 선택:** 순위/행동 열에는 플레이어가 누르는 **전문화 기술만** 배치. **전투 물약·사용형 장신구·일반 소비품은 스킬 우선순위 행에 넣지 않는다.** 기준 원문이 이를 1순위로 표기하더라도, 소비재 **사용 시점·효과 정렬 근거**는 전투 전 준비, 오프너(정확한 시간순), 별도 아이템 사용 원칙에서 보존한다. 오프너에서 소모품은 실제 선택 타이밍을 바꾸는 원문 단계이므로 임의 삭제하지 않는다. 원문과 사용자용 우선순위가 달라질 때는 **편집 분리**임을 기록하고, 나머지 실제 기술의 상대적 우선순위를 유지한다.
2. **영어 'window'는 게임 내 버프 이름이 아님:** `Eclipse window`→**일월식 활성 중**, `Celestial Alignment window`→**천체의 정렬 지속 중**, `Doom Winds window`→**파멸의 바람 효과 지속 중**, `Improved Garrote's 6-second window`→**소멸 뒤 강화 목조르기 사용 가능 6초**처럼 **기술/버프명 + 시작·종료/지속시간**으로 표현한다. 원문이 정확한 효과를 특정하지 않은 `burst window`는 서로 다른 기술을 무작정 하나로 묶지 말고 단일 패치·영웅 선택·실제 효과를 확인한다. `큰 강화 창 / 이번 창 / 다음 창`처럼 참조 대상이 빠진 교본 문구를 금지. 단, **얼음창·표창 폭풍** 같은 실제 기술명의 글자 `창`은 변경 대상이 아니다.
3. **문장 길이는 '조건 → 행동 (필요할 때만 이유)'로 압축:** `마무리 기술은 기본적으로 연계 점수 6점 이상에서 사용합니다` → `마무리 기술: 연계 점수 6점 이상에서 사용`; `어둠의 춤 밖에서는 자원 수급이 느리므로 자동 공격을 유지하세요` → `어둠의 춤 밖: 근접 자동 공격 유지(기력 수급)`. `~합니다/~하세요`를 전부 기계적으로 빼거나 `>=6` 같은 낯선 토큰으로 축약하지 않는다. **공식 한국어 명칭·아이콘·발동/예외/중첩/수치·행동을 바꾸는 부정 조건·읽기 쉬운 괄호**를 보존한다. **2026-11-17 사용자 긍정 평가로 '중간 수준의 압축'을 신규 집필·관련 UPDATE의 기본 문체로 채택.** 적용 범위는 첫 화면·핵심 원리·심화 요약 등 빠른 판단용 설명이며, 상세 장은 설명이 필요하면 온전한 문장도 허용한다. **V71 실물에서는 잠행 첫 화면의 한 문장만 문체 시범 변경**되었고, 그 외 전문화가 자동으로 새 문체를 적용받은 것은 아니다. 기존 모든 전문화를 문체만 바꾸기 위해 일괄 재작성하지 않으며, 다음 실제 콘텐츠 UPDATE 때 조건·예외를 보존하면서 적용한다.
4. **QA:** 원문(한 패치·빌드) → 우선순위 기술 행/정렬 → 소비재 시점 별도 보존 → 첫 화면/상세 대응 → 문맥별 `window`의 실제 스킬 확인 → 모바일 줄바꿈과 영웅 선택. 검증 결과는 콘텐츠 Q0/Q1과 기능 Q4를 따로 보고하며, 단순 정규식 일괄 치환이나 스키마/신규 검사기 확장을 기본 경로로 삼지 않는다.

### E.2.3. 제로베이스 제작에서 콘텐츠 독립성과 UI 품질 재사용을 분리 — V73 재발 방지 (2026-11-17 사용자 반례)

**실패 실증:** 비전 단독 V73은 동일한 원시 우선순위 배열을 `첫 화면 3열 전체표`와 `상세 3열 전체표`에 반복 렌더링하고, 단일/광역은 머리의 선택 버튼 하나로만 바꿔 보이게 설계했다. 정상 비교본 냉기 통합 V46은 `상황 | 조건별 지속 딜 우선순위`의 단일·광역 **동시 비교**, 단일·광역 오프너, 핵심 원칙을 첫 화면에 배치했다. V73은 규칙 대응/overflow/버튼 정상이라는 Q4 검사만 통과했고, 정보 계층·읽기 동선·열 폭의 **Q3 독해 실패**를 잡지 못했다. 사용자 화면 평가 **FAIL**, 코드 기능은 범위 내 PASS, 게임 정확성 Q0/Q1은 REVIEW로 **별개 표기**한다. 자세한 증거는 [QUALITY_GENERALIZATION_CASEBOOK](QUALITY_GENERALIZATION_CASEBOOK.md)의 V73 실패 항목과 [CURRENT_STATE](CURRENT_STATE.md)에 기록한다.

**새 CREATE/독립 재집필 시 코딩 이전과 이후 반드시 거치는 편집 게이트(별도 검사기/엔진 불필요):**

1. **정본 역할 먼저 결정:** 제로베이스의 **게임 콘텐츠**는 같은 패치 원문에서 독립 추출하며 실패한 구교본 규칙을 복사하지 않는다. 반면 **표현·UX 문법**은 정상 V11 7개, 사용자 평가가 좋은 냉기 V46 등 최소 여러 개 정상 사례를 **집필 전 먼저 확인**한다. 사용자 승인을 받지 못한 초안은 표현 정본으로 삼지 않는다. **콘텐츠 독립 ≠ 기존 성공 UI 지식 폐기**.
2. **화면별 정보 역할 선설계:** 상세는 `순위 | 행동 | 조건/이유`로 원문 판단을 보존하고, 첫 화면은 **단일·광역 우선순위·해당 오프너·핵심/심화 판단**을 빠르게 비교·결정하는 역할로 별도 설계한다. 같은 규칙 데이터는 공유할 수 있지만, **첫 화면과 상세표에 동일한 3열 표를 그대로 두 번 렌더링하는 것을 기본 설계로 금지**한다. 정보 형식이 달라도 순위와 실제 선택 조건은 동일해야 한다. 콘텐츠 양/조건이 특별해 동일 표가 더 우수하다는 직접 비교 증거가 있을 때만 예외를 검토한다.
3. **전환 동선 검증:** 영웅 특성은 선택 전환 가능하되, 단일/광역은 첫 화면에서 **두 상황을 한눈에 비교**할 수 있게 배치하는 것을 기본값으로 한다. 선택 UI가 필요한 특별한 경우에도 **스크롤을 되돌리지 않고 전환 가능한 접근 경로**를 제공하거나 직접 가독성 비교로 그 불편이 없는지 확인한다. 스크롤 상단에만 있는 전투 유형 버튼 + 길게 이어진 한 분기 표는 V73 실패 반례. 서로 동시에 수행할 수 없는 물약/빌드의 선택형 분기는 무조건 모두 공개하지 않는다.
4. **HTML 생성 전 간단한 화면 구성 스케치·질문:** 첫 화면에서 사용자가 **현재 영웅의 단일/광역, 오프너, 핵심 예외**를 어디에서 어떻게 읽는지, 상세표가 별도로 어떤 가치를 주는지, 조건이 긴 기술 행의 열 너비/줄바꿈을 어떻게 처리하는지 **정상본과 대조**한다. 필요한 경우에만 UI 구조를 유연하게 변경하되 정보 역할을 설명할 수 없는 동일 표 복제는 하지 않는다.
5. **완료 전 두 축 검증:** (A) 원문→조건·행동·상위 순위·영웅/대상 분기 Q0/Q1, (B) 첫 화면 독자 동선·단일↔광역 비교·표의 열 배분/줄바꿈·핵심 행동 발견성·시각 위계 Q2/Q3. PC/모바일 실제 화면을 **냉기 V46 등 정상본과 나란히 검토**하고, Q4의 `JS 오류 0 / 스크롤 0 / 첫 화면↔상세 순위 일치`만으로 Q3 PASS라고 표기하거나 제품을 추천하지 않는다. 중요한 UX 역행이 발견되면 **검토본을 정상 재현 성공으로 계산하지 말고 실패 반례로 기록**한다.

## E.3. 제품 완성 실증 — 신규 전문화 CREATE와 V11 제로베이스 재생성 (2026-11-16 사용자 확정)

**목적:** 전문화명을 한 번 입력하면 실제 원문 분석부터 판단 가능한 한국어 단일 HTML이 V11 이상 품질로 반복 제작되는지 검증한다. 신규 검사기나 거대 엔진을 추가하는 실험이 아니다.

1. **미제작 전문화 독립 CREATE:** 통합 HTML에 없는 전문화를 선택해 원문 최신 패치·날짜·영웅 특성·전투 형태·선택형/접힌 원문을 확보하고, 상태→조건→행동→이유·예외를 먼저 구조화한다. 기존 실패 JSON·서식·게임 내용으로 조건을 채우지 않는다. 첫 화면과 상세/오프너 연결, 공식 한국어 명칭·아이콘, Q0~Q4를 각각 평가한다.

3. **비교의 두 축을 분리:** (A) 동일 패치·동일 원문 범위가 확보되면 기술·조건·우선순위·오프너·예외의 사실/판단 재현성을 비교한다. (B) 패치가 다르면 게임 내용 불일치를 제작 오류라고 단정하지 않고, 각자 해당 패치 원문과 먼저 대조한 후 설명 밀도·다음 행동 결정력·첫 화면·모바일 UX·아이콘·툴팁 등 **구조적 품질**을 비교한다. 역사 원문이 없으면 동일 버전 재현을 PASS라고 주장하지 않는다.
4. **평가 기록:** 일치·개선·누락·오류·버전 차이·원문 접근 불가를 분리하고 Q0/Q1 중대한 실패 0건, Q2/Q3 사용자 평가, Q4 보존·실제 브라우저 테스트로 판정한다. 기계적 문장·표 개수 유사도를 품질 지표로 쓰지 않는다. 특정 사례의 통과가 모든 전문화의 정확성을 자동 보장하지 않는다.

## E.4. 표 열의 내용 침범을 금지 — 2열/3열 구분 및 반응형 읽기 규칙 (2026-11-16 사용자 제보·V51 실증)

**사용자가 발견한 반복적인 UI 결함은 단순 페이지 가로 넘침과 다르다.** 고정 너비 3열 표 CSS를 2열 요약표에 재사용하면 라벨 열이 지나치게 넓어지고 우선순위 열이 좁아진다. 3열 상세표에서 상태 칸 `white-space:nowrap`, 기술 아이콘+이름의 무분별한 비분리, 전역 `nth-child` 너비가 겹치면 텍스트가 **다른 열의 내용 위에 그려질 수 있다.** 페이지 전체 `documentElement.scrollWidth <= innerWidth`만 확인해서는 발견되지 않는다.

1. **열 수에 맞춰 독립 너비를 설계:** `상황 | 조건별 우선순위`와 `상태 | 다음 선택 | 이유`는 **서로 다른 표 유형**이다. 2열 빠른 참조는 상황·구간 라벨에 필요한 짧은 폭(데스크톱 V51 기준 150px)을 주고 나머지를 행동 열에 배정한다. 3열 표는 상태·행동·이유가 각각 필요한 폭을 확인한다(V51 실증 시작값 **24%/36%/40%**, 다른 전문화/내용 길이에 고정하지 않는다). 과거 3열 `th:nth-child(2){width:32%}`를 2열에 그대로 상속시키지 않는다.
2. **셀 내부에서 자연스럽게 줄바꿈:** 상태 문장·행동 나열·이유는 자기 셀 안에서 줄을 바꿔야 한다. 무제한 `nowrap` 금지. 아이콘+한글 기술명은 **한 행동 식별 단위**로 연결하되, 기술 *사이*의 공백/구분자와 조건 텍스트에서 줄바꿈을 허용한다. 줄바꿈 때문에 내용을 삭제하거나 글씨를 불필요하게 작게 만들지 않는다.
3. **폭 부족 시 열을 세로 배치:** 실제 읽기 영역이 충분하지 않으면 2열/3열을 억지로 유지하지 않고 한 논리 행의 `상황·상태 → 행동 → 이유`를 세로로 표시한다. 헤더의 의미를 숨기지 않고 접근성 구조를 유지하며, 기존 `→`의 우선순위/시간순 의미도 보존한다. V51 기준 1100px 이하에서 새로 만든 세 전문화 표에 반응형 세로 행을 적용했으며, 향후에는 컨테이너 폭/콘텐츠 길이별로 검증한다.
4. **실제 셀 침범 검증을 Q4에 포함:** PC·모바일 최소 폭뿐 아니라 **중간(900/1100)·넓은(1365/1480) 화면**에서도 화면에 나타나는 각 표의 `td` 경계와 텍스트 노드/기술 아이콘의 실제 렌더링 경계를 비교한다. **다른 셀의 영역을 침범한 건수 0**이어야 한다. 전체 가로 넘침 0·JS 오류 0과는 **독립적으로** 판정한다. 아이콘 불러오기 실패로 너비가 줄어드는 모의 환경뿐 아니라 아이콘 자리가 실제 예약된 상태도 확인한다.
5. **범용화는 검증된 범위부터:** 원인이 공유되는 전문화에서 공통 CSS 규칙을 재사용하되 기존 7개 V11 본문·표 서식을 전역 일괄 교체하지 않는다. 교정 전에 실제 피해가 있는 상태를 재현하고, 새 스타일이 다른 전문화의 정상 표에 영향을 주지 않는지 검토한다. 품질 오류 방지를 위한 **제작·QA 정책**이며 새로운 대규모 검사 엔진을 구축하라는 지시가 아니다.

### E.4.1. 열 너비·실제 줄바꿈 효율의 콘텐츠 기반 시범 검증 — V76→V77 (2026-11-17)

**문제:** 페이지 가로 넘침이나 다른 셀 침범이 **0**이어도 (a) 중요한 짧은 `판단` 열이 **67px**로 줄어 상태 문구가 3~4줄로 깨지고, (b) 긴 괄호 조건 때문에 `화살표+기술+조건` 전체가 줄째 넘어가거나 고정된 `div` 단위가 가로 여백을 남기는 문제가 발생한다. **가독성은 영역 침범 여부뿐 아니라 열 사용률·행 높이·기술/조건 분리 위치를 실제 비교**해야 한다.

**새 CREATE/관련 UPDATE에 적용할 편집 원칙 (전체 전문화 일괄 강제 금지):**

- **행 내용에 맞춰 열의 실효 폭 확인:** `판단/다음 행동/이유` 등 3열 표의 첫 열을 단순히 짧다는 가정으로 최소폭으로 두지 않는다. 화면 실제 폭에서 `기존 설정 → 실제 레이아웃 결과`를 비교하고, 판단 상태가 여러 줄로 분절되어 행 높이를 결정하면 **첫 열을 넓히고 이유/행동과 균형 있게 재배분**한다. 고정 전역 27/29/44%를 표준화하지 않는다. 두 열만 있는 첫 화면 요약은 **상황 라벨이 읽히는 최소 폭 + 대부분의 흐름 폭**을 우선한다. 1100px 이하처럼 기존 반응형 세로행이 정상인 구간은 이를 무리하게 3열로 되돌리지 않는다.
- **정보 손실 없는 래핑의 최소 원자:** `→ + 아이콘 + 기술명`은 한 덩어리로 유지. **짧은 괄호 조건은 함께 유지해도 되지만**, 조건이 길면 같은 행동 뒤에서 *조건 내부의 단어 경계*로 줄바꿈을 허용한다. 필수 발동·대상 수·중첩 수치·AND/OR를 삭제하거나 기본 조건을 `?`에만 숨기지 않는다. 화살표가 줄 끝에 고립되지 않게 다음 기술명과 묶은 실제 DOM을 검증한다.
- **고정 줄 구분을 의미 단위와 구별:** 같은 우선순위 흐름을 임의로 둘 이상의 `div`로 쪼개며 빈 가로 공간을 남기면, **한 연속 흐름으로 병합**하고 브라우저 자연 줄바꿈에 맡긴다. 다만 실제로 다른 단계/상황/원문 시간순 묶음인 분리는 보존하고 `→`의 우선순위/오프너 의미를 바꾸지 않는다.
- **기능(Q4)과 실제 독해(Q3) 함께 평가:** PC·모바일 320/390/900/1100/1365/1480 등 **내용이 달리 보이는 폭**에서, 단순 스크롤·셀 침범 0만 보고하지 말고 **열의 실효 폭, 긴 라벨의 행 높이, 액션 앞 화살표의 고립, 동일 표의 전후 세로 길이**를 검토한다. 고정 `3줄 이상 무조건 FAIL`이나 특정 행 높이·문자수를 만들지 않고, 설명 밀도 대비 개선과 정상 사례의 역행 여부로 판단한다. 게임 의미 Q0/Q1은 별개.

**밀도 개선 뒤 행간 별도 확인(2026-11-17 사용자 V77 피드백):** 기술·조건 줄바꿈을 자연스럽게 고치면 정보량은 더 잘 들어가지만, 여러 줄에 걸친 흐름이 **지나치게 다닥다닥 붙어 읽기 어려울 수 있다.** 해당 흐름의 실제 `line-height`를 화면 폭·영웅별로 확인하고, 필요할 때 **현재 값 기준 약 10~15%의 소폭 증분**을 시범 적용한다. **전체 표 패딩·모든 전문화의 줄 간격을 일괄 증가시키지 않는다.** 내용·기술명·조건의 정보 손실 없이 행간만 개선하고, 화살표-기술 원자성/본문·셀 넘침과 화면 세로 팽창을 함께 평가한다. V77→V78의 징벌 첫 화면에서 `line-height:1.77→1.98`(실제 22.66→25.34px, +11.9%)만 변경; **6개 화면 폭×2영웅 12상태**의 문서 넘침/고립 화살표/JS 오류 0. 다른 전문화 기존 스타일·게임 규칙은 유지; V78 Q3 최종 사용자 평가는 REVIEW.

## E.5. UPDATE: 최신 패치 번호와 원문 갱신일·핫픽스 분리 (2026-11-16 V57 실증)

기존 전문화 UPDATE에서는 **라이브 패치 번호 → 가이드 본문 실제 수정일 → 그 이후 공식 패치 노트/핫픽스 적용일** 순서로 확인한다. 패치 번호가 같아도 원문 이후 피해량/기술 효과 조정이 있을 수 있다. `PTR 12.1.7`과 `라이브 12.1.5`를 혼합하지 않고 각 자료의 적용 상태를 기록한다.

1. **변경점의 증거:** 공식 블리자드 핫픽스·패치 노트의 기술/수치와 실제 날짜를 우선 확인하고, 기존 교본의 해당 문장·선택 판단·오프너 중 무엇이 영향을 받는지 **차이표**로 확인한다. 직접 바뀐 수치는 갱신한다.
2. **판단과 수치 분리:** 피해량 증감만으로 기술 선택·대상 수 임계·우선순위·영웅 추천이 달라졌다고 단정하지 않는다. 최신 로테이션 원문·검증된 게임 판단의 독립 근거가 있어야 행동 분기를 바꾼다. 미확인이면 기존 해당 패치 원문 순서를 보존하고 Q0/Q1 **REVIEW**로 둔다.
3. **무변경도 정상 결과:** 라이브 패치 차이가 없고 실제 가이드·핫픽스가 반영된 기존 교본과 일치한다면 **NO-OP**으로 보고한다. 별도 버전 번호와 설명 박스를 억지로 늘리지 않는다.
4. **국소 UPDATE와 보존:** 변경된 전문화/장만 수정한다. 원문·아이콘·첫 화면/상세/오프너를 오염시키지 않으며, 다른 `.manual-view` DOM·공통 JS·CSS를 보존한다. Q4는 PC/모바일·기술 전환·기존 표 셀 경계를 재검사한다.
5. **버전 전환 실증 구분:** 같은 버전의 10월 핫픽스 적용은 **시점 차이 UPDATE**이지 12.1.5→12.1.7이나 새 시즌 전체 변경 검증이 아니다. 실제 라이브 패치가 바뀐 후에는 원문 Gate A 및 상태→행동 판단을 해당 패치로 다시 검증한다.

**실물 사례 V56→V57:** 사격 사냥꾼 2026-10-14 Wowhead 기준 우선순위 이후 블리자드 **2026-10-27 긴급 수정**: 교묘한 사격 튕김 피해 증가율 **75→85%**, 폭발 사격·연발 공격 각각 피해 **+10%**. <https://news.blizzard.com/en-us/article/24307310/hotfixes-november-6-2026>. 해당 수치·근거 설명만 업데이트하고 47개 기준 우선순위/4개 오프너·다른 10개 전문화를 보존했다. 이 변경만으로 우선순위 변화 PASS라고 주장하지 않았다.

**원문 주문 ID가 효과 ID인 타임라인 단계(2026-11-16):** 출처 `rt-step`의 ID가 실제 주문책에 없는 출혈/버프 ID일 수 있다. 이를 **무조건 누를 기술로 그대로 노출하거나, ID가 직접 시전 불가라는 이유만으로 오프너에서 삭제하지 않는다**. 실제 주문 DB에서 시전 기술과 효과 ID를 구별하고, 같은 원문의 Notes·쿨다운·전후 행동을 대조해 **에디터가 의도한 행동**을 확인한다. 시전 단계는 실제 누를 기술의 ID와 원문 참조 ID를 별개로 보존하고, 불일치/타이밍이 확정되지 않으면 REVIEW한다. [분노 전사 V60 피범벅 ID 사례](FURY_OPENER_SOURCE_20261116.md)처럼 **게임 행동을 바꾸는지**가 검토의 중심이다. 이 검사는 신규 ID 정규화 엔진 개발 요청이 아니다.

**WHML 오프너 배치와 GCD의 구별(V61):** 원문의 `rt-step`은 타임라인 **표시 단계**, `rt-half-step`은 별도 배치 표시이다. 이를 일괄로 **각각 독립 GCD** 또는 **전부 GCD 면제**로 해석하지 않는다. 실제 주문별 GCD·시전 가능 상태·관련 Notes를 확인해 사용자에게 누를 기술과 시간 관계만 설명한다. 분노 전사의 무모한 희생(GCD 0초)·폭풍망치(GCD 1.5초, 칼날폭풍 중 선택 사용) 사례가 반례. **동일 가이드의 Notes와 영웅별 타임라인/상세 우선순위가 충돌하면** 불확실한 행동을 임의로 추가하거나 삭제하지 말고 명시적으로 REVIEW한다. [FURY_OPENER_SOURCE_20261116 §6](FURY_OPENER_SOURCE_20261116.md). 원문 표식 용어를 사용자 첫 화면에 장황하게 노출하지 않는다.

**선택형 원문 텍스트 평탄화 금지(V62):** Wowhead 같은 공략 페이지를 웹 텍스트로 읽을 때 여러 물약·특성 선택에만 각각 표시돼야 할 단계가 **한 목록에 연속으로 합쳐질 수 있다**. 같은 기술이 3회 연속 보인다고 실제 3연속 시전으로 만들지 말고 **원문 `display-options`·상위 조건, 실제 영웅/전투/소비재 선택 상태별 순서**를 확인한다. 특정 선택에서 **다음 행동·선시전·사용 시점이 바뀌면** 사용자 교본에 선택형 조건을 반드시 표시하되, 공통 흐름 12번을 중복 복제하지 않고 변경 행동만 읽기 좋게 분리할 수 있다. **실증:** [고양 V62 12개 물약 선택 분기](ENHANCEMENT_OPENER_SOURCE_PATHS_20261113.md). 기본 웹 텍스트에 같은 전격의 불길이 3회 나오는 것은 물약 3분기의 병합이지 3연속 사용을 확정하는 증거가 아님. 원문 선택 경로를 실제로 확인하지 못한 완전 시전 순서는 REVIEW.

**기준 원문 우선순위 14행 복원 반례(V63):** 각 영웅×단일/광역의 **원본 가이드 행동/순서**를 완성 전에 실제 확보한다. 원문 `[ol]` 안에 `[li]`가 **조건의 하위 목록**으로 다시 나타날 수 있어 **평탄화한 `li` 수가 실제 기술 순위 행 수와 다르다**. Wowhead 징벌 성기사 12.1.5 기사단 단일은 행동 **14행**, 중첩 조건 `li` **2행**으로 전체 토큰 개수만 보면 16개다. 보조 공략으로 17행을 임시 보완하면 다른 영웅의 '천벌의 망치 2충전' 같은 규칙이 섞여 **실제 다음 기술 순서를 변경할 수 있다**. 기준 원문이 회수되면 **원문 14행↔교본 첫 화면 14행↔상세 14행**과 기술 순서/조건을 다시 일치시키고, 보조 출처 기반 문장은 REVIEW/제외한다. '재사용 임박 아님'으로 일반화한 **실제 5초 이상 조건**처럼 원문 숫자를 빠뜨리지 않는다. [V63 실증](RETRIBUTION_TEMPLAR_SOURCE_20261116.md). 이를 위해 새 검사기를 만들지 말고 기존 WHML/원문 확보 경로와 내용 대조를 먼저 사용한다.

5. 실패한 테스트는 해결 후 전달하고, 미해결은 정확히 고지. 실제 검증을 수행하지 않았다면 'PASS'를 주장하지 않는다.
