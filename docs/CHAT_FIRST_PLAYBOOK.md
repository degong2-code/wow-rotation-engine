## B. 원본/규칙 자동 복구

1. ChatGPT 현재 Project·대화 첨부 및 개인 Library에서 **V11 원본 파일 이름을 검색**. 접근 가능할 때만 파일 바이트와 SHA를 검증한다. 원본이 없다면 승인된 최신 비공개 교본을 찾아 SHA를 검증한다.
2. GitHub 연결로 `docs/ADR_003_CHAT_FIRST_EDITORIAL.md`, 이 문서, `docs/SOURCE_ACQUISITION.md`, `docs/V11_RECOVERY.md`, `docs/V11_FIDELITY.md`, `docs/ARCANE_CREATE.md` 및 필요한 `engine/v2` 파일을 확인한다.
3. 이전 대화의 정적 로컬 `/mnt/data` 경로는 **새 실행에서 존재하지 않을 수도 있다**. Files/프로젝트 첨부를 실제로 확인하고 새 출력 경로를 생성한다.
4. **공개 저장소로 원본이나 결과 HTML을 업로드하지 않는다**. 실제 원본은 사용자 개인 Project/Library/대화 첨부 또는 허용된 비공개 소스에서만 읽는다.
5. 해당 파일·GitHub 연결·웹 자료에 접근할 수 없다면 오류를 명시하고 접근 가능한 범위만 진행. **없는 근거·원본을 AI가 복원했다고 주장하지 않는다**.

## C. 소스 조사 — 한번의 전문화 명령 이후 자동 처리

1. 요청 날짜와 게임 버전, 전문화/영웅 특성/난이도를 확인. 현재 패치가 특정 문서의 옛 패치와 같다고 가정하지 않는다.
2. 사용자가 공략 URL/원문을 줬으면 우선. 그렇지 않으면 [SOURCE_ACQUISITION](SOURCE_ACQUISITION.md)의 **신뢰 가능한 원문 위치를 웹 검색**하고 실제 최신 날짜·패치·빌드를 확인한다.
3. 가능하면 해당 전문화의 Wowhead, Icy Veins, Method 등 **서로 다른 자료 최소 2개**를 대조. 하나만 접근되면 단독 근거로 명시하고 품질·불확실성을 보수적으로 표시한다.
4. 기계적인 최신성만으로 순위 확정 금지: 일부 문서는 '쉬운 회전/간편판'과 '상세 우선순위', 시즌 세트·특성·광역 상황이 서로 다를 수 있다. 각 조건이 어떤 빌드에 해당하는지 직접 확인한다.
5. 주문/버프·영웅 특성 식별: 게임 공식/신뢰 소스의 ID·한국어 명칭·이미지 및 발동 조건을 검증. **ID를 추측하지 않는다**.
6. 복제 가능한 외부 자료의 이용 권한을 확인. 저장소에는 **공략 제목/URL/확인 일자/검토 지표**만 보관하고, 장문 원문·번역문은 공개하지 않는다.

## D. ChatGPT 집필 기준 — 기존 7개 V11을 교본 품질 기준으로 삼는다

단순 우선순위 표 출력은 **불합격**. 해당 전문화에서 실제로 필요한 항목을 충분히 다룬다.

- 특성 선택/빌드 분기, 영웅 특성 차이와 스펙의 핵심 메커니즘을 원인→발동→행동→예외 흐름으로 설명.
- 입문자용 요약/심화 차이를 구분하고, 중요한 주문과 버프의 역할·활성 조건·상호작용, 단일/광역 우선순위를 이해 가능한 표로 작성.
- 쿨다운·오프너·자원/중첩 운용, 사용 전후 판단, 예외 처리, 구간·대상 수·세트 효과에 따른 조건 변화.
- 기존 V11의 장/헤더, 기술 아이콘·툴팁, 문맥별 내부 기술 링크, `?` 추가 원리, `!` 주의사항, 비교표·흐름도·용어집을 **내용상 필요한 위치**에 재사용.
- 장 개수·총 글자 수를 맞추기 위해 단순 반복/불필요한 빈 항목을 추가하지 않는다. V11의 맥락·설명 밀도를 따라가는 것이 기준.
- 확인되지 않은 실전 조건은 위험성이 드러나게 표시. 임의로 거짓 확신의 문장을 쓰지 않는다.

**비전 필수 교훈:** 자동 생성 초안의 스타일·설명량을 복사하면 V11의 원본 7개보다 품질이 떨어질 수 있다. 비전 기존 JSON은 기초·검토 목록으로만 사용하고, V11 품질과 실제 출처를 재대조하며 **실질적으로 재집필할 수 있다**.

## E.1. 왼쪽 메뉴 접기/펼치기 — 재사용 UI 원칙

2026-11-11 생존 사냥꾼 CREATE 과정에서 원래 V11 왼쪽 목록을 2단으로 개선했다. 이후 교본에서 **직업 상위 메뉴를 클릭하면 전문화 목록**, **전문화를 클릭하면 영웅 특성 버튼 목록**을 각각 접거나 펼칠 수 있어야 한다. 구현은 진짜 `button`과 `aria-expanded`/`aria-controls`, `hidden`을 사용하고 포커스·Enter/Space·선택된 전문화 자동 펼침 및 URL 목차 복원을 지원한다.

기본 화면은 첫 선택 교본이 있는 마법사/화염 목록만 열린 상태이며, 다른 직업은 접어 공간을 절약한다. 사용자는 언제든 임의의 직업이나 전문화만 펼칠 수 있다. 신규 전문화는 기존 직업 그룹 내부에 추가해야 한다. 기존 7개 전문화의 실제 교본 `manual-view` 본문을 재직렬화·덮어쓰기 하지 않는다.

테스트·근거·개인 출력 해시: [생존 제작 실작업 기록](CHAT_FIRST_RUN_SURVIVAL_20261111.md).

## E.2. ‘한눈에 보는 딜사이클’ — 반드시 실전형 빠른 참고표로 구성

**2026-11-11 생존 사냥꾼 개선 후 고정된 편집 품질 기준.** 첫 장을 공략의 개요·빌드 설명으로 채우면 **불합격**이다. 기존 V11의 야수 사냥꾼/냉기 마법사처럼, 독자가 **요약표 하나만으로 단일·광역 전투에 진입하고 다음 기술을 고를 수 있도록** 구현한다.

요약 영역의 기본 구조:
1. `한눈에 보는 딜사이클` / `QUICK REFERENCE`와 영웅 특성 선택 버튼(필요한 전문화에만)
2. 영웅 특성별 `overview-table` **다섯 행**: **단일 딜사이클 → 광역 딜사이클 → 단일 오프너 → 광역 오프너 → 꼭 기억할 것(자원·버프·중요 예외)**
3. 같은 요약 영역에서 바로 **`핵심 운용 원칙`** 제목과 짧은 원칙 목록. 설명 장의 긴 배경·전문 메커니즘 해설은 여기가 아니라 이후 장에 둔다.
4. 기술명은 V11 아이콘/툴팁과 연계하고 필요한 `?`/`!` 마커로 주의사항을 열람하게 한다.
5. **지속 딜사이클은 고정 시전 순서가 아닌 조건별 우선순위**, **오프너는 진입용 예시 시퀀스**라는 차이를 텍스트로 반드시 표시. 영웅 특성별 분기를 한 표에 섞지 않는다.

QA 필수: 영웅 특성 전환 후 위 다섯 행과 그 특성의 핵심 운용 원칙만 보이는지, 기존 비대상 본문이 byte-identical인지, 모바일 표 내부 스크롤/기술 설명/메뉴를 유지하는지 확인. 글자 수 맞추기·장식적 원리 설명만 넣은 요약은 금지.

실제 이 기준으로 재편집한 생존 검토본 기록은 [Survival chat-first run](CHAT_FIRST_RUN_SURVIVAL_20261111.md) 참고. 다른 전문화의 기존 요약 구성이 더 충실하다면 그 내용을 축약해서 다섯 행으로 강제하지 않으며, **사용자가 원했던 단일·광역·오프너 4구분과 핵심 운용 원칙을 최소 요건**으로 유지한다.

## F. 실제 결과 확인

1. 입력 정본 SHA와 결과 SHA, 기존 전문화 `manual-view` 바이트 동등성 보고.
2. 신규 전문화의 메뉴 표시, 영웅 전환, ST/AoE 분기, 관련 기술 링크, 표 개수/행 개수, 주요 `?`/`!`·툴팁 정상 여부 확인.
3. 가능할 때 HTML/JS 정적 검사·브라우저에서 데스크톱/모바일 테스트. **스크린샷은 사용자에게 보내지 않는다**.
4. 게임플레이 사실 검증은 구조·기능 테스트와 별개임을 표시. 대표적인 메커니즘·상충 조건과 대응 출처를 점검한다.
5. 실패한 테스트는 해결 후 전달하고, 미해결은 정확히 고지. 실제 검증을 수행하지 않았다면 'PASS'를 주장하지 않는다.
