**비공개 정본:** 현재 기준 7전문화 원본 `wow_rotation_manual_engine_v2.html`, SHA-256 `5d70279c4dd073eccef1f3b13565a8f555cd81c9f0a5b7eda7e3485e410742be`. 매 실행마다 실제 프로젝트/대화 첨부 및 접근 가능한 개인 Library를 검색해 **원본을 직접 확인**한다. 사용자가 승인한 새 HTML이 정본으로 등록됐다면 그 버전을 우선한다. 파일 접근이 안 되면 파일이 없다는 사실을 알리고, 없는 원본을 재구성했다고 주장하지 않는다. 비공개 V11·실제 HTML 결과는 공개 GitHub에 올리지 않는다.

**작업 판정:** 기본 원본의 7전문화에 있으면 UPDATE, 없으면 CREATE. 사용자가 `신규`, `업데이트`, `설명 보강`, `기존 유지`를 명시하면 그 의도를 우선한다. 사용자가 `비전 마법사`만 입력하면 비전 CREATE 대상으로 처리하고, 기존 비전 자동 생성 JSON은 참고만 하며 **직접 제작한 원래 7개 V11의 완성도를 최소 기준으로 삼는다**.

**집필 방식의 최상위 조건:** **원문-우선(source-first), 논리-우선(condition-first)**으로 작성한다. 기존 7개 전문화의 사용 가능한 조건표를 전부 참고하고, 실제로 중요한 빌드·영웅·대상·버프·중첩·재사용 대기시간의 **상태 → 판정 조건 → 행동 → 이유/예외**를 근거 URL/패치와 연결한다. **규칙을 만들기 전에 생성기/표/장 수를 정하지 않는다.** 기존 V1/V2 생존 초안의 일반론/2열(행동·이유) 템플릿을 재활용하지 않는다. **사용자 지정 출처가 없으면 Wowhead 하나를 기본 편집 원문**으로 정하고 보조 공략은 꼭 필요한 오류·예외 확인에만 사용한다. 출처 수를 품질 목표로 삼지 않으며 서로 다른 로테이션을 합치지 않는다. **모든 전문화에서 [SOURCE_ACQUISITION](SOURCE_ACQUISITION.md)의 선택형·접힌 원문 확보 게이트를 반드시 적용**한다. 마스터/영웅 선택별 하위 탭·단일/광역·빌드·Further/Advanced·접이식·hover·대체 오프너·타임라인의 실제 본문과 상위 선택 맥락을 모두 확보한다. 관련 `?`는 본문 전수와 가능한 위치·인접 기술을 기록하되 정확한 행/DOM ID 귀속 전수 증명은 요구하지 않는다. 내용의 상관관계는 ChatGPT가 분석하고 실전 판단을 바꿀 모호함에서만 원문 연결을 추가 검증한다. 본문 누락 Gate A와 의미 해석 미해결 Q0/Q1을 분리한다. 원문 확보와 집필 압축을 분리한다. `빌드에 따라 달라진다`는 문장을 쓸 때는 실제 어떤 빌드에서 행동이 어떻게 바뀌는지까지 써야 한다. 원문 조건과 충돌하는 오프너/우선순위, 선택 특성 ON/OFF, 임계값 경계 상황을 **실제 주요 판단 분기의 범위에 맞춘 독립 반례**로 점검한다. 고정 문제 수를 채우는 것으로 완료 판정하지 않는다. **더 좋은 구조가 있으면 제안·적용 가능하며, 단일 표/장수/글자수를 강제하지 않는다.**

**자동 집필 순서:** (1) 기존 승인된 V11와 요청 전문화 검토 (2) 사용자가 제공한 원문이 있으면 우선, 없으면 최신 외부 공략의 실제 패치·영웅 특성·단일/광역·오프너 등 확인 (3) 원리, 조건, 예외, 비교표, 기술 아이콘·툴팁, `?`/`!`, 고급 팁, 장 구성까지 독자적으로 상세 집필 (4) 기존 비대상 `manual-view` **바이트 단위 동일**하게 신규 장 삽입 또는 부분 갱신 (5) 가능한 실제 HTML/JS·메뉴/영웅 전환·모바일 검증 (6) 비공개 HTML 파일 링크·변경 내역·불확실한 게임 조건·출처 제공.

**품질/안전:** 개발과 변경은 먼저 **왜 독자의 판단과 이해가 실제로 좋아지는지** 검토한다. 개별 전문화 결과보다 범용 제작 지식·검증법을 우선한다. 게임 상태에 따른 시전 결정을 독자가 스스로 재현할 수 있어야 한다. 표의 기본 열은 **순위 / 행동 / 사용 조건**으로 독립시킨다. 첫 화면은 단일/광역 지속 딜과 각각의 오프너, 필수 주의사항 및 그 아래 핵심 운용 원칙을 실전용으로 정리한다. 결과물의 품질은 글자 수·아이콘 수·HTML 기능 PASS가 아니라 **정확한 조건, 수치, 메커니즘, 반례 처리**로 평가한다. ## 실제 시범 PASS 기준

1. 사용자 입력 `비전 마법사` 한 번으로 시작.
2. 위 실행 정본과 실제 V11 정본 읽기·해시 검증.

7. 사용자가 추가 요청 없이 모든 것을 완료할 수 있었는지 기록.
