- 첫 화면 **비전의 여파** 발동 시점을 **비전 탄막·오색 화살 투사체 비행 중 또는 비전 쇄도 잔여 ≤13초**로 표시. 상세 오프너의 실제 시전 순서는 보존.
- V31에서 삭제한 가상의 실전 사례 장을 비전 소개에서 여전히 언급하던 잔여 문구를 제거.
- 이전 인계의 실물 Q4: V31 대비 비전 외 **8개 전문화 DOM 동일**, 공용 JS/CSS 동일, 비전 상세 36 ↔ 첫 화면 36·두 오프너 각 7단계 동일. Chromium JS 활성 320·360·390·800·1365px × 양 영웅 특성 전환, 기술 툴팁/ESC, 가로 넘침 0·JS 오류 0. **이는 기록된 기능 검증 결과**이며 이번 인계에서 CI/브라우저 QA를 불필요하게 재실행하지 않았다.

## 3. 사용자가 직접 확정한 편집·UX·검증 원칙 — 최우선 유의사항

1. **비전 V29의 표현을 품질 기준으로 재사용:** 사용자는 첫 화면의 **정확하고 짧은 한국어 축약어·부등호·숫자·아이콘·조건 묶음·줄바꿈**을 매우 긍정적으로 평가했다. V22 성난태양 / V23 서리불꽃도 가독성 긍정. 성능 정답·V32 최종 승인과는 구분.
2. **가상 실전 사례 사용자 장 금지(최신 강한 지시):** V29 10개 → V30 5개로 줄인 뒤 **V31부터 「06 실전 상황별 판단 예시」 전체 삭제**가 사용자 최종 결정. 무엇을 실제 유저가 혼동하는지 입증할 수 없고 가정 상태별 '실전 경험'을 지시하는 것은 정확성 책임 범위 초과. **내부 상태→조건→행동 반례·모순 검증은 유지하되 사용자 교본에서 별도의 합성 실전 시나리오 장을 다시 만들지 않는다.** 과거 '선별 5개' 제안은 철회·대체된 이력이다.
3. **영웅 특성별**을 정식 표현으로 사용(`영웅별`처럼 모호한 표현 금지). 공식 한국어 기술명·버프명은 임의 축약 금지. `ST/AoE/T/AP/CD/GCD/DoT` 같은 단독 영문 약어, `balance-keeper-st-in-2` 같은 식별자 사용자 노출 금지. 자원·쿨·연사·충전 등의 **처음 한 번 정의한 한국어 약어**, `≥, ≤`, 중첩 수치는 조건 논리를 보존하며 적극 활용.
4. **트래킹 가능한 기술·강화·발동 명칭은 위치 무관 아이콘/툴팁 연결:** 첫 화면뿐 아니라 조건·오프너·원리·심화·제목/본문에도 실제 확인된 대응 아이콘을 사용. 불명확한 공식 아이콘은 다른 아이콘으로 꾸미지 않고 REVIEW.
5. **첫 화면 완전성:** 단일/광역 지속 우선순위 전부, 실제 오프너 시전 순서, 핵심 번호 원리, 자원/쿨 연계를 빠르게 판독할 수 있어야 함. 지속 딜 `→`는 **조건부 우선순위**, 오프너 `→`는 **실제 순서**. 상세표 `순위 / 행동 / 조건` + 짧은 이유. 장식성 박스·반복 안내는 줄이며 장/표/오프너 수 기계적 고정 금지.
6. **조건 추출과 선별 분리:** 패치/빌드/영웅 특성/선택 특성/대상 수/세트가 같은 기준 원문을 고정하고 **원문 모든 동적 선택/숨김 하위 탭/도움말/오프너/투사체·시간 수치**를 확보한다. OR→AND 왜곡, 독립 두 우선순위 합병, 숨긴 HTML 텍스트를 동시 발동으로 오판, 복합 단계의 부가 효과를 추가 시전으로 오해, 포션 조건부 슬롯을 연속 중복 사용으로 표현하는 오류 금지. 원문 내용을 **완전히 수집**하는 일과 독자가 볼 **간결한 교본을 작성**하는 일은 다르다.
7. **출처 버전 혼합 금지:** 동일 와우헤드 URL을 일반 열람하면 오래된 **12.0.7/12.1.0 캐시**가 오는데 검색 색인에서는 **12.1.5 / 2026-10-16** 등 최신 수정본이 보인 경우가 있었다. 본문 실물을 직접 확보하지 못한 선택형 조건을 *확보 완료*라고 기재하거나 과거/다른 영웅/다른 빌드 문장을 합치지 않는다. 초안 JSON이나 실패 HTML을 게임판단의 기준 소스로 사용하지 않는다.
8. **Q0(사실·패치/주문), Q1(실제 다음 행동), Q2(이해), Q3(가독성/실전 사용성), Q4(HTML/JS/기존 본문 보존)를 구별.** Q4 PASS·CI success는 Q0/Q1 정답이 아니다. 사용자 **최종 승인**도 별개의 상태다.
9. **도구 과잉 개발 금지:** 신규 검사기·스키마·독립 API·Codespaces/웹앱을 최종 목표처럼 개발하지 않는다. 기존 비교/Chromium/QA와 직접 원문 수동 검증으로 해결 가능한 문제는 작은 범위에서 종료하거나 REVIEW 처리한다.
