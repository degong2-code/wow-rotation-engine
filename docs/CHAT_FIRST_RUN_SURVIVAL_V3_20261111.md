## 1. 기존 V11 일곱 전문화 전체의 강점

| 기존 전문화 | 직접 관측한 콘텐츠 구조/결정 변수 | 재사용해야 할 품질 원리 |
|---|---|---|
| 화염 마법사 | 발화 중/외·몰아치는 열기·30% 이하 실행 구간; 4개 우선순위 표 / 27행 | 시점·구간에 따라 **동일 버튼의 우선순위를 분리** |
| 냉기 마법사 | 주문술사/서리불꽃·단일/광역 4표 / 42행; 빙결 6/12중첩 | 특성·중첩 **임계값을 해당 행에 명시** |
| 냉기 죽음의 기사 | 단일/광역 2표 / 26행; 룬 무기 강화 2충전·도살기 중첩 | 제한된 자원과 충전의 **낭비 방지 조건** |
| 사격 사냥꾼 | 단일/광역 2표 / 22행; 정밀 사격·교묘한 사격·세트 분기 | 사용 기술뿐 아니라 **소비해야 하는 버프와 대상 수**를 표시 |
| 야수 사냥꾼 | 단일/광역 2표 / 13행; 야수의 격노 3초·날카로운 사격 2충전 | 길지 않은 표에도 행동 시점이 **수치로 결정 가능** |
| 잠행 도적 | 그림자 춤 중/외, 연계 점수 6 이상; 5표 / 15행 | **상태 전환과 생성기/마무리 기술**을 구분 |
| 암살 도적 | 영웅 빌드별 단일/광역 4표 / 32행; 출혈·연계 점수 5점 | 유지 효과/자원/쿨기 사이 우선권을 **상세한 조건**으로 분리 |

가장 중요한 공통점은 *표·아이콘·문장 수가 아니라 독자가 다음 GCD를 고를 수 있다는 것*이다. V11의 기존 7개는 모두 우선순위의 '순위 / 행동(기술) / 조건' 구조를 활용한다. 화염의 특수 발화 구간처럼 서로 다른 전문화는 서로 다른 설명 구조를 가져도 좋다.

## 2. V2 생존 교본의 근본적인 실패

1. **2열 템플릿이 원인:** 최초 일회성 생성 스크립트의 `priority(title, rows)`가 `(action, reason)` 두 입력만 받고 `우선/기술·조건/왜 이 순서인가`를 만들었다. <b>조건만 별도로 검증할 필드가 없었다.</b>
2. **동일 패치/특성 범위의 고정 실패:** Wowhead·Method·Icy Veins 문장을 무리하게 혼합해 빌드 경계가 흐려지고, 12.1 PTR 제거 기록이 있는 Flamefang Pitch가 초안에 남았다.
3. **품질 기준 오류:** 10장·38개 행·다수 아이콘·세 자료 통합 등의 수량에 주목하면서, 창끝 2 vs 0 같은 독자의 실제 행동 분기를 검증하지 않았다.
4. **반례/모순 검사 부재:** 제압 전후의 창끝 중첩, 파수꾼 붐스틱 제압 전 배치, 무리의 지도자 제압 뒤 첫 살상 명령, 쌍둥이 송곳니와 쇄도의 과충전 충돌 등 조건이 **한 문단 안에서 서로 충돌**할 수 있는데 확인하지 않았다.
5. **반복적 회피 문장:** `상황에 따라`, `특성에 따라 다름`으로 미해결 메커니즘을 덮었다. 소스가 갖고 있던 구체적인 수치·원리를 제품 문구에서 삭제했다.
6. **범위가 좁은 패치:** V2 Quick Reference 수정은 overview 한 영역만 교체하여 근본적으로 잘못된 우선순위·오프너 본문을 수정하지 못했다.
7. **콘텐츠 품질과 UI PASS 혼동:** JS 정상 동작, 7개 본문 보존은 훌륭한 테스트지만 신규 생존 교본이 게임플레이상 옳다는 증거가 아니다.

따라서 이번 실수는 기존 자동화 엔진 파일을 그대로 사용했기 때문만이 아니라, *자체 편집 템플릿/다중 출처를 먼저 설정하고 실제 조건을 나중에 채우는* **생성 방식의 오류**다. 입력 정보량이 많다는 사실 자체보다는 서로 다른 빌드의 조건을 선별·고정하는 기준이 없었다는 점이 결정적이다.

## 3. V3의 달라진 접근과 결과

- 원본 V11을 **설명 품질 비교 기준**으로만 사용하며 장 수/표 수를 강제하지 않음.
- Wowhead 12.1.5를 중심으로 선택 특성과 주 기준을 정한 뒤 **논리식·원인·예외를 먼저 작성**.
- `순위 / 행동 / 사용 조건·판단 기준` 3열의 **4개 표/37행**으로 영웅·단일/광역 분리.
- `한눈에 보는 딜사이클`: 영웅별 단일·광역 순환/오프너/핵심사항 + 아래 핵심 운용 원칙. 첫 화면만으로 실제 스킬 판단을 시작할 수 있게 수치/트리거 표기.
- 제압: **쌍둥이 송곳니 미선택 = 창끝 ≥2**, 선택 = **창끝 0**; 생성 3/소비 1, 8초+20% 효과 및 1초 차이 두 타격 원인.
- 파수꾼: 표식은 창끝 **소비**로 발동 가능, 폭탄은 표식 대상 또는 완충 **4~6초 전**, 달빛 회전 표창/추적과 타격 선택 시 폭탄 CD **10초 감소**.
- 무리의 지도자: 제압 뒤 **첫** 살상 명령으로 쇄도; 약 **30야드 직선/7초** 위치 결정. 쌍둥이 송곳니와 살상 명령 재생성 사이 실제 중첩 낭비 충돌도 명시.
- 붐스틱: **집중 50 / 전방 20야드 / 약 3초 채널**, 치명적 보정 폭탄 대상당 **2초 최대 10초** 재사용 감소.
- 랩터의 휩쓸기: 랩터의 일격 **두 번째**마다 강화. 야생불 폭탄 직접 피해/6초 DoT의 강화 범위를 구분.
- PTR 제거 기록의 Flamefang Pitch를 **우선순위/시전 기술에서 제외**.
- 내용 간결화: V2 전체 텍스트 16,172자 → V3 12,796자(약 **20.9% 감소**), 장 10→8, 우선순위 표는 4개 유지. 개수·길이 감소를 자동 품질 보증으로 취급하지 않음.
- 기존 7개 본문을 손대지 않는 메뉴 구조 유지. 복제한 V2 이전 결과물을 임시 기반으로 활용하되 생존의 `manual-view`는 전면 재집필. 7개 기존 본문은 raw byte-by-byte 검증.

## 5. 재사용 금지/재사용 권장

**재사용:** 원본 V11의 실제 조건/행동 분리, 숫자 명시 방식, 기존 아이콘·툴팁·메뉴 CSS/JS, 비대상 본문 원형 보존 검사, 실전 판단 사례 테스트.

**금지:** V2 생존의 2열 우선순위 템플릿, 이전 AI 초안의 뭉뚱그린 문장, 같은 패치·특성인지 확인하지 않은 자료 결합, 빠진 조건을 `상황에 따라`라는 단서로 대신하기, 글자·표·아이콘 수를 콘텐츠 품질로 간주.

**정본:** 이번 V3는 사용자가 검토할 새 결과이며 아직 최종 정본 승인 여부를 확인하지 않았다. 사용자 승인 이전에는 7개 기존 V11의 보존 지침과 다른 개인 산출물을 덮어쓰거나 `main`에 병합하지 않는다.
