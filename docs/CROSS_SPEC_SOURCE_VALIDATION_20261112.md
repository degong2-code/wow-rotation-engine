# 범용 원문 확보 — 다전문화 실자료 조사·구조 반례 (2026-11-12)

> **2026-11-12 최신 정정 — 이 문서는 과거의 검색 색인 기반 예비조사입니다.** 이후 실제 Wowhead 12.1.5 HTML을 HTTP로 취득했고, 사용자가 확인한 고양 저장본과 WHML SHA가 일치했습니다. 특히 아래 표의 ‘물약명은 분기 근거가 아니다’와 예시 분기 관련 문구는 **과거 가설로서만** 보존합니다. 실제 고양의 물약별 기술 시전 시점 차이가 확인됐으므로 최신 제작에는 [실물 역검증](HISTORICAL_REGRESSION_AUDIT_20261112.md) 및 [원본 취득 규격](AUTO_PAGE_ACQUISITION.md)을 우선합니다. 생존·비전에서도 실제 원문 취득이 확인됐으나 모든 패치·실전 메커니즘의 독립 승인으로 확대하지 않습니다.


**목적:** 고양 주술사 전용 수정에서 벗어나 다른 전문화의 실제 공략이 제공하는 선택 유형을 확인하고, 범용 검사기가 적어도 이런 구조를 빠뜨리지 않는지 검증한다. **실제 Wowhead 라이브 DOM을 직접 확보한 보고서는 아니다.**

### 발견한 원문 취득 문제

- 냉기 마법사 같은 URL에서 검색 색인은 **2026-10-13 업데이트**를 보여주지만 직접 웹 열람은 **2026-04-20 / 12.0.7**을 반환했다. 버전이 다른 두 표현을 하나의 현재 규칙으로 결합하지 않는다.
- 웹 검색 색인은 탭·영웅 특성을 텍스트로 나열할 수 있지만, **실제 `?` 개수·부모 행·하위 선택지 전체·동적 렌더링**의 독립 검증은 제공하지 못한다.
- 사용자의 브라우저 연결이 없는 실행 환경에서는 실제 탭을 열어 UI를 확인할 수 없었다. 이 점은 범용 구조 검사기 구현만으로 해결되지 않는다.

## 회귀 테스트 (실제 자료의 '구조'에서 동기를 얻되 본문·기술은 전부 합성)

`tests/test_source_coverage_cross_spec.py`는 세 가지 전문화 비종속 UI 형식으로 시험한다.

1. 두 영웅 특성 → 단일·광역 → 오프너 하위 상태: 하나라도 비면 `unvisited_choice`.
2. 영웅 A에서만 추가 토글이 나타나는 구조: 영웅 B에 존재하지 않는 조합을 강제로 만들지 않고 A의 ON/OFF 누락만 찾음.
3. 물약 두 종류를 예시로 표시하는 오프너: 선택한 물약을 새로운 기술 시퀀스로 자동 확대하지 않음.

추가로 검색 색인만 있는 상태는 `inventory_not_checked`, 같은 URL이지만 수정본이 다른 수집은 `source_version_conflict`, 본문 없는 `?`는 `missing_content`를 유지한다. **합성 테스트 통과는 실제 세 전문화의 Gate A PASS가 아니다.**

## 현재 상태와 다음 과제

정적 HTML 탐색기·WHML 해석기·후보↔원문 대조기는 재사용 가능하게 구현되어 있다. HTML SHA-256 및 URL·패치·수정본 결합으로 **다른 원문을 같은 자료로 오인하는 오류**를 차단한다. 그러나 최신 원본에 직접 접근해 JS 렌더링 후의 모든 선택지와 `?`를 발견하는 일은 아직 미완료이며, 범용화의 다음 실증 과제다.

**개인 원본·와우헤드 장문 공략 텍스트는 공개 저장소에 복사하지 않았다.**
