## 5. 반드시 승계할 디자인·한국어 UI 요구

1. 기존 V11처럼 **처음 열자마자 플레이**: 단일/광역 지속딜 우선순위, 단일/광역 오프너, 주요 쿨 연계, 자원/중첩 관리, 숫자로 나눈 핵심 원리. 2열 첫 화면 표와 상세 3열 `순위/행동/조건`을 필요에 맞게 사용.
2. **아이콘 + 공식 한국어 기술명 + 툴팁을 한 요소로** 연결하고, `→`로 우선순위 표현. 지속딜 `→`는 **왼쪽부터 조건 검사**, 오프너 `→`는 **원문 실제 시전 순서**. 같은 의미로 혼합하지 않는다. 기본 판단 이유는 `?` 툴팁에 숨기지 않고 조건 가까이에 짧게 공개한다.
3. **영웅/빌드/선택 특성으로 서로 다른 원문 내용은 해당 선택에서만 노출.** 선택하지 않은 스킬 행/오프너/심화 예제/빠른 요약은 숨김. 외부에서 확인되지 않은 게임 상태를 조작하여 다른 분기의 조건을 끼워 넣지 않는다. `화신` 활성 중 `일월식` 일반 재시전과 오프너의 선행 일월식→화신을 혼동하지 않는다.
4. 설명을 감싸는 **큰 박스·장식 테두리·반복 경고/장황한 텍스트를 지양**. 기존 V11의 표·여백·접이식 메뉴 중심으로. 스크린샷 별도 미리보기 제공 불필요; **HTML 내부 스킬 아이콘은 필수**.
5. **사용자 화면에 기술 키를 노출하지 않음**: `balance-keeper-st-in-2`, snake_case, 내부 주문 ID/아이콘 파일명, 기계식 로마자·영문 약어 노출 금지. 숨겨진 JSON·`data-*`에는 출처 연결을 유지. 사용자에게 보이는 제목, 표, 툴팁, 목차, 접근성 문구, 복사 텍스트 전부 확인.
6. **한국어 간단 표기:** 대상 수, 천힘(천공의 힘), 쿨(재사용 대기시간), 전역 쿨, 단일, 광역, 지속 피해, 발동, 강화 효과. 첫 등장 한 번 정의. `T/AP/CD/ST/AoE/GCD/DoT`의 단독 사용자 표시는 금지. 수치 `≥/≤`, 논리 `∧/∨` 보존. 모호하면 정식 한국어 명칭을 사용. 공식 게임 기술명 자체는 임의 축약/변경하지 않는다.
7. 영웅 수·장 수·표 수·오프너 수를 V11이나 조화 한 사례에 맞춰 고정하지 않는다. **범용화할 것은 소스 이해·게임 판단·표현 및 회귀 품질 방법**이다.

## 6. 원문 정확성에서 반복 금지할 과오

3. 근거 있는 오류만 수정해 개인 단일 HTML 검토본을 제공, 기존 V11 7개 본문을 보존. 사용자 Q3 피드백을 최우선으로 반영한다.
4. 공통 제작법에 실제 재발 방지 가치가 생긴 부분만 GitHub 문서에 기록. 새 검사기 개발, CI 숫자 늘리기, 소소한 마커 조사에 매몰되지 않는다.
