# SOURCE_ACQUISITION — 교본 공략 자료 자동 확보·검증 규칙

> ChatGPT가 채팅에서 전문화 이름만 받았을 때 실행하는 **공개 원문 위치 탐색 지침**. 다른 사이트의 공략 전체를 GitHub에 보관하거나 무단 재게시하는 자료 창고가 아니다.

## 1. 탐색 순서

**1순위: 사용자 지정 자료.** 채팅에 URL·텍스트·파일을 제공하면 우선하되, 패치·특성·대상 수가 실제 요청과 일치하는지 확인.

**2순위: 사용자 지정이 없을 때 Wowhead 하나를 기본 기준 공략으로 선택.**
- [Wowhead 직업 가이드](https://www.wowhead.com/guides/classes) — 전문화의 Rotation/Cooldowns/PvE를 기본 원문으로 선택하고 패치/빌드/영웅/대상 수와 간편판·상세판의 차이를 확인한다.
- **조건부 보조 검증:** [Icy Veins WoW](https://www.icy-veins.com/wow/), [Method WoW Guides](https://www.method.gg/guides) 등은 기준 자료의 누락·모호함·상충 또는 삭제된 기술 등 구체적인 의문을 해결해야 할 때에만 해당 부분을 대조한다. **기본적으로 복수 공략을 수집하지 않는다.**
- **기술 사실 확인:** [Blizzard WoW 직업 안내](https://worldofwarcraft.blizzard.com/ko-kr/game/classes), 해당 패치 노트, 실제 주문 페이지의 기술 유효성·ID·변경 사항을 확인한다. 이는 다른 사이트의 전체 로테이션을 합치는 것과 다르다.

위 사이트의 접근 정책·이용 조건을 준수하고, 직접 확인할 수 없는 원문을 실제로 확인했다고 쓰지 않는다. **위 목록은 무조건 모두 조사하라는 체크리스트가 아니다.** [QUALITY_FIRST_POLICY](QUALITY_FIRST_POLICY.md)의 최소 필요 근거 원칙을 따른다. 일반 검색 결과의 검색 날짜만으로 '최신'이라고 확정하지 않는다.

## 2. 검색 질의 구조

먼저 버전·레이드/시즌·직업·전문화를 확인한다. `{CURRENT_PATCH}`와 `{SPECIALIZATION_EN}`는 **실제 발견된 값**으로 대체하고 문자열 그대로 검색하거나 오래된 버전을 추측해서 넣지 않는다.

예시 (검색 식이며 확인 완료된 URL이 아님):
- `{SPECIALIZATION_EN} WoW {CURRENT_PATCH} rotation cooldowns raid single target aoe`
- `{SPECIALIZATION_EN} {CURRENT_PATCH} opener hero talents detailed priority`
- `site:wowhead.com/guide/classes {SPECIALIZATION_EN} rotation`
- `site:icy-veins.com/wow/ {SPECIALIZATION_EN} rotation cooldowns`
- `site:method.gg/guides {SPECIALIZATION_EN} rotation`
- `{SPECIALIZATION_EN} buff proc tier set spell ID Korean localized`

동시에 확인할 필드:
- 페이지 제목, URL, **게시/수정일과 실제 적용 패치**, 작성자의 범위, 빌드/영웅 특성, 대상 수, 매크로/특수 상황, 최신 패치와의 일치.
- 우선순위 행별 **조건과 예외**, 특성/버프/리소스/세트 효과의 전제, 간략판·상세판의 차이.
- 다른 출처를 **실제로 사용한 경우에만**, 해당 쟁점의 조건 차이·패치/빌드·작성자/파생 출처의 독립성 여부를 기록. 출처가 하나라면 단독 기준이라고 명시할 뿐 사이트 수를 채울 필요는 없다.
- **추출 충실도:** 선택한 영웅 특성 탭·접힌/동적 표·오프너 단계·선택 특성 분기의 문맥이 텍스트 수집 과정에서 소실되지 않았는지 확인. 잃어버린 조건을 한 시퀀스로 합성하지 않는다.

### 선택형·접힌 원문 확인 — 모든 전문화의 필수 확보 게이트

**완료의 의미:** 원문의 유효한 선택별 실제 **본문·조건·선택 맥락**을 빠짐없이 확보한다. `?` 팁은 실제 모든 관련 설명 본문을 확보하고, 가능한 위치·주변 문맥 단서를 수집한다. 특정 DOM ID·우선순위 행과의 정확한 연결을 전부 증명하는 것은 수집의 필수 조건이 아니며 의미적 귀속과 행동 판단은 다음 Q0/Q1 단계에서 수행한다. 해석에 영향을 주는 모호함에서만 원본 연결을 추가 조사한다. 신규 CREATE/전체 UPDATE 및 관련 범위 국소 UPDATE에 적용한다.

| 실제 원문 UI 유형 | 확보 범위 |
|---|---|
| Hero Talent Master Switches 등 전체 페이지 전환 | 각 영웅/전문화/빌드 상태마다 변경되는 모든 관련 영역 |
| 지역 탭(예: Major Cooldowns) | 각 쿨다운·발동·장신구 탭의 실제 내용 |
| Fight Style / 선택 특성 / 오프너 / 대상 수 | 실제 전투·빌드별 기술 시퀀스·조건·팁. **물약은 별도 오프너 분기가 아니라 시퀀스 내 사용 시점**으로 기록; 이름은 예시 |
| Further Details, Advanced, Notes, Talent Swaps 등 | 접힌 영역의 본문 및 펼친 뒤 나타나는 하위 내용 |
| 기술 옆 ?·!·hover·정보 아이콘 | **모든 실제 관련 설명 본문**과 가능한 위치 단서(영웅·전투 선택/섹션/표·행/인접 기술·조건). 정확한 행 ID 귀속 전수 입증은 필수 아님 |
| Sample Timeline·Alternative Opener·이미지·동적 표·링크된 관련 페이지 | 행동·시간·조건을 바꾸는 실제 정보와 필요한 맥락 |

**범용 자동 누락 감사(선택적 보조):** [SOURCE_COVERAGE_AUDIT](SOURCE_COVERAGE_AUDIT.md)의 오프라인 검사기가 실제로 관측해 기록한 중첩 선택지·툴팁 본문·패치 충돌을 검사한다. 전문화 전반에 재사용하지만 원문 DOM을 가져오는 크롤러가 아니며 **관측하지 못한 실제 UI 요소는 자동 발견할 수 없다**. 결과의 declared_coverage_candidate는 Gate A 독립 검증 완료와 다르고, 원문 의미 분석·HTML 최종 QA를 대체하지 않는다.

### 오프너의 물약 사용 — 종류가 아니라 시점 (2026-11-12 사용자 확정)

- **오프너의 분기 축:** 실제 기술 순서·조건이 달라지는 **영웅 특성, 단일/광역, 관련 특성/전투 조건**. 물약 종류 자체로 별도 오프너를 만들지 않는다.
- **원문의 물약 이름:** 특정 가이드가 제시한 예시·선택 가능한 소비재다. 사용자가 장비·상황에 맞춰 고르며, 교본은 해당 시점에 **`물약 사용`**을 배치한다. 특정 제품을 필수로 권하거나 모든 물약을 차례로 사용하도록 표현하지 않는다.
- **실제 수집 대상:** 기술의 **전투 전·전투 시작·버스트 구간 순서**, 물약 사용 위치, 원문이 시점에 부여한 조건이다. 검색 색인에 Liquid Luster, Potion of Recklessness, Light's Potential가 나란히 등장한다고 해서 **세 개의 오프너**가 있다는 증거는 아니다. 물약별 고유 효과·타이밍이 명시됐더라도 통상적인 오프너 기술 순서와 구별해 **선택형 참고**로 처리한다. 특별한 소비재가 실제 **기술 순서를 변경한다고 명시될 때만** 그 효과의 조건을 개별 확인한다.
- **QA:** 영웅×단일/광역 오프너의 행동 순서 보존, 물약 슬롯의 유무·위치, 물약 선택에 따라 기술 순서가 근거 없이 달라지지 않았는지 검증한다. **물약별 기술 시퀀스의 전수 검증은 Gate A 요건이 아니다.** 본문의 다른 선택형·접힌 자료와 `?` 팁 전수 확보 요건은 변하지 않는다.

**완료 불가 항목의 명시(고양 V3 사례):** 영웅별 Notes 전부, 실제 관련 `?` 본문 전부, 오프너 속 물약 사용 시점, 마스터 선택 뒤 하위 분기를 반드시 확인한다. 텍스트는 확보했으나 정확한 행 연결을 모른다면 `내용 확보·위치 미확인`으로 기록한다. **본문 누락·상호 배타적 시퀀스 혼합은 Gate A FAIL**, 본문이 있지만 적용 의미가 모호한 경우 **Q0/Q1 REVIEW**로 구분한다. 클릭/호버 수행만으로 완전 수집을 입증하지 않는다.

**같은 URL의 패치 충돌 차단(필수):** 해당 공략의 **실제로 반환된 텍스트**에서 페이지 표시 수정일·패치·시즌을 확인한다. 직접 열람·검색 색인·접힌/선택 상태·언어/라이브/PTR 접근 사이에 **같은 URL인데도 날짜/패치가 다르면** 현재 자료의 통일성이 검증되지 않은 것이다. 서로 다른 날짜의 우선순위·툴팁을 묵시적으로 합치지 않는다. 최신 날짜가 명시된 접근 표현을 특정 규칙의 잠정 근거로 사용할 수 있지만, 실제 상태별 원문이 동일 버전인지 확인할 때까지 전수 확보 PASS는 보류한다. **우선순위 행 수와 관련 `?` 팁 개수는 별개**다. 실제 각 상태에서 나타난 모든 팁을 확인해야 하며 임의로 1행=1팁을 가정하지 않는다. [사례집 §23](QUALITY_GENERALIZATION_CASEBOOK.md).

**우선 처리 방식(2026-11-12 사용자 확정): 관련 본문 전수 + 가능한 표시 위치·문맥 수집을 최우선**으로 한다. 검색 색인·정상 제공 텍스트를 먼저 활용하고 접근 가능한 HTML/DOM/WHML/내장 JSON·스크립트에서 숨겨진 본문과 위치 단서를 보강한다. 화면에 접혀 있다고 데이터까지 없는 것은 아니다. **정확한 행 참조 복원을 위해 실제 내용 확보가 불필요하게 지연되지 않도록 한다.** 다음 기술 단계는 접근성과 누락 여부에 따라 선택한다.

1. **HTML 원본**의 비활성 패널·숨김 블록·접힌 설명·팁 및 페이지에 내장된 자료를 조사한다.
2. 가능하면 **라이브 DOM**에서 `?`의 상위 탭·섹션·표/행·인접 기술·주변 텍스트를 위치 단서로 기록한다. `hidden`, `aria-hidden`, 탭/패널·참조 ID는 필요한 만큼 조사한다. **전수 ID 검증을 수집 완료의 필수 요건으로 삼지 않는다.**
3. **스크립트에 포함된 JSON/데이터 객체/템플릿**에서 로테이션 분기·선택형 Notes·툴팁의 본문과 조건을 확인한다. 출처 패치·페이지 수정일을 결합해 다른 버전의 결과와 혼합하지 않는다.
4. 위 자료만으로 아직 부족할 경우에만 **사이트가 정상적으로 제공하는 네트워크 데이터**가 선택 시 추가로 로드되는지 살핀다. 외부 접근 제약·사이트 정책을 준수한다.
5. 그 후에도 불명확한 **실제 동작 차이**에만 필요한 최소한의 UI 클릭/호버로 검증한다. 수백 건 수동 클릭이나 로컬 앱 설치는 기본 경로가 아니다. 사용자 개인 브라우저 사용은 앞선 경로가 불가능한 최후 대안으로 협의한다.

**완료 판정 2단계(2026-11-12 최신 정책):** **Gate A=관련 실제 내용의 완전성**(버전·유효 선택별 본문·관련 모든 `?` 본문). `?`의 위치는 가능한 단서로 기록하지만 정확한 행/ID 연결 전수 증명은 강제하지 않는다. **Q0/Q1=의미·실전 판단 정확성**(ChatGPT가 기술·상태·조건·행동·예외의 상관관계 분석). 행동이 바뀌는 중요한 모호함에만 원본의 정확한 연결을 재확인한다. 핵심 본문 누락=Gate A FAIL, 본문 확보·중요 의미 불확정=Q0/Q1 REVIEW. 최종 교본은 두 단계가 해결돼야 승인 가능. 현 고양 V3.7은 여전히 원문 전수 확보가 확인되지 않았다.

**Wowhead 내부 마크업에 대한 실제 근거(2026-11-11 확인):** 공식 [Advanced WHML 문서](https://www.wowhead.com/guide/advanced-wowhead-markup)는 `toggler`·`tabs`를, [작성 안내](https://www.wowhead.com/guide/help)는 `tooltip name`·`span tooltip` 참조를 설명한다. 원본 WHML/DOM이 접근 가능하다면 표시 위치와 설명 본문을 효율적으로 수집하는 데 사용한다. **정확한 대상 행 참조가 밝혀지면 활용하되 전체 항목에 대해 증명할 의무는 없다.** 이 작성 문서가 최신 고양 페이지의 실제 구현을 증명하는 것은 아니다.


### 실제 원본 HTML의 진입점 — 2026-11-11 검증

[공개 Wowhead 실물 HTML 저장본](https://github.com/aurokin/warcraft_cli/blob/main/tests/fixtures/wowhead/guide_3087_page.html)(분노 전사 과거 버전)에서 `WH.markup.printHtml(..., "guide-body", ...)` 호출의 JS 문자열을 복호화해 **WHML 14,037자**를 추출했고 `data.pageMeta` JSON을 확인. 메뉴용 `interior-sidebar-related-markup`와 구분. 동일 원리를 사용하는 [제3자 파서](https://github.com/aurokin/warcraft_cli/blob/main/packages/wowhead-cli/src/wowhead_cli/page_parser.py)도 발견. 원본 HTML을 확보하면 WHML 탭·접힘·명명 툴팁 참조를 분석할 수 있다는 실제 구현 근거다. 개인 오프라인 검사기(표준 라이브러리만 사용)를 작성해 합성 5개 테스트 PASS. **최신 고양 12.1.5 원본 HTML/각 ? 팁→행 연결은 아직 접근 실패**, 따라서 수집 Gate A는 계속 미통과. 접근 제한 우회·사용자 로컬 설치를 기본으로 하지 않음.

**누락 방지 강화(2026-11-11 발견, 2026-11-12 수집 정책 변경):** 공식 WHML 예시처럼 `tooltip`과 `tooltip2`가 동일 요소에 병존할 수 있으므로 모든 관련 설명 본문을 각각 확보한다. 위치·인접 기술·선택 상태가 보이면 단서로 기록하고, 확인되지 않으면 `위치 미확인`으로 구분한다. 정확한 행 ID 연결은 필수가 아니지만 여러 기술에 적용될 수 있거나 실전 행동이 달라지는 모호함이라면 추가 검증한다. 해당 페이지에 팁이 없다는 판정은 실제 관련 영역 확인 후만 내린다.

**실행 순서(필수, 특정 기술 구현에 종속되지 않음)**

1. 페이지 전체의 관련 컨트롤과 섹션을 식별한다. 명칭이나 DOM 클래스의 고정 목록에 의존하지 않고 실제 표시·전환·펼침 동작을 확인한다. 관련 기술/특성·Talents·세트 페이지도 적용 빌드를 이해하는 데 필요하면 확인한다.
2. 상위 마스터 선택 상태별로 페이지 관련 영역을 재확인한다. 각 상태의 하위 탭/단일·광역/선택 특성 등을 전환하고, 나타나는 접힌 영역과 호버 팁을 펼쳐 확인한다. **새 내용/하위 선택지가 나타나면 같은 과정을 반복**한다. 상태와 내용을 연결하고, 해당하지 않는 조합을 임의 생성하지 않는다.
3. 각 선택에서 실제 본문·우선순위 행·하위 조건·오프너 단계·타임라인·관련 모든 팁 **설명 본문**을 확인한다. 팁의 탭/섹션/표·행/옆 기술 등 **관측 가능한 위치**를 함께 기록한다. 본문 확보·위치 미확인과 본문 미확인을 구별한다. 서로 다른 영웅·전투·특성 빌드의 실제 시퀀스를 합치거나 조건 목록을 시전 단계로 승격하지 않는다. 행 수 일치만으로 전수 완료를 주장하지 않는다.
4. 누락은 우선 동일 Wowhead URL의 실제 표시/원문 구조 또는 검색 색인 등 접근 가능한 표현으로 복구한다. 실제 브라우저 조작이 불가능해도 **내용과 선택 상태 귀속이 확인되는 근거**가 있다면 사용 가능하다. 단, 실제 조작과 간접 확인을 구별한다. 결정에 필요한 누락만 보조 출처로 확인하며, 확인되지 않은 기준 원문의 분기를 완전 확보로 주장하지 않는다.
5. 최소 기록: `패치·선택 경로 / 영역 / 본문·근거 / 가능하면 위치·인접 기술 / 내용 상태 / 의미 연관성 확실성`. 본문 누락은 Gate A FAIL, 중요한 의미적 연관성이 불명확한 것은 Q0/Q1 REVIEW로 처리한다. 실제 수집과 ChatGPT 해석을 구분하고 둘 중 하나라도 핵심 미해결이면 최종 교본 완성 PASS를 선언하지 않는다.
6. 확보 후에는 핵심 조건·수치·행동·인과·예외를 원문 상태와 연결해 추출한다. 교본에서는 의미 있는 내용을 짧게 재서술하고 공통·중복·비관련 설명을 축약한다. 관련 근거 수집 자체를 줄이거나 긴 원문을 그대로 옮기는 방식은 금지한다.

**툴팁 본문 전수 + 위치·문맥 단서:** 모든 실제 관련 `?`/hover/정보 아이콘의 **본문을 확보**하고, 가능하면 `영웅 선택 > 단일/광역 > 섹션 > 표/행·옆 기술` 같은 표시 위치를 기록한다. 이후 ChatGPT가 의미를 분석하며 우선권 상승 조건과 최소 사용 가능 조건을 혼동하지 않는다(예: 신성한 힘 5에서 우선권 상승은 5 미만 사용 금지와 다름). 정확한 DOM/행 연결을 일괄 강제하지 않되 의미가 모호해 행동이 달라질 수 있으면 **그 팁만** 원본 관계를 조사한다. 원문 전체 복제·장문 번역 대신 판단에 필요한 의미를 보존한다.

**추가 누락 방어:** 처음 보이는 선택지 목록만 끝으로 보지 않는다. 상위 선택 전환 뒤 새로 표시되는 섹션·동적으로 표시되는 하위 탭·중첩 접이식·툴팁·오프너 대체안·조건 목록의 계층·시각 타임라인을 재탐색한다. 같은 문구의 반복은 진짜 공통 규칙인지 상태 귀속을 확인한 뒤만 중복 제거한다. 원문에 제공되지 않는 모든 게임 내 특성 조합의 전수 탐색은 요구하지 않는다.

이 원칙은 **사용자 확정 필수 정책**이다. 별도 크롤러/새 엔진 구축 자체는 목표가 아니며, 기존 가능한 접근 방식으로 실제 확보가 되는지 검증하고 실패가 반복되어 제작에 실질 영향이 있을 때만 도구 개선을 검토한다. [범용 사례집 §19–20](QUALITY_GENERALIZATION_CASEBOOK.md).

## 5. 저작권·근거 표현

- 외부 공략의 **전체 표·문단·대량 번역문을 복제하지 말고**, 기술적 조건을 검토한 뒤 독자적인 한국어 설명으로 표현한다.

- 공식 spell ID, 버프 이름, 주문 아이콘은 실제 데이터와 맞지 않으면 `미확인`으로 유지.
- 출처에서 게임플레이 판단 근거가 모호하면 다른 모델의 추론만으로 사실을 확정하지 않는다.
- 공개 GitHub에는 제목/URL/확인일/패치/해시 같은 **메타데이터만** 저장한다. 사용자가 제공한 개인 원문은 개인 실행 환경에서만 분석한다.
