# QUALITY GENERALIZATION CASEBOOK — 과거 교본으로 범용 품질 기준 검증

> 기준: 2026-11-11 KST · Chat-first ROTATION TEXTBOOK · 개인 HTML 원문 비공개
>
> 이 문서는 교본 본문/게임 데이터 정본이 아니라 **제작법과 품질 평가법을 반증 가능한 사례로 검사하는 정본**이다. 우선순위는 내용 판단의 정확성 > 이해/실전 사용성 > 원본 보존/기능 QA > 도구 확장. 독립 AI 자동화 제품 개발 지시가 아니다. **확정 정책과 잠정 관찰의 구분은 [QUALITY_FIRST_POLICY](QUALITY_FIRST_POLICY.md)를 따른다.**

## 0. 최상위 원칙

- 생존·비전·V11 교본은 **실험 자료**다. 목표는 특정 전문화의 완성이 아니라 **다른 전문화에서 재사용 가능한 제작·검증 지식**이다.
- 검증은 오류 탐지(민감도)와 **정상 사례의 오탐 회피(특이도)**를 함께 본다. 패턴 검사 실패 = 게임플레이 오류라는 등식은 성립하지 않는다.
- 구조/스크립트 PASS, 출처 URL 매핑, 규칙 의미 검증, 사용자 이해/승인, 실전 성능은 **서로 다른 증거**다. 서로를 대체하지 않는다.
- 과거 버전/패치의 기술 수치·우선순위는 **역사적 테스트 사례**일 뿐 현재 패치의 게임 규칙으로 자동 재사용하지 않는다.
- 이 문서의 관측은 **후향적 비교**다. V11을 이미 보고 원칙을 설계했으므로 진정한 블라인드 홀드아웃 검증이 아니다. 향후 새로운 전문화에서 별도 확인이 필요하다.

## 5. 다음 전문화에 적용할 경량 결정 사례 계약

별도의 범용 AI 실행 엔진/고정 JSON 생성기 구축을 요구하지 않는다. ChatGPT가 일시적인 분석 메모로 다음을 남기면 충분하다.

- **범위**: 패치·영웅 특성·선택 특성·대상 수·세트·전투 구간.
- **현재 상태**: 충전·중첩·버프/디버프·자원·쿨다운·거리·대상 이동 등 실제 관련 변수만.
- **선행 판단**: 더 높은 우선 규칙이 적용되는지, 오프너의 직전 행동이 상태를 어떻게 바꿨는지.
- **독립 기대 행동**: 실제 공략/공식 변경 자료에서 확인한 행동. 불명확하면 `REVIEW`, 추측해서 PASS 금지.
- **교본 행동**: 실제 사용자가 빠른 참고/우선순위/오프너에서 선택하게 될 행동.
- **결과**: `MATCH` / `MISMATCH` / `INDETERMINATE` / `NOT_APPLICABLE`. 구조 점수와 별도로 기록.
- **학습**: 특정 전문화 사실인지, 범용 실패 메커니즘인지, UI 문제인지 구별하고 일반화에 따른 오탐 사례도 연결.

**핵심 방어:** 교본을 읽어 만든 기대 답으로 다시 교본을 채점하지 않는다. 오프너·지속 딜 전환은 직전 행동의 상태 변화까지 포함한다.

## 6. 품질 기여를 승인하기 위한 두 방향의 시험

새 규칙/도구를 추가할 때 적어도 아래 두 방향을 함께 검사한다.

1. **양성 대조(오류 탐지):** N01~N06 중 어떤 실패를 이전 방식보다 정확히 발견하는가? 단순한 검토 알림과 사실상 틀린 행동의 확정 판정을 구분한다.
2. **음성 대조(오탐 방어):** P01~P05 같은 정상·경계 사례를 불필요하게 수정하거나 탈락시키지 않는가?
3. **경계 시험:** 다른 특성 선택, 우선순위 선후, 새 패치, 불완전한 외부 근거일 때 `INDETERMINATE`로 머물 수 있는가?
4. **변경 기여:** 수정 전/후 같은 사례에서 개선이 확인되는가? 해결되지 않은 다른 조건과 기존 전문화가 퇴보하지 않는가?
5. **독립 검증:** 지식을 도출할 때 사용하지 않은 새로운 전문화에서 적용성을 평가한다. 이번 V11/생존/비전의 비교는 **후향적 적합성 검사**이지 완전한 독립 검증이 아니다.

**증거 부족이면:** `개선 제안` 또는 `개선 미확정`으로 유지한다. 원칙을 강제하거나 새 코드·교본 본문을 수정하지 않는다.

## 7. 현재 코드의 활용 범위

- `engine/v2/parity.py`, `import_v11.py`, `patch_v11.py`의 원본 보존·수정 경계는 유효한 **기능 안전 자산**. 콘텐츠 의미 검사로 오인하지 않는다.
- `engine/v2/fidelity.py`의 모든 구성요소 요구, `mechanics.py`의 최소 3개 흐름/1개 비교표, `rule_source_audit.py`의 정해진 세 출처 카탈로그는 **역사적 비전 파일럿에 한정된 계약**. 모든 전문화에 확장하기 전에 P01~P05의 오탐을 검증한다.
- `CONDITION_WORKLIST.md`의 부분 조건 후보 2개/177행은 전체 행동 지시를 의미하지 않는다는 **보수적 상태 구분**을 유지한다.
- 이 사례집은 독립 AI API, 웹앱, 대량 수집, 자동 커밋·게시의 필요성을 입증하지 않는다.

## 8. 다음 검증 우선순위

1. G02/G05를 우선 사례집 기반 평가에 적용해 **정상 V11 오탐 방어**를 확립.
2. G01/G03/G04를 새로운 전문화 제작 전 단계에 적용. 실제 규칙 출처·행동 비교를 남기되, 임계값 시험 개수는 고정하지 않는다.

**범용 절차 수정:** HTML 원본 숨김 요소 → DOM 선택 경로/팁 귀속 → 스크립트/JSON 데이터 → 정상 네트워크 응답 → 최소 UI 조작(최후 수단) 순서로 조사. 선택/호버가 실제로 일어났는지가 아니라 **실제 각 상태의 전문화·특성/전투/물약/오프너/팁 본문을 모두 회수하고 올바른 행에 연결했는지**로 확보 완료를 판단. 기존 로컬 사용자 브라우저 설치를 기본 계획으로 둔 §24의 제안보다 이 순서를 우선한다. 최초 원문 시점 충돌(2026-07-26/12.0.7 vs 2026-10-13/12.1.5)을 무시하지 않고 자료 접근별 버전을 확인한다. **현재 고양 V3의 전수 확보 완료를 의미하지 않음.**

## 34. 사용자 교정 — 전체 원문 수집 후 의미 분석, `?`의 위치는 단서 (2026-11-12)

**과도한 기존 요구 수정:** 앞선 사례에서는 모든 관련 `?` 본문 확보뿐 아니라 실제 DOM ID/특정 순위 행 귀속을 전수 입증해야 수집 완료라고 해석했다. 그러나 사용자가 요구하는 것은 UI 복제가 아니라 **원문의 모든 판단 정보를 얻은 뒤 ChatGPT가 상관관계를 해석하는 교본 제작**이다. 이름/행 연결을 전수 입증하기 위한 무리한 개발은 실제 내용 확보를 지연시킬 수 있다.

**유지할 안전 장치:** 다른 패치(예: 2026-07-26/12.0.7과 2026-10-13/12.1.5)를 혼합하지 않음; 물약별 상호 배타적인 오프너를 합치지 않음; `tooltip2` 등 복수 팁 본문을 빠뜨리지 않음; 이미 확보한 정확한 위치 관계는 활용하되 모든 행의 기계적 증명을 강제하지 않음. 앞선 §20–§33은 실패 기록으로 보존하고 **본 절이 최신 작업 규칙**이다. 최신 고양의 모든 팁 원문 확보나 V3.7 승인 완료를 뜻하지 않는다.
