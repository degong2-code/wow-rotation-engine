## 4. V46~V62의 재사용할 성과·반례(역사, 최신 제품 아님)

- **UI 승인:** V29 비전의 정보 밀도, V46 냉기 **기술명 주정보 + 조건 괄호/작은 글씨/옅은 색** 채택. 괄호를 뺀 V47은 **비채택**. 깔끔한 `순위/행동/조건` 표, 정확한 이유·예외, 아이콘·툴팁, 첫 화면에서 실행 가능함이 목표.
- **왼쪽 메뉴:** 직업·영문명은 **완전히 같은 행**; 노치 포인터 삼각형 형태 축소, 짧은 구분선, 행 높이/정렬·접고 펼침. 새 전문화에도 좁은 너비에서 한 행에 가깝게 유지.
- **표 가독성:** 열 침범만 없으면 되는 게 아니라 적정한 **실측 열 너비 배분**·반응형 줄바꿈·좁은 화면 세로 배치를 확인한다(V53~V55). 두 열 중 라벨이 본문보다 비대하게 넓어지지 않도록 한다.
- **정확한 기술·상태 표현:** 사용자 화면에서 내부 키·단독 영문 약어·`∧` 등을 노출하지 않고, 확인된 한국어 기술명/아이콘/툴팁을 관련 위치마다 묶는다. 조건은 **실제 행동을 바꾸는 것만**. '사용 가능할 때', '상위 조건이 없고', 기술 자체가 전제하는 '발동 중' 등은 반복하지 않는다. OR/AND 관계·시간·중첩·대상 수·부정 조건은 정확히 보존. 기본 `→`는 **지속 딜 우선순위**, 오프너 `→`는 **실제 시전 예시 순서**(GCD와 자동 동치 아님).
- **원문이 먼저:** HTML/표 템플릿 선제 제작, 출처 혼합, 선택 조건 평탄화, 숨김 `?`·접힘·오프너 순서 누락을 금지. 기존 정상 HTTP/WHML 경로(일반 웹 텍스트보다 상세)를 먼저 재사용. DNS 실패는 HTTP 403과 다름.
- **고양 V62:** 물약 3종×영웅 2×전투 2=**실제 시작 행동 차이 12가지** 복원. 여러 선택의 `전격의 불길`이 웹 텍스트에 연이어 나타나도 실제 3회 연속 시전이 아니다. 물약별 **차이만 접이식 표**로 표시, 12개 완전한 GCD 시퀀스는 미검증. [증거](ENHANCEMENT_OPENER_SOURCE_PATHS_20261113.md).

## 7. 새 채팅 첫 응답의 엄격한 범위

**첫 메시지는 읽기 전용 독립 복원만 한다.** GitHub HEAD/PR/base/CI를 새로 조회, 최신 CURRENT_STATE와 이 스냅샷을 대조, 개인 Library의 **V63 HTML 실제 바이트·SHA·12개 전문화**를 확인, V11 기준 원본 접근 여부 분리, 원문·게임·독해·Q4의 검증/REVIEW, 다음 작업을 1~3개만 보고한다. **HTML/코드/문서 수정, 커밋/PR 변경, Actions 수동 실행, 대량 원문 수집, 신규 전문화 집필, 공개 배포 금지.** 이미 충분한 Q4를 인계만을 위해 재실행하지 않는다. 보고 후 사용자의 **`진행`** 지시를 기다린다.

**프로젝트 설정 안내:** GitHub의 정책·인계 문서는 ChatGPT 프로젝트 지침을 자동으로 수정하지 않는다. Project settings에는 [CHAT_FIRST_PROJECT_INSTRUCTIONS](CHAT_FIRST_PROJECT_INSTRUCTIONS.md)의 최소 부팅 지침(프로젝트 정의·필수 문서 경로·인계 원칙)을 사용자가 직접 등록해야 새 일반 채팅에도 일관되게 적용된다.

**변하지 않는 최종 질문:** (1) 실제 게임 상태에서 독자가 정확한 다음 기술을 선택할 수 있는가? (2) 다른 전문화에서도 같은 품질의 한국어 단일 HTML을 반복 제작할 수 있는가?
