# 실제 WHML의 선택 조건 범위와 본문 행 귀속 — 2026-11-12

## 문제와 해결

과거 생존/비전 교본에서 템플릿을 먼저 만들면서 **원문 조건·예외·적용 범위가 누락**됐다. `display-options` 자체를 딜사이클 조건으로 등치하거나, 한 행 안의 일부만 표시하는 조건을 **전체 행의 조건**으로 합치는 것도 같은 종류의 오류다.

`engine/source_scoped_evidence.py`는 `source_editorial_packet.packet_from_html()`가 생성한 **비공개 전체 WHML 원문**을 입력으로 다음 사실만 추출한다.

- `[li]`/`[tr]` 등 원문 행 후보의 정확한 위치와 **원문 조각** (비공개)
- 열리고 닫히는 컨테이너의 `display-options` 조건이 행 전체에 적용되는지, 해당 행 자체 조건인지
- **행 안의 일부**에만 적용되는 하위 `display-options`가 있어 하나의 행동으로 병합하면 안 되는지
- 상위 `[tab]`·직전 제목의 위치, 행 안 `?` 참조 이름, 본문이 **툴팁 정의 안에 있는 설명**인지 여부
- `rt-step`, `rt-step-group`처럼 **독립적인 사용자 정의 요소의 조건 마커**. 닫힘 태그가 확인되지 않는데도 부모 컨테이너로 가정하지 않음
- 알 수 없는 닫힘·잘못 짝지어진 태그 등의 구조 경고 및 위치를 **문장 없이 태그 이름과 오프셋만** 보고

이 단계는 **원문 화면 표시 조건(visibility)을 구성하는 근거 색인**일 뿐, 선택 특성·자원 중첩·기술의 실제 gameplay 사용 조건은 아니다. 사용 기술·순위·이유·예외·임계값을 추측해서 넣지 않는다.

## 실제 Wowhead 3개 전문화 검증

| 2026-11-12 수집 원문 | 원문 행 후보 | 원문 조건 총수 | 범위형 조건 | 독립 조건 마커 | 미귀속 | 구조 경고 |
|---|---:|---:|---:|---:|---:|---|
| 고양 주술사 | 164 | **82** | 62 | 20 (rt-step 10/rt-step-group 10) | **0** | 닫힘 구조 불일치 1건 |
| 생존 사냥꾼 | 121 | **61** | 61 | 0 | **0** | 없음 |
| 비전 마법사 | 72 | **5** | 5 | 0 | **0** | 닫힘 구조 불일치 1건 |

**계수 검증:** 원문에서 찾은 `display-options` 개수 = `짝이 확인된 범위형 조건 + 독립 마커 + 미귀속`이 되는지 실제 HTTP로 받은 세 원문에서 전수 대조했다. 모두 일치하며 미귀속은 0. 행 후보에는 설명·표의 일반 목록도 포함되므로 우선순위 행 수를 뜻하지 않는다.

**남은 불확실성:** 고양과 비전의 닫힘 태그 1건씩은 실제 WHML 비표준 구조/기존 사이트 표기/분석기 한계 중 무엇인지 아직 판정하지 않았다. 해당 범위를 잘못 연결해 행동으로 합치지 않고 검토 대상으로 유지한다. 고양의 **혼합 표시 조건 행 1개**는 부분 조건을 별도로 판단해야 한다. 0개 미귀속이 모든 UI/게임 로직 완전성을 보장하지 않는다.

## 내부 실행과 프라이버시

`source_acquisition_pipeline`의 비공개 출력 파일:

- `editorial-evidence-private.json`: 원시 WHML 전체, 정의된 tooltip 본문 및 참조, 선택·조건의 원문 위치
- `scoped-evidence-private.json`: 원문 조각·행의 적용 범위·조건 마커 위치·미해석 구조 (원문 포함)
- `scoped-audit.json`: 원문 없이 개수·구조 경고·미귀속 조건 수만
- `pipeline-audit.json`: 전체 출처 취득·구조 비교·검토 필요 여부

**이름이 있는 실제 Wowhead HTML, 개인 V11/V3.11 HTML, 원문 패킷을 PUBLIC GitHub/Actions Artifact에 게시하지 않는다.** CI에는 조건 개수·태그 이름·오프셋·메타데이터만 출력한다. 원문은 임시 private directory 안에서 처리 후 폐기한다.

## 다음 콘텐츠 QA 방법

1. 실제 텍스트에 따라 `상태 → 수치/발동/선택 조건 → 다음 행동 → 이유 → 예외`를 ChatGPT가 원문과 해당 `?` 본문에 연결해 작성한다.
2. `rt-step`/물약 조건 등 독립 UI 표시 요소를 보았다는 사실만으로 **무조건 게임플레이 분기**라고 정하지 않는다. 정확한 시전 행동 변화가 확인되면 분기, 아니면 예시/공통 슬롯으로 정리한다.
3. 조건을 요약 장·오프너·우선순위·심화로 나눠 표현할 때 **같은 근거의 누락·상충**을 다시 검토한다.
4. 반례는 **실제 선택이 갈리는 경계·스택·영웅/특성 ON/OFF·쿨다운**에 비례하여 고른다. 수를 맞추기 위해 가짜 상태나 규칙을 만들지 않는다.
5. Q0/Q1 콘텐츠 검증 뒤에만 V11 수준 이상의 단일 HTML에 합치며 기존 7개 전문화와 UI 회귀 테스트(Q4)를 별도 검증한다.
