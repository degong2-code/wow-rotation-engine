# QUALITY FIRST — 단일 Wowhead 출처 전이 예비시험: 고양 주술사

> 2026-11-11 KST · **연구/실험 기록, 운영 정책 아님** · 교본/HTML 미생성 · 독립 실전 성능 검증 아님.
>
> 목적: 생존/비전에서 도출한 G01(규칙 우선), G02(콘텐츠 역할), G03(검증 상태 분리), G04(교차 표현 일관성), G05(표현의 유연성)가 **새 전문화의 Wowhead 단일 공략**을 처리할 때 무엇을 찾고 무엇을 보류하는지 확인한다. 특정 전문화의 회전을 완성하는 것이 목표가 아니다.

## 1. 시험 조건·사전 판정 기준

- 시험 전문화: **Enhancement Shaman / 고양 주술사**. 기존 V11 정본 7개, 생존·비전 파일럿에 없는 새 전문화.
- **기준 출처 1개:** [Wowhead Enhancement Shaman Rotation Guide](https://www.wowhead.com/guide/classes/shaman/enhancement/rotation-cooldowns-pve-dps), 편집자 **wordup**, 페이지 표기 패치 **12.1.5**, 수정 **2026-10-13**. 동일 페이지의 검색 결과 표현·본문 텍스트를 비교했고, 별도 사이트 공략은 이 시험에 **사용하지 않음**.
- 시험 대상: 영웅 특성 **Stormbringer / Totemic** × **단일 / 광역**, 오프너 및 자원 소비·발동 예외 중 관찰 가능한 사례. 특성 빌드·시즌 세트의 개별 게임 내 최종 적합성 검증은 **범위 밖**.
- 정해둔 판정: `EXPLICIT`(기준 페이지 해당 목록·설명에 조건 직접 연결), `CONTEXT_NEEDED`(페이지는 설명하지만 특정 행/선택 상태 귀속 불명), `INDETERMINATE`(추출 방식 차이로 선택 결과 불명), `NOT_TESTED`(게임 내·독자 검증 미수행).
- **성공 조건:** 자료 한 곳으로 확인 가능한 부분과 불가능한 부분을 실제로 분리하고, 무근거 조건·로테이션 합성을 피한다. 분류가 가능하다는 결과만으로 **고품질 완성 교본 제작의 재현성 PASS**라고 선언하지 않는다.

## 2. 실제 확인된 추출 단위

- 페이지의 지속 딜 목록은 **4개 우선순위 그룹**으로 분리 가능: Stormbringer 단일 **9행**, Totemic 단일 **12행**, Stormbringer 광역 **10행**, Totemic 광역 **12행**; 총 **43개 표면 행**. 각 행의 조건과 팁이 완전히 복구됐다는 의미는 아니다.
- 오프너는 **4개 시퀀스**로 구분 가능: 각 영웅 특성 × 단일/광역. 전투 시작 전 선택과 GCD 외 사용은 맥락에 따라 별도로 읽어야 함.
- 영웅 특성별 주요 축이 달라짐: Stormbringer는 Maelstrom/Tempest, Stormstrike/Ascendance; Totemic은 Surging Totem, Hot Hand/Lava Lash, Doom Winds. **이것은 해당 출처에 대한 편집 구조 관측**이며 다른 패치의 규칙 정본이 아님.

## 3. 검증 사례 매트릭스

| ID | 입력 맥락 / 대조 목표 | 근거 위치(같은 Wowhead 페이지) | 판정 | 범용 학습 |
|---|---|---|---|---|
| E01 | 영웅 2 × 대상 범위 2의 우선순위를 4개 그룹으로 분리 | Single Target / AoE → 각 Priority | **EXPLICIT** | 메뉴·DOM 역할에 상관없이 **기준 상태 축**을 먼저 식별 |
| E02 | Stormbringer 단일: 10 Maelstrom에서 Tempest/Lightning Bolt 규칙, 낮은 우선권의 5+ Lightning Bolt 예외 행과 구분 | Single Target → Stormbringer Priority | **EXPLICIT(행 수준)** | 같은 기술의 여러 임계값은 **우선순위/발동 상태**를 구분. 해당 전투 상태의 정답은 다른 상위 행도 확인해야 함 |

| E04 | Totemic 단일: Hot Hand/Whirling Fire 중 Lava Lash 우선, 광역에서는 Sundering이 그 행 앞에 위치 | Single Target / AoE → Totemic Priority | **EXPLICIT(행 순서)** | 영웅·대상 조건뿐 아니라 **상위 행동 순서** 보존 |
| E05 | Totemic의 5+ Maelstrom 소비 예외: Elemental Tempo 초기화 또는 Hot Hand 연장 여부 | Totemic Priority 앞의 조건 설명, Totemic Notes | **CONTEXT_NEEDED** | 추출된 팁·설명과 우선순위 행의 **정확한 연결** 없이 기본 5+ 규칙을 확정하지 않음 |
| E06 | Ascendance/Thorim's Invocation 중 수동 소비보다 자동 소비를 우선하는 규칙 | 단일/광역 팁, Stormbringer Ascendance / Thorim 설명 | **EXPLICIT(설명 수준)** | 설명과 우선순위가 **동일 시전 상태**에 적용되는지 추적; 모든 상황의 행동 정답을 단정하지 않음 |
| E07 | Totemic ST opener: Sundering→Lava Lash→Doom Winds + Primordial Storm; AoE opener: Sundering→Doom Winds + Crash Lightning→Lava Lash→Primordial Storm | Opener → Totemic ST / AoE | **EXPLICIT(시퀀스 차이)** | 오프너는 단일 고정 콤보가 아니라 **빌드·대상별 상태 전이** |
| E08 | Totemic 오프너의 Voltaic Blaze 단계 수: 검색 추출문에서 반복 구간이 나타나지만 본문 추출문과 일치하지 않음 | 같은 URL의 검색 결과 vs 오픈 본문 추출 | **INDETERMINATE** | **추출 결과의 불일치**는 즉시 공략 오류로 단정하지 않음. 동적 선택 상태를 직접 확인하기 전 숫자/단계 자동 생성 금지 |
| E09 | 페이지 하단 오래된 댓글과 편집자 본문을 구분 | Comments 섹션 vs Rotation 본문 | **EXPLICIT(문맥 역할)** | 같은 URL의 역사적 사용자 댓글을 현재 패치의 공략 규칙·독립 승인 근거로 혼동하지 않음 |

**해석 제한:** EXPLICIT은 **해당 원문에 명시돼 있음**을 의미하며 실제 게임의 최적 회전, 패치 내용의 독립 검증, 사용자의 다음 GCD 전체 상황을 통과했다는 뜻이 아니다. 팁과 표의 귀속이 모호한 항목(E05/E08)은 사실을 추정해 수선하지 않고 보류했다.

## 4. 품질 기여 검토 — 전후·오탐 관점

| 과거 취약 접근 | 이 시험에서 적용한 대안 | 검증된 범위 | 과장 금지 |
|---|---|---|---|
| 단일 요약 화살표로 양쪽 영웅/단일·광역을 합침 | 4개 그룹 + 4개 오프너로 범위 분리 | **분기 혼합 위험 예방 방식 확인** | 실제 교본 시연/사용자 판단 개선은 미실증 |
| 검색 결과에 보이는 순서를 그대로 오프너로 확정 | 검색/열람 결과가 다른 단계는 E08 INDETERMINATE | **원문 추출 불확실성을 포착** | 실제 브라우저 토글 원인·정답은 미확인 |
| 축약된 5+ 스택 규칙을 공통 행동으로 적용 | 관련 조건/상위 우선순위 연결 전 E05 보류 | **근거가 부족한 일반화를 차단** | 정확한 완전 조건을 최종 복원한 것은 아님 |
| 규칙마다 2~3개 사이트가 있어야 통과 | 기준 공략 단독으로 E01~E07 일부 확인 | **복수 사이트 필수 규정 불필요함을 사례로 지지** | 모든 로테이션 조건에 단일 출처가 충분하다는 결론 아님 |
| 페이지의 모든 텍스트를 동일 권위의 원문으로 인식 | Comments와 편집자 본문 분리 | **역사적 댓글의 최신 공략 오인 예방** | 개별 댓글의 진위를 판단한 것은 아님 |

**남는 위험:** HTML의 `note`·조건·선택 상태와 실제 표시 행의 귀속을 텍스트 추출만으로 확정하지 못하는 경우가 있다. 해결을 위해 **다른 공략 사이트를 무조건 늘리는 것은 부적절**하다. 먼저 원래 기준 Wowhead 페이지의 **선택 상태를 유지한 구조적 접근**이 가능한지 확인하는 것이 더 직접적이다. 해당 접근 자체의 시간·복잡성이 실질 품질에 기여하지 않으면 일부 규칙은 검토 대기로 남기는 것이 낫다.

## 6. 후속 검증 권고(과잉 개발 방지)

1. **선택/툴팁 구조의 원문 충실도**를 확인할 수 있을 때만, E05·E08의 미확정 연결을 재시험한다. 우선 또 다른 공략 사이트 수를 늘리거나 전용 크롤러를 제작하지 않는다.
2. 새 전문화에서 **증거 단위→독자 판단 단위**를 소수의 대표 사례로 실제 집필하여, 기존 일반론보다 정확한 조건을 보존하는지 비교한다. 이때도 **완성 교본을 만들 필요는 없음**.
3. 긍정 사례는 `EXPLICIT`, 부정·미확인 사례는 `CONTEXT_NEEDED/INDETERMINATE`로 구별해 사례집에 축적. 같은 오류가 다른 전문화에서 재발하지 않는다는 증거가 확보돼야 제작 표준의 효과를 입증할 수 있다.
4. 본 연구로 Q0~Q4 평가법이 **독자 품질의 정확한 대리변수임이 증명된 것은 아님**. 사용자 평가가 가능한 실제 CREATE/UPDATE 단계에서 별도로 확인한다.
