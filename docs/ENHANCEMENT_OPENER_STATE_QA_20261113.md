초기 폭풍의 일격이 보장하는 자원 생성의 **정확한 중첩 수**, 모든 공격의 GCD 길이, 실제 재사용 대기시간의 진행, 실전 DPS 최적화는 프로그램이 추정하지 않는다. 기계 판정의 기대값은 출처의 오프너·우선순위·Notes에서 작성한 것이며 그 자체가 독립 게임플레이 실증은 아니다.

### 정확하게 막은 실패 반례 6개

1. 폭풍인도자 광역 Liquid Luster의 **전투 시작 낙뢰를 선시전**으로 잘못 옮긴 경우 → mismatch.
2. 폭풍인도자 단일에서 **선택한 초기 폭풍의 일격을 무단 생략**한 경우 → mismatch.
3. 승천 중 낙뢰 준비 상태를 제공하지 않고 임의로 바람의 일격으로 넘기는 경우 → underdetermined.

6. 토템술사 광역에서 **낙뢰보다 먼저 사용할 파멸의 바람의 GCD 내 선후관계가 뒤집힌** 경우 → mismatch.

## 3. 발생 원인을 일반화한 설계 수정

기존의 “같은 beat에 한 GCD 기술 + 여러 off-GCD 기술 허용”만으로는 실제 행동의 조건을 검증할 수 없다. 가령 파멸의 바람은 **태고의 폭풍/낙뢰 전에** 사용해야 효과가 이어지는데, 단지 같은 beat의 이벤트를 무순서로 모으면 역순을 정상 처리한다.

수정된 공통 규칙:
- 원문이 선후관계를 요구할 때만 event.within_beat_order를 사용한다. 0인 비GCD 활성화가 동일 beat의 1인 GCD 공격보다 **앞선다**.
- 명시 순서가 있는 경우 **앞선 기술의 set_state를 즉시 반영**한 뒤 뒤따르는 기술의 when을 판단한다. 따라서 강화 상태가 없는 채로 강화된 행동을 수행하는 잘못을 방지한다.
- 순서를 명시하지 않은 일반적인 동시 이벤트는 **기존처럼 같은 시작 상태**로 판단하여, 상충 상태 변경은 모호함으로 분류한다.
- 순서의 일부만 선언하거나 동일 실행 순서를 충돌하게 기록하면 underdetermined/ambiguous. GCD 시간 길이와 실제 시전시간은 자동 계산하지 않는다.
- 다른 전문화/다른 능력 이름으로 만든 테스트를 포함한 **합성 정상·오류 대조**로 엔진의 적용 범위를 분리 검증했다. 정답을 정하지 않은 상태에서 선후관계를 임의로 만드는 규정은 아니다.

범용화 대상은 **선후관계가 실제 다음 행동을 변경하는 경우를 표현/검증하는 방법**이며, 고양의 파멸의 바람이나 물약 수는 범용 제약이 아니다.

## 4. 남은 Q0/Q1 본질적 문제

- 오프너 모든 단계의 세부 동시 행동/스킬 선택/상황별 이동과 실제 GCD 소모를 다 모델링하지 못했다.
- **물약 자체의 사용 시점·효과·후속 상태를 전부 모델링하지 않았다.** 지금의 12개 문맥은 물약이 **낙뢰 선시전과 진입 단계**를 바꾸는 점을 포함하지만, 물약 효과 자체의 수치/버프를 추측하지 않는다.
- 선택적인 초기 폭풍의 일격의 실제 자원 중첩, 발동 효과, 전투 중 재사용 대기시간/파멸의 바람 지속시간, 승천 내부의 낙뢰 갱신 등을 독립 게임 로그로 증명하지 않았다.
- 원문의 tooltip-to-step 맥락은 필요한 위치에서만 추가 검토한다. 원문 확보 사실을 텍스트 의미의 독립 증명으로 과장하지 않는다.
- 개인 V3.11의 일부 27개 집중 규칙 대조는 [앞선 기록](ENHANCEMENT_OPENER_SOURCE_PATHS_20261113.md)에 별도 보존. 이번 실제 전이 검사는 해당 개인 HTML의 최종 검증 또는 정본 승격을 수행하지 않았다.
- 다른 전문화 **실제 원문**에 똑같은 분석 방법을 적용해 정상 사례의 오탐 여부를 재검증해야 최상위 일반 정책으로 승격할 수 있다.

## 5. 다음 적용 순서

1. 이번 부분 모델이 **생략한 물약 액션의 실제 독립 원문 위치와 사용 시점**을 확인하고, 근거가 있는 타임라인 구성요소만 추가한다.
2. 선택적 초기 폭풍의 일격 ON/OFF 이후 자원/발동의 실제 수치와 우선순위 접속을 Q0/Q1 검토한다. 의미를 확정할 수 없으면 REVIEW.
3. 토템술사 ST/AoE의 파멸의 바람→타격→후속 강화 행동을 원문 각 영웅/전투 상태에서 비교한다.
4. 생존/비전 또는 정상 V11 사례에서 선후관계가 불필요한 경우까지 강제되는 **오탐이 없는지** 검증한다.
5. 최종적으로 개인 V3.11과 HTML 기능/원형 보존 Q4를 별도 확인하되 사용자가 승인하기 전까지 검토본 상태를 유지한다.
