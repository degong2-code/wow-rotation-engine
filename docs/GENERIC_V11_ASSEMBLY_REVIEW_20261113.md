# V11 단일 HTML 공통 조립 — 3개 실제 전문화 교차 검증 (2026-11-13)

## 해결한 제품 문제

기존 `engine/v2/create_guide.py`의 실제 HTML CREATE는 `arcane` 및 성난태양·주문술사 2영웅·4개 표·비전 전용 메뉴/스크립트에 종속되어 있었다. 다른 전문화의 **집필본을 그대로 완성된 단일 HTML에 넣는 최소 공통층**부터 분리하여, 이미 검토한 내용의 기술명·조건·설명·서식이 재조립 과정에서 달라지지 않도록 한다. **집필/콘텐츠 의미를 엔진이 임의 생성하거나 교정하지 않는다.**

모두 **같은** `engine/v2/generic_v11_assembly.py`의 `repackage()` 호출과 동일한 원본 V11 입력으로 재조립. 신규 전문화 ID·영웅 이름·영웅 수·표 행 개수를 출력 코드에 기입하지 않는다. `data-canonical-id` 및 비공개 원문 검토 메타데이터는 입력에서 **그대로 보존**하며, 규칙을 새로 만들어내지는 않는다.

Chromium으로 직접 연 1365×880 / 390×844 **3전문화×2화면**에서 신규/기존 7개 전문화 탐색, 영웅 특성 2개 전환, 기존 냉기 마법사·암살 도적 영웅 변경, 신규 화면 영웅 버튼, 툴팁·ESC 닫기, 모바일 가로 넘침과 JS 오류 없음 확인. 파일을 로컬 파일 URL로 직접 여는 방식이 아니라 `page.set_content()` 방식의 검사이므로 다른 환경의 파일 열람을 보증하지 않는다. 스크린샷·이미지 미리보기는 생성하지 않음.

## 범용 조립 계약

1. 원본 7개 V11 입력 SHA 고정; 후보 집필본은 V11 원본 7개 `manual-view` 바이트가 동일하고 **신규 전문화 1개만** 포함해야 함. 독립 집필본은 사용자가 리뷰할 실제 HTML이므로 기존 잘못된 버전을 자동으로 좋은 정본으로 간주하면 안 됨.
2. 새 전문화의 `manual-view`, 사이드바, 목차, 추가 스타일/확장 스크립트를 분리해 기존 원본 V11 구조로 재조립한다. **기존 전문화 내부의 HTML은 절대 재직렬화하지 않는다.**
3. 7개 원본 JS의 전문화별 하드코딩 메뉴 등록부를 **DOM에서 전문화를 읽는 공통 네비게이션**으로 교체한다. 기존 `fire/frost/dk/hunter/bm/rogue/assassination`과 다른 전문화 이름에 종속되지 않는다. 실제 원본 가이드 7개와 신규 가이드의 영웅/목차/툴팁 기능을 회귀 검증한다.
4. 중복 DOM ID, 수정된 원본 7개, 원본 CSS 변경, 잘못된 기준 SHA, 신규 가이드 0/2개 등은 실패로 중단. 원문·정규화 우선순위의 **내용 정확성 승인은 하지 않는다.**


## 한계 / 다음 제품 과제

이 조립기는 **이미 독립 집필된 V11+ HTML**을 입력받아 전문화 중립적으로 재조립하는 기능이다. **원문 하나에서 자동으로 게임 논리를 집필하거나, 완성되지 않은 전문화의 장·표·오프너를 만드는 범용 작성기는 아니다.** 고정된 기존 뷰 7개를 보존하는 V11 기반 경로이며, 기존 8개 이상 교본의 선택적 UPDATE에도 일반화되었다고 주장하지 않는다.

**실제 다음 우선과제:** 최신 원문 WHML 및 선택형 조건을 ChatGPT가 한 번만 정확하게 상태→행동→이유·오프너 구조로 만들고, 그 **독립 집필된 새로운 전문화**를 이 공통 조립층에 투입한다. 별도의 자동 문장 생성기/미시 검사기를 추가할 필요는 없다. 생존(원문 선택 미해결)·비전·고양의 게임 Q0/Q1은 여전히 REVIEW. 별도 사용자 Q3 최종 승인은 아님.
