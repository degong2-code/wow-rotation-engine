# ADR-003 — ChatGPT 중심 교본 제작으로 전환 (Chat-first Editorial Workflow)

- **결정일:** 2026-11-11 (KST)
- **상태:** 사용자의 신규 제품 방향 반영 / 실제 전문화 단일 입력 종단 간 시범은 별도 검증 필요
- **기준 저장소:** `degong2-code/wow-rotation-engine`, Draft PR #14~#19 기존 성과 **보존**
- **이번 결정:** 자체 AI 구독 연결·OAuth·Codespaces·상시 웹앱을 최종 사용자의 필수 작업에서 **제외**한다.
- **목표:** ChatGPT 프로젝트 채팅에 **전문화 이름 한 번 입력 → 현재 공략 탐색·분석 → 기존 V11 수준 교본 CREATE 또는 UPDATE → 검증된 단일 HTML 제공**. 단, 사용자의 입력만으로 시작하는 **요청 기반** 흐름이며 백그라운드 무인 실행을 의미하지 않는다.

## 1. 변경 사유 및 사용자 평가

1. 사용자 직접 AI 편집으로 만든 **기존 7개 전문화 V11 교본**은 비전 신규 자동 생성 초안보다 깊이·설명·사용성에서 더 우수하다. 우선 순위는 공통 엔진 코드가 아니라 **이미 입증된 결과물 품질**.
2. 자체 AI 앱은 로그인·인증·토큰·모델 라우팅·Codespaces/Actions·검토 화면 등을 이동해야 하며, 사용자 행동과 유지보수 부담이 증가한다.
3. 사용자는 ChatGPT Plus를 유지한다. **현재 채팅 자체에서 분석하고 집필**하면 별도 구독 연동이나 개인 API 키를 필수로 만들 이유가 없다. 일반 채팅의 이용량은 해당 ChatGPT 채팅 정책에 따르며 Work/Codex 연동량과 항상 동일한 계량 단위라고 가정하지 않는다.
4. GitHub는 **운영 지식, 프롬프트, 출처 경로, JSON/메타데이터, HTML 무결성 검증 도구, 개발 기록**을 보관한다. ChatGPT는 자료 탐색·조건 이해·설명 집필·필요한 HTML 수정 및 테스트의 **실행 주체**가 된다.
5. 공개 GitHub에 사용자 비공개 원본 V11, 장문의 외부 공략 번역/원문, 결과 교본, API 키 등을 올리지 않는다.

## 2. 사용자의 실제 경험

기본 명령 예시:
- `비전 마법사` → 기준 V11 정본에 해당 전문화가 **없으면 CREATE**. 이전 비전 초안은 참고/검토 자료일 뿐 완성품으로 강제하지 않음.
- `화염 마법사` → 기준 V11 정본에 이미 있으면 **UPDATE** 후보 조사. 공략 의미의 변경이 없으면 불필요한 재작성을 하지 않음.
- `암살 도적 최신 패치로 업데이트` → 명시된 UPDATE.
- `사격 사냥꾼 설명만 더 자세히` → 게임플레이 조건 변경과 구별되는 설명 개선.

처리 순서:
1. 채팅에서 전문화 이름과 요청 의도를 파악. 이미 기준 V11에 존재하면 UPDATE, 없으면 CREATE를 기본값으로 삼는다. 명시된 CREATE/UPDATE 의도가 있으면 우선한다.
2. GitHub의 **이 ADR, CHAT_FIRST_PLAYBOOK, SOURCE_INDEX** 및 기존 V11 보존 도구를 읽는다. 실제로 접근할 수 없는 파일이나 도구를 읽었다고 주장하지 않는다.
3. 현재 ChatGPT 프로젝트/대화 파일 또는 접근 가능한 개인 Library에서 `wow_rotation_manual_engine_v2.html`을 찾아 SHA-256 **`5d70279c4dd073eccef1f3b13565a8f555cd81c9f0a5b7eda7e3485e410742be`** 검증. 새 기준 버전이 승인되어 정본으로 교체된 경우에는 정본 등록을 업데이트한다.
4. 사용자 지정 공략·링크가 있으면 우선하고, 없으면 GitHub의 소스 카탈로그 + 현재 시점의 합법적인 공식/전문화 공략 페이지를 조회. 버전·특성 빌드·날짜·원문에 있는 구체적 발동 조건을 대조한다.
5. 기존 7개 V11을 **설명 깊이 및 UI의 정본**으로 삼아, 신규 전문화에는 충분한 핵심 원리·단일/광역 우선순위·오프너·쿨다운·심화 응용·예외·기술 툴팁·비교표·질문/경고 마커를 집필한다. 길이만 늘리는 문장 반복, 근거 없는 조건 보완, 비전 파일럿의 축약 템플릿을 금지한다.
6. UPDATE는 기존 HTML의 관련 부분을 최소 수정. 변경되지 않은 전문화는 **바이트 단위 동일**. 신규 등록은 기존 7개 `manual-view` 바이트 동일. `create_guide.py`, `patch_v11.py`, `parity.py` 등은 필요할 때 **검증/보존용 부품**으로 활용하며 독립 자동화 웹앱 완성을 선결 조건으로 삼지 않는다.
7. 필요한 검증을 실행: SHA·DOM 파싱·대상 전문화 존재·기술/영웅 선택 UI·`?`/`!` 열림·JS 오류·데스크톱/모바일; **실제 게임플레이 의미 검증과 기능 검증을 각각 구분**.
8. 결과물을 채팅에서 **비공개 단일 HTML 다운로드 링크**와 변경 요약/검토 보류 사항으로 전달. 사용자가 원할 때만 별도의 공개 게시를 검토한다.

**전제 조건:** ChatGPT가 해당 대화에서 공개 웹 검색, GitHub 저장소, 원본 V11 파일에 실제 접근할 수 있어야 한다. 새로운 채팅·다른 클라이언트에서 자료 접근이나 세션이 누락되면 자동 복구 가능한 소스를 탐색하되, **접근하지 못한 파일을 복원한 척하지 않는다**. 프로젝트 파일/개인 Library에 V11을 보관하고, GitHub 접속을 활성화하는 1회 설정이 최선이다.

## 3. 역할 재정의

| 기능 | 담당 | 반드시 유지할 것 |
|---|---|---|
| 전문화 선택·제작/갱신 요청 | 사용자 채팅 | 한 문구로 시작 |
| 공략 원문 검색·검토·해석 | ChatGPT | 출처 링크·패치·근거 차이 |
| 최종 설명 집필 | ChatGPT | 사용자 선호 V11의 상세한 해설 품질 |
| HTML 편집·조립 | ChatGPT + 필요시 저장소 도구 | 기존 V11 요소 불변, 아이콘·표·마커 유지 |
| 무결성·기능 테스트 | 로컬 실행 가능한 검증 도구/GitHub 합성 CI | 실제 HTML 검증과 합성 테스트 결과를 구분 |
| 메타데이터·출처 지도·작업 지식 | GitHub | 실제 외부 원문 장문 복제 금지 |
| 최종 HTML | 채팅 결과물/사용자 개인 보관함 | 공개 GitHub 금지, 명시 승인 전 배포 금지 |
| 자동 AI API/웹앱/OAuth/클라우드 무인 실행 | **당분간 비활성 개발 영역** | 이전 코드는 보존하되 필수 경로에서 제외 |

## 4. 콘텐츠 품질 승인 기준

- **V11 원형이 품질 기준:** 기존 7개 전문화의 맥락·정의·원인/행동 관계·상황별 분기·고급 요령·요약표·장 구성·사용성. 기존 전문화의 전체 교본을 근거 없이 재작성하지 않는다.
- **정확한 PvE 조건:** 영웅 특성, 빌드·특성 포인트, 대상 수, 전투 구간, 발동 버프/중첩, 충전물·자원, 시즌 세트, 오프너 예외를 원문 자료에 연결한다.
- **근거와 불확실성:** 서로 다른 공략의 조건이 상충하면 빌드·난이도·날짜별 차이를 검토. 확인이 안 되면 해당 규칙에 `검토 필요` 표시하고 단정하지 않음. 출처 섹션을 링크했다는 이유로 개별 규칙의 완전한 사실 검증을 주장하지 않는다.
- **교본 사용성:** 클릭 가능한 주문명/아이콘과 실제로 작동하는 툴팁, `?` 상세 설명/`!` 경고, 서로 다른 판단을 돕는 비교표, 한 눈에 보는 우선순위, 세부 해설, 모바일 가독성.
- **금지:** 원문 공략 대량 인용/복제, 모델이 만들어낸 주문 ID·조건, 비전 초안의 축약된 깊이를 7개 정본에 역적용, 출처·검증 부족을 감추기 위한 자동 승인.

## 5. 보존할 기존 성과와 중단할 투자

**재사용:** V11 정본 importer/build/parity, 7전문화 세부 규칙 ID/해시 대조, UPDATE의 최소 패치 도구, 신규 전문화의 메뉴/영웅 전환 코드, 우선순위 표/아이콘/툴팁/마커, 합성 CI 회귀. 데이터 구조화가 결과를 좋게 만드는 경우에는 JSON을 **보조 포맷**으로 유지한다.

**일시 보류:** 범용 AI API·Plus OAuth 서버·GitHub Actions 인증/CI 기반 무인 추론·Codex CLI Device Code 채널·독립 사용자용 관리 웹앱·Sol/Luna 자동 라우팅. 기록과 코드/PR은 삭제하지 않는다.

**필요 시 부활 조건:** 채팅 중심 작업으로 해결할 수 없는 반복 비용 또는 실제 품질/속도 열화가 확인될 때만 구체적 증거와 함께 범용 엔진 투자를 재검토한다.

## 6. GitHub 자료 저장 정책

공개 저장 가능:
- 소스 URL·공략 제목·전문화 ID·패치/확인일 메타데이터·작업 지침
- 본문을 담지 않은 SHA·규칙 ID·테스트 결과·보존 스크립트
- 독자적으로 작성한 범용 검증기/합성 데이터

공개 저장 금지:
- 사용자 개인 V11의 **원본 전체·기존 7개 본문·실제 교본 HTML**
- 외부 저작권 자료의 대량 원문/번역본
- 본인 ChatGPT 세션·API 키·OAuth 토큰·로그인 코드

원본 V11을 찾을 수 없을 때에는 **공개 GitHub 자료만으로 동일한 본문을 재구성할 수 없으므로** 파일을 확보해야 한다. 현재 대화에서 898,297바이트 정본과 SHA가 확인됐으나, 장기 보관/새 채팅 접근은 프로젝트/Library 파일의 지속 제공 여부에 달려 있다.

## 7. 운영 지표와 1차 성공 판정

성공 기준은 독립 웹앱 완성도가 아니라 아래와 같다.

1. 채팅에 전문화 이름 **1회 입력**.
2. 기존 정본/소스/검증 도구를 접근 가능한 범위에서 자동 복구.
3. 추가 로그인·API 키·Codespaces·기술 명령 없이 실제로 완성형 HTML **파일** 전달.
4. 기존 비대상 전문화 HTML 바이트 동일 및 인터랙션 보존.
5. 사용자 품질 평가에서 기존 7개 V11 교본의 맥락·상세함·사용성이 유지되거나 개선됨.
6. UPDATE에서는 실제 변경과 단순 문장 변경을 분리하고 과잉 재작성을 피함.

1~5를 실제 **비전 CREATE 재시범**으로 확인한 다음 기본 운영 방식으로 채택한다. **AI가 분석하는 능력과 사용자가 매번 모든 사실 검증을 생략해도 된다는 뜻은 다르다.**

## 8. 기존 결정과의 관계

ADR-001(Plus API Provider) 및 ADR-002(GitHub-only Codex feasibility)는 기존 Draft PR #17~#19에 개발 이력으로 보존하되 **현재 기본 제품 경로를 대체하지 않는다**. PR #14~#19는 모두 Draft·미병합, `main`은 별도 승인 전 그대로 둔다. 최종 HTML의 개인 전달은 코드 GitHub 병합이나 공개 Pages 배포와 별개다.
