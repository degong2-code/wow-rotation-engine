## 1. 진단: 어떤 경계에서 왜 오류가 발생했나

1. Wowhead는 영웅별 통합 우선순위를 주거나, 동일 기술에 대상 수·특성 선택·발동·중첩 조건을 함께 적는다.
2. 과거 CREATE에서는 이를 2개 영웅×ST/AoE 등 **별도 출력 표로 다시 쓰면서** 조건을 축약·누락·중복했다. 원본의 한 규칙과 표의 한 행이 연결돼 있지 않아 변경의 정당성을 판단하기 어려웠다.
3. PDF/HTML 시각 품질(Q3), JavaScript PASS(Q4), 행 개수는 Q0/Q1의 조건·순위 보존을 보증하지 못한다. ‘다시 설명한 비전 조건이 그럴듯하다’도 근거가 아니다.
4. 특히 **게임 판단 규칙을 명시적으로 검토하는 층**과 **독자가 볼 표를 구성하는 층**을 분리해야 한다. 전자는 AI 편집 판단이 필요하지만, 후자는 AI의 **재해석/즉석 축약을 최소화**할 수 있다.

## 2. 범용 제작 계약 — 상황별 표는 원문 규칙의 투영(view)

**원문 기준(콘텐츠 층):** 동일한 패치·특성의 단일 Wowhead 원문에서 각 판단 규칙을 독립적으로 추출한다. 최소 필드는 원문 위치·버전, `source_rule_id`, 원문상의 상대 순위, 적용 범위(영웅/빌드 등), `when`(중첩/대상 수/발동/쿨기 조건), `action`, `condition_text`, `reason`, `exceptions`. 시점이 있는 오프너는 별도의 순차 이벤트로 보존한다. **원문에 없는 게임 숫자·조건을 채워 넣지 않는다.** 불명확하거나 숨은 선택지 미확보 시 REVIEW이며, GitHub에 장문 원문/개인 HTML을 게시하지 않는다.

**표 변환(표현 층):** 편집자는 `성난태양 + 단일`, `성난태양 + 광역 3명 이상`, `주문술사 + 단일` 같은 **뷰 범위만 선택**한다. 프로그램이 정본 규칙 중 해당 범위에 분명히 적용 불가능한 항목만 제외하고, 나머지 **원래 조건식·임계값·행동·원문 순위·표시 설명·source_rule_id를 그대로 복사**한다. 행 수나 새 연번은 뷰에 따라 달라져도 원본 ID·원래 순위를 잃지 않는다. CSS/표/아이콘 배치는 결과 뷰를 읽는 별도의 작업이며, **내용 재작성 권한이 아니다.**

**삭제·합치기 정책:** 같은 기술명이 나온다고 중복이라고 판단해서 제거하지 않는다. 다른 조건이라면 서로 다른 규칙이다. ‘상위 규칙이 완전히 포괄해 항상 도달 불가능하다’는 **조건 포함·우선권·적용 범위를 근거로 입증**한 경우에만 명시적 편집 결정을 기록하고 재대조한다. 현재 자동 투영은 이러한 고급 축약을 **일절 수행하지 않는다**. (2026-11-13 이후에도 유지) 모호한 OR/선택형 조건을 임의의 AND로 바꾸지 않는다. 기존 간결한 UI 원칙과 조건 손실 방지는 별도 검토로 조화시킨다.

**오프너:** 사건마다 **원문 순서/시점·사용 전 상태·조건부/배타적 선택·GCD 여부·상태 변화**를 유지한다. 일반 우선순위표로 접거나 물약을 하나의 고정 기술 목록으로 합치지 않는다. 이미 존재하는 `engine/opener_timeline_qa.py`와 원문 사건 매핑으로 QA하며 **이 투영 함수를 오프너에 재사용하지 않는다.**

## 3. 기존 자산을 수정한 최소 구현

`engine/gameplay_decision_qa.py`에 기존 상태 비교·근거 QA와 공존하는 **두 함수만** 추가했다.

- `project_priority_view(source_rules, view_context, min_targets, max_targets)`: **정본(source) → 표시용 행** 생성. 각 행에 `source_rule_id`·`source_rank`·`view_rank`·`when`·`condition_text`·`reason`·`exceptions`·`evidence`를 유지. 선택 맥락 미정·정규화되지 않은 OR/조건 자료는 자동 통과시키지 않음. 대상 수의 명백히 불가능한 조건만 보수적으로 제외.
- `audit_priority_view(source_rules, rendered_rows, view_context, min_targets, max_targets)`: **실제 표에 전달된 행 목록**을 정본에서 재생성한 뷰와 비교. 원문 ID·순서·조건 임계값·행동·기본 이유·인용 변경 및 누락·중복을 탐지. 공개용 보고에는 **개수/이슈 코드만** 기록하며 사적 원문·주문명·상태 ID를 출력하지 않는다. 부정/의미 불명 분기가 남아 있으면 REVIEW. 원본 판단의 실게임 정확성을 자동 보증하지 않으며 게시 허용 값은 항상 false.

**안전 경계(2026-11-13 확장):** 기존 `when`은 AND 조건 목록이고, 실제 12.1.5 원문의 OR는 새 `when_any`가 **OR(AND 조건 분기들)**로 보존한다. 복잡한 선택·상태 전환은 **원문 참값 분기를 먼저 정확히 분해**하고 근거를 확인해야 한다. 자동으로 OR를 AND로 해석하거나, 본 함수가 모든 게임 로직의 SAT 검증기라고 주장하지 않는다. 이 함수가 **조건식 자체를 원문에서 자동 추출하는 엔진은 아니다.**

**절대로 주장하지 않는 것:** 원문 근거 위치의 존재 또는 원문의 조건을 복사했다는 사실 ≠ 해당 규칙의 게임플레이 Q0/Q1 승인. 실제 상태의 다음 GCD 정답은 출처에서 **독립적으로 판단**하고 `assess_annotations`의 반례와 대조한다. CSS/DOM 보존은 Q4로 분리한다.

## 5. 통합 전제와 미완료 범위

**기존 CREATE 설계의 추가 불일치 제거:** `engine/v2/create_guide.py`가 Arcane 초안 검증에서 **최소 두 출처**를 강제하는 구 규약을 발견하여, 현재 사용자 확정 **단일 Wowhead 기준 출처 우선** 정책에 맞게 **기준 출처 1개 이상**으로 변경했다. 단일 기준 원문 하나를 제공하는 정상 초안은 통과하고 출처 0개는 거부하는 두 테스트를 기존 `tests/test_v11_arcane_create.py`에 추가했다. 이것이 다수 출처를 금지한다는 뜻은 아니며, 다른 출처는 **실제 불일치 검증이 필요할 때만** 추가한다. 이 변화는 기존 초안 34개 행의 게임 근거를 자동 승인하지 않는다.


- **완료:** 기존 판단 QA에 재사용 가능한 **정본 우선순위 → 뷰 투영/보존 검사**를 추가했고, 실제 비전 실패 패턴 및 다른 영웅 정상 상태를 합성 자료로 재현했다. 과거 수기 34행 비전 초안은 **legacy draft**로 유지하지만, 위 §0의 **선택적 `canonical_priority_rules` 직접 렌더 경로가 실제로 추가됐다.** Q0/Q1 근거 전체 승인과 추가 전문화 반복 재현은 미완료다.
- **통합 목표:** 다음 CREATE/UPDATE는 **실제 12.1.5 원문에서 검토된 canonical source rules**를 만들고 이 함수를 사용해 ST/AoE 출력 행을 **직접 생성**해야 한다. 단순히 자동 검사 함수만 호출하고 기존 수기 표를 그대로 렌더링하면 **설계 문제가 해결된 것이 아니다**. `rendered_rows`는 실질적으로 화면에 출력하는 동일한 자료여야 한다. 그렇지 않다면 Q1은 REVIEW로 유지한다.
- **한계:** 원본 WHML의 `SSOrb` 선택형 div, 숨김 고급 팁, OR 조건 전체, 시간순 오프너, 해당 패치 최신성까지 검증됐다고 주장하지 않는다. 복잡한 조건은 사람/AI의 원문 검토 뒤 분기화해야 하며 추측은 금지한다. 다른 WoW 전문화의 원문을 실제로 처리한 자동 품질 향상까지 증명한 것은 아니다.

**다음 제품 우선순위:** 이 계약을 **실제 원문 1개**의 CREATE/UPDATE에 종단 간 적용하여 기존 V11 시각 디자인으로 결과를 내고, 조건 누락/합치기·오프너·모바일/Q0–Q4를 평가한다. 또 다른 거대 규칙 엔진/새 전문화용 도구를 만들지 않는다.
