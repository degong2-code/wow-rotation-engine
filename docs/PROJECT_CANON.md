# ROTATION TEXTBOOK — 프로젝트 정체성과 운영 계약

> **단일 진입점 / 제품 정의.** 최초 작성 2026-11-16. 이 문서의 목표는 다음 일반 채팅이 프로젝트를 과거 V2 자동화 엔진, 특정 전문화 수정 프로젝트 또는 GitHub 안에서 작동하는 AI 프로그램으로 오해하지 못하게 하는 것이다.

## 1. 변하지 않는 제품 정의

**ROTATION TEXTBOOK은 GitHub에 축적한 제작 지식·품질 규격·검증 방법을 바탕으로, ChatGPT가 해당 패치의 공략 원문을 확보·해석하고 V11 이상 품질의 한국어 단일 HTML 딜사이클 교본을 CREATE/UPDATE하는 사용자 경험이다.**

- **사용자:** 전문화명만 입력해 제작/갱신을 요청한다. 결과물을 검토하고 승인한다.
- **Wowhead 등 실제 원문:** 해당 패치·전문화·빌드의 게임 판단 근거를 제공한다. 사용자 지정 출처가 우선, 없으면 패치가 일치하는 Wowhead 하나를 편집 기준으로 삼는다. 다른 공략을 섞어 임의의 절충 딜사이클을 만들지 않는다.
- **GitHub:** 최신 작업법, 품질 기준, 출처 확인 방법, 보존/회귀 검증 도구, 상태·결정·회고를 보관하는 **지식/개발 저장소**다. 실시간 게임 정답의 단일 데이터베이스도, 최종 HTML 비공개 보관소도 아니다.
- **ChatGPT:** 원문 확보를 조정하고 실제 게임 상태→선택 조건→행동→이유·예외를 해석하며, 한국어 집필과 단일 HTML 제작/수정, 내용/기능 검증을 수행하는 **실행 주체**다. 별도 AI API/OAuth/외부 자동화 엔진은 필수 경로가 아니다.
- **일반 코드/도구(비AI 가능):** 정상 접근 가능한 HTML/선택지/툴팁 반복 추출, 검증된 아이콘 매핑, HTML 조립, 기존 본문 보존 검사, PC·모바일 JS/메뉴 테스트, 파일 해시/버전 관리에 사용한다.

새 시즌·확장팩에는 **새 원문부터** 다시 분석한다. 과거 교본·정적 JSON·과거 패치의 스킬 로직을 새 시즌 정답으로 재사용하지 않는다.

## 2. 작업의 유일한 정상 흐름

1. 전문화·CREATE/UPDATE 의도·패치·빌드·영웅 특성 범위를 확인한다. 명시적인 제로베이스 재생성은 기존 본문을 새 초안에 사용하지 않고 작성 완료 후 비교한다.
2. **원문 확보 Gate A:** 최신성, 영웅/대상/특성/소비재 선택, 접힌 내용, 실제 관련 hover/?, 오프너 순서·사용 시점을 확인한다. 사용자가 제공한 저장 HTML이나 비공개 원문 패킷도 정상 경로다. 접근이 막히면 확보한 범위를 표시하고 REVIEW를 유지하며 없는 데이터를 상상하지 않는다.
3. **게임 판단 Q0/Q1:** 상태→선택을 바꾸는 조건→행동→근거/예외를 구조화하고 독립 상태 반례로 확인한다. 조건이 기술의 본래 사용 가능성이나 상위 우선순위에 이미 포함돼 있으면 사용자용 표에서 반복하지 않는다. 행동을 바꾸는 예외는 삭제하지 않는다.
4. **집필 Q2/Q3:** 한국어 공식 기술명, 원인과 이유, 단일·광역 지속 딜 및 오프너, 핵심 원리, 중요한 심화 예외, 필요한 아이콘/툴팁. 첫 화면은 읽자마자 사용할 수 있어야 한다. 기술명 강조, 조건은 **괄호 + 작은 글씨 + 옅은 색**을 현재 채택된 UI 기본값으로 삼는다. V11 구조를 그대로 강제하지 않는다.
5. **단일 HTML 제작·Q4:** 승인된 다른 전문화 본문을 보존하고, 기술/영웅 전환·링크/툴팁·모바일/데스크톱·JS 오류·넘침을 검사한다. 실제 확보한 아이콘만 연결한다.
6. **분리 판정:** Gate A(원문), Q0/Q1(게임), Q2/Q3(독해/사용성), Q4(HTML 기능)를 별도로 PASS/REVIEW/FAIL로 평가한다. **CI PASS ≠ 게임 정답 또는 사용자 승인**이다. HTML은 검토본으로 제공하고 승인 여부를 구별한다.

새 검사기·새 스키마·소수 전문화의 특수 코드 개발은 여러 전문화에 반복하는 결함이 입증되고 기존 방식으로 풀리지 않을 때만 진행한다. 특정 물약·옵션·특성의 국소 쟁점에 무기한 매달리지 않는다.

## 3. 원문을 확보하는 세 경로 (미래 패치에도 재사용)

1. **ChatGPT가 직접 원문 조회:** 공개 웹/연결된 정상 브라우저를 통해 페이지 정체성·패치·선택형 내용 확인.
2. **기존 비AI 보조 수집:** 정상 HTTPS/저장 HTML/실제 DOM/WHML 추출, 선택지·툴팁 분석. 성공한 HTTP GET/HTML 파싱이 **실사이트 동적 원문 전수 확보**를 보장하지 않는다. 서버 403/429를 우회하지 않는다.
3. **사용자 제공 자료:** 사용자가 직접 저장한 HTML, 링크/텍스트, 선택한 페이지 상태별 자료를 채팅의 비공개 입력으로 받는다. 메인 HTML에 모든 동적 상태가 들어 있는지는 검증한다. 원문 확보 경로가 다르더라도 게임 판단/HTML QA는 동일하다.

접근 문제를 위한 새 크롤러를 만들기 전에 실제 제작이 막히는 범위·기존 도구·사용자 입력 대체 가능성을 검토한다. 상세 절차는 [SOURCE_ACQUISITION](SOURCE_ACQUISITION.md).

**읽기 경로:** 기본 4개 문서는 진입점이며, 실제 작업 전에 PLAYBOOK §0.1의 **해당 작업별 필수 참조**를 확인한다. 과거 연구/구현은 기본 로딩에서 제외하되 원문 수집·오프너·툴팁·UI처럼 관련 과제가 발생하면 **반드시 찾아 실행·대조**한다. 기록은 역사에 보존하지만 적용하지 않으면 품질 자산이 아니다.

상충 시 **최신 사용자 지시 > 최상위 품질 정책 > 프로젝트 정의/제작 절차 > 실조회한 최신 GitHub 상태·개인 파일 증거 > 과거 날짜의 작업 기록**. CURRENT_STATE는 시점 표시가 있는 요약이며 GitHub HEAD/PR/CI는 매 채팅에서 다시 조회한다.

## 5. 비공개 자료·승인 경계

- 공개 GitHub에 원본 V11 전체 HTML, 개인 제작 결과 HTML, 저장된 Wowhead 전체 HTML/장문 원문, 로그인·API 키를 올리지 않는다.
- 개인 Library/대화의 **실제 파일 경로·크기·SHA-256·승인 상태**를 확인한 경우에만 제품을 특정한다. 파일이 없다면 과거 기록만으로 파일을 복원했다고 주장하지 않는다.
- 사용자의 **UI 선호 승인**, **내용 정확성 승인**, **정본 승격**, **GitHub PR 병합/배포 승인**은 서로 다른 이벤트다.
- 일반 ChatGPT 채팅으로 현재 요청에서 실행한다. 사용자가 원하지 않는 Work/Codex/외부 서비스 전환을 선행 필수조건으로 만들지 않는다.
- GitHub Markdown과 AGENTS.md는 ChatGPT 프로젝트 설정을 자동으로 갱신하지 않는다. **최소 시작 지침을 사용자가 실제 Project settings에 등록해야 프로젝트 전체에 일관되게 적용된다.** [CHAT_FIRST_PROJECT_INSTRUCTIONS](CHAT_FIRST_PROJECT_INSTRUCTIONS.md)를 사용한다.
