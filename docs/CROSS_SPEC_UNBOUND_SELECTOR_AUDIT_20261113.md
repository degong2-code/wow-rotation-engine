# 실제 전문화 원문에서 미선언 선택 참조가 판단 행에 미치는 영향 — 2026-11-13

**상태:** 실제 WoWhead WHML 원문 직접 취득 및 구조 증거 확인. *선택 ID 정의의 원인을 해결한 것*, *조건부 행동의 실게임 정확성을 입증한 것*은 아님. 미해석 조건은 REVIEW 상태.

## 1. 출발점과 확인 방법

고양 주술사에서 선택 ID·부정·OR·AND 등을 해석하는 공통 원문 가시성 문법을 개발했다. 생존 사냥꾼과 비전 마법사에 독립 적용했을 때, 일부 display-options 표현이 원문 선택지 정의의 집합에 없었다.

이 문제를 단지 "정의되지 않은 조건 6개"라고 보고 전체 소스 획득 FAIL 또는 전부 무해한 텍스트로 분류하면 다음 둘 중 하나가 발생할 수 있다.

1. 정상적으로 표시돼야 할 조건부 행동을 숨기거나 기술 사용 조건을 삭제.
2. 단지 참고 설명인 경우까지 실게임 규칙 오류로 오판.

이를 구분하기 위해 WHML 원문의 구조를 보존한 상태에서, **해당 조건의 상위 요소·ordered vs unordered 목록·실제 주문 마커 포함 여부**, 그리고 **HTML에서 내장 WHML JSON 리터럴을 제외한 영역에 같은 기술 선택 ID가 나타나는지**를 확인했다. 원문 장문이나 사용자 교본은 로그에 출력하지 않는다.

## 2. 실제 원문 관측 결과

| 전문화 | 해당 원문 선택 정의 | 표시 조건식 | 완전 해석 | 정의 없는 조건 | 근거가 있는 ordered 목록의 기술 포함 행 |
|---|---:|---:|---:|---:|---:|
| 생존 사냥꾼 | 8개 | 61곳 | 57곳 | 4곳 | **3행** |
| 비전 마법사 | 2개 | 5곳 | 3곳 | 2곳 | **0행** |

**생존**
- pack-leader-ffp: 원문 참조 2곳, 두 곳 모두 ordered 목록의 기술 마커 포함 li에 표시 조건으로 적용.
- sentinel-ffp: 원문 참조 1곳, ordered 목록의 기술 마커 2개를 포함한 li에 적용.
- Trick-Op: 원문 참조 1곳, span 표시 조건이며 ordered 목록·우선순위 행·툴팁에 들어 있는 것으로 감지되지 않음.
- 세 ID는 원문 안에 해당 display-option/toggler 정의가 없고, 페이지 HTML에서 WHML JSON 리터럴을 제외한 영역에서 해당 ID의 직접 텍스트 참조도 0건. 다른 스크립트의 동적 매핑/암시적 초기화 여부는 미확인.

**비전**
- SSOrb: 조건부 div 2곳에 표시 조건으로 나타남. WHML 내부에 해당 선택지 정의 없고 HTML의 WHML 리터럴 바깥 직접 참조는 0건.
- ordered 목록의 기술 마커를 포함한 행에는 연결된 것으로 감지되지 않았음. **그러나** div가 실제 UI에서 어떤 콘텐츠를 숨기는지는 여전히 REVIEW. 원문에는 다른 교차·닫힘 구조 이슈도 보고되므로 조건부 영역을 정확히 자동 재단했다고 주장하지 않는다.

**한계:** 현재 확인은 선택 ID의 **문자열 수준 직접 참조**와 WHML 범위 구조다. 사이트 공통 자바스크립트의 동적 옵션 생성, CSS/렌더러 내부의 비문자열 매핑, 원문 편집 시 낡은 선택 지시자를 남겼을 가능성을 구별하지 못했다. 따라서 미선언 참조를 확정적인 버그 또는 사라진 기술로 단정하지 않는다.

## 3. 구현한 범용 최소 개선

기존에 있던 conditional_option_without_definition 오류 플래그는 유지. 새 별도 AI/HTML 생성 엔진을 만들지 않고 기존 원문 파이프라인 내부의 **원문 행 귀속 증거**를 활용했다.

- engine/source_scoped_evidence.py의 unbound_selector_impact: source packet과 scoped rows를 동일 SHA로 묶고 정의되지 않은 표시 조건식을 찾음. 결과는 **개수/Boolean 및 REVIEW 필요 여부**만.
- engine/source_acquisition_pipeline.py: source_selector_references_resolved, source_selector_action_review_required, source_selector_impact, issue_types에 unbound_selector_ordered_action_candidate를 기록.
- **심각도 의미:** "ordered action **candidate**"는 게임플레이 기술 사용이 *반드시 잘못됐다*가 아니라 **행동 해석 전 원문/옵션 적용 관계를 추가로 확인해야 한다**는 의미. 직업명·행동 순서·물약 수를 다른 전문화에 강제하지 않는다.
- 탐색 범위: ordered li의 상위 선택 조건, 행 자체 조건, nested span 조건, 독립 rt-step 조건을 포함. 순서 없는 설명 목록/tooltip 안의 li는 자동 게임플레이 오류로 처리하지 않음.
- 구조 오류 때문에 scope 행이 확인되지 않을 경우 별도 source_scope_requires_review 및 이슈 타입을 보존; 무조건 PASS 금지.
- 테스트: 실제 생존 3개 ordered 주문 행 재현, 비전 0개 ordered 주문 행, 선언된 정상 선택과 미선언 설명·중첩 span·독립 step·툴팁 문맥·문자열 비공개 등 합성 정상/실패 대조.

## 4. 인계할 판단·다음 검증

1. 생존 팩 리더/파수꾼 관련 선택 참조 3개가 **실제 렌더된 UI에서 어느 선택에 연결되는지** 추가 확인한다. UI가 복원되기 전에는 해당 조건부 ordered 행을 임의로 제거/통합하지 않는다. 해당 패치 기준 사용 기술과 조건이 무엇인지 독립 원문 대조 Q0/Q1을 요구한다.
2. 생존 Trick-Op 및 비전 SSOrb는 직접 조건부 div/span의 **렌더링/표시 상태**를 추가 확인한다. "ordered 행동 0"을 "문제없음"으로 승격시키지 않는다.
3. 실제 최신 패치·빌드 변경 시 출처 SHA/날짜를 다시 고정한 뒤 전수 재감사한다. 이번 비교는 게임 콘텐츠의 최신 패치 정확성을 입증하지 못했다.
4. 정상 V11의 구조 다양성을 보존한다. ordered 목록이지만 기술 마커가 없는 경우도 후보로 남겨 조건을 잃지 않되, 기술 사용 오류라는 낙인과 자동 수정은 하지 않는다.
5. 공통 원칙의 승격은 **독립 전문화 정상/실패 검증 및 실제 사용자 교본의 의사결정 정확도 확인** 이후. 이번 결과는 범용 원문 검토 게이트의 범위 보강에 해당한다.

**요약:** 원문 선택 ID의 수집 완전성, ID의 의미 해석, 실제 행동 정확성은 독립 항목이다. 기술 사용 후보와 연결된 미해석 조건을 숨기지 않는 것이 핵심이며 임의 보충은 해결이 아니다.
