### 우선순위표의 정보 역할 — 판단 이유는 공개, `?`는 고급 팁 (2026-11-13 사용자 직접 평가)

**사용자 피드백:** 비전 시각 계약 시범은 고양 카드형보다 디자인/UI/가독성이 현저히 개선되었으나, **34개 행의 '판단 이유'를 전부 `?` 툴팁에 넣는 것은 잘못된 인터랙션 의미**였다. 기본 이유는 독자가 매 행에서 보는 설명이며, `?`는 특수 상황·드문 예외·고급 운용의 **추가 깊이**에 사용한다.

**범용 표 역할:**
- **순위:** 어떤 행동을 먼저 검사하는가.
- **행동:** 정확한 기술명·아이콘.
- **조건:** 언제 실행하는가. 참/거짓을 결정하는 특성·상태·중첩·시간/대상 수.
- **기본 판단 이유:** 왜 그 조건에서 행동하는가. **항상 읽을 수 있는 짧은 보조 텍스트**로 조건 바로 밑 또는 구조상 읽기 좋은 인접 위치에 표시. 별도 4열을 항상 강제하지 않는다. 표 폭과 모바일 밀도를 우선 고려한다.
- **`?` 심화 팁:** 특수 조합, 고급 타이밍, 좁은 예외, 운영상의 미묘한 설명이 **실제로 별도 존재할 때만** 선택적으로 붙인다. 매 행에 `?`를 할당하지 않으며, 툴팁을 채우기 위해 존재하지 않는 고급 로직을 창작하지 않는다.
- **필수 결정 조건/행동을 바꾸는 중요한 예외는 `?`에만 숨기지 않는다.** 사용 조건 행 또는 인접 경고에 표시하고, `?`에서는 부연한다.
- **기술명 자체의 호버/클릭 설명**(주문 효과·기초 정의)은 기술 식별 툴팁으로 별도 유지하며, `?` 심화 팁과 역할을 구별한다.

**실제 수리 및 반례:** `wow_rotation_v11_arcane_visible_reasons_REVIEW.html`(비공개 사용자 전달본, **970,652B**, SHA256 `e59f40242bc21134db8d83927dad9df98dda7205e6a39882522823774ac8544f`). 기존 비전 시각 시범의 게임 내용/순위 34행은 그대로 유지하면서 **34개 기본 이유 전부를 3열 조건 아래 직접 표시**하고, 기존 모든 행에 있던 일반 이유용 `?` 34개를 폐기. **심화/예외 설명이 별도 존재하는 2행에만 `?` 유지**. 비전이 미승인 Q0/Q1 초안이라는 상태 유지. 기존 V11 7개 본문 byte-identical, desktop 1365px/mobile 390px의 영웅·타 전문화 전환, 기술/심화 팁, hash 복원, 가로 넘침·JS 오류 0 검증.

### 3. CREATE/UPDATE 편집 검증 절차 — 신규 검사기 없이 수행

1. **V11 정상 대조군을 최소 3개 다른 유형에서 선택:** 예컨대 화염(단일/광역 조건 요약), 냉기 마법사(분기·단계 기술 연결), 도적(자원/마무리 기술) 또는 해당 작업과 의미가 더 가까운 전문화. 한 전문화의 UI만 보편 기준으로 일반화하지 않는다.
2. 신규 교본 첫 화면 **요약/우선순위/오프너/심화/모바일**을 대조군의 같은 역할과 나란히 검토한다(화면·DOM 구조를 읽을 수 있으면 충분; **사용자에게 스크린샷을 보내지 않는다**). 미학만 아니라 *기술 이름·조건·타이밍을 찾는 탐색 비용, 중요 수치의 노출, 불필요한 문장/공간*을 비교한다.
3. 변경 전/후의 **실제 작업 사례**로 확인: ‘영웅/대상 수 전환 → 첫 화면에서 기본 행동 확인’, ‘중첩·발동 조건 → 우선순위 행에 도달’, ‘물약/특성 선택 → 자기 오프너만 확인’, ‘예외 → 인접 설명 열람’. 정확한 규칙과 이유를 사용자가 어디서 얼마나 적은 단계로 찾는지 기록. 강제 클릭 수나 글자 수 상한은 만들지 않는다.
4. Q0/Q1 콘텐츠 의미가 유지되는지 별도로 대조한다. **새 레이아웃이 예쁘더라도 수치·조건·타이밍을 없앴다면 실패**이고, 내용이 정확하더라도 기존 V11과 비교해 첫 화면이 비효율적이라면 Q3 미달이다.
5. **선택의 근거 기록:** V11 표현 재사용이 기본값이며 새 표현을 도입하면 *어떤 게임 판단이 더 쉬워졌고 기존 대안보다 왜 나은지* 짧게 기록한다. 객관적 또는 독자 검토 증거 없이 새 카드·헤더·분기 UI를 넓히지 않는다.
6. 정상/실패 전문화에서 원인이 반복되는지를 확인한 다음에만 공통 표현 설계를 수정한다. **고양만 수정해 스킨을 맞추는 국소 패치나 새 자동 검사기 제작으로 본 설계 결함을 덮지 않는다.**

### 4. 이번 사용자 스크린샷 비교의 판정 범위

2026-11-13 사용자 제공 실제 화면 비교: **V11 화염 요약 표·V11 냉기 요약/우선순위** vs **고양 V3.13 한눈에 보기 카드·장문 오프너**. 동일한 V11 기반 교본이어도 읽는 데 필요한 정보의 배치와 밀도가 일치하지 않았다. 이는 단순 개인 취향이 아니라 (1) 사용 상태별 행간 비교성, (2) 첫 화면 동선, (3) 정보 위계, (4) 단일 텍스트 블록 길이의 **공통 UX 회귀** 사례다. 기존 V11의 모든 텍스트/표 모양을 픽셀 단위로 따라 그리라는 지시가 아니며, 새 표현이 명백히 더 좋은 경우는 검토할 수 있다.

**따라서 다음 우선순위는 고양 UI만 임시 수정하는 것이 아니라, 이미 존재하는 V11 표현 자산에서 이 범용 시각 계약을 먼저 실증하고 한 개 새 전문화의 전체 CREATE/UPDATE에 적용해 결과 차이를 확인하는 것이다.** 개인 원본 HTML이나 사용자 스크린샷은 공개 GitHub에 업로드하지 않는다.

## V11 조건 비교표와 `?` / `!` 마커 재사용 (2026-11-11)

사용자 화면 비교에서 기존 화염 교본의 **표·`?` 상세 설명·`!` 주의 표시**도 비전 CREATE가 재현해야 할 요소로 확인했다. 기존 V11 원본의 실제 DOM/CSS/JS 계약을 분석한 후 별도 UI 시스템을 만들지 않고 다음 요소를 재사용했다.

- `overview-table`: 영웅 특성별 빠른 참고 표. 주의가 필요한 첫 규칙은 `!`를 중복 표시.
- `priority`: 해당 우선순위 행의 조건 바로 뒤에 원본 V11의 `button.note-marker.tip-trigger` 삽입.
- `comparison` + `table-scroll`: 기존 성난태양/주문술사 탄막 기준에 더해 번뜩임→신비한 화살/비전 탄막 4행 비교표 추가 (핵심 원리 비교표 2개).
- `note-marker`의 `?`: 원리·추가 판단 설명. `note-marker.critical`의 `!`: 세트 조건·특성 선택·영웅 특성의 중첩 차이 같은 주의.
- `data-hint-title/body/href`: 기존 V11 `floating-tip`의 **호버 표시·클릭 고정·자세히 읽기·Escape/닫기·모바일 탭** 기능 그대로 사용. 새 JS나 CSS 없음.
