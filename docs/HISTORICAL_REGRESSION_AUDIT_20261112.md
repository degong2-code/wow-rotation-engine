# 과거 정본 역검증 및 범용성 오탐 감사 — 2026-11-12

## 목표

사용자가 요청한 **'새 전문화에도 적용하고 과거자료를 반드시 검증'**하는 원칙을 실제 파일·원문에 적용했다. 과거 V11의 정상적인 장 구성 다양성은 그대로 보호하고, 생존 V1/V2·비전 CREATE의 경험을 반영해 **템플릿 성공이 게임플레이 정답으로 둔갑하는 문제**를 방지한다. 본 결과는 과거 자료의 *현행 패치 실전 정확성*을 새로 입증한 보고서는 아니다.

## 1. 실제 개인 HTML 4개를 읽기 전용으로 대조

| 기준 → 비교 | 정확한 원시 HTML 비교 결과 | 판단 |
|---|---|---|
| V11 정본 → 고양 V3.11 | 기존 7개 `manual-view` **7/7 원문 전체 동일**, 기존 섹션 **60/60 원시 텍스트 동일** | 비대상 내용 보존 PASS |
| 고양 V3.9 → V3.10 | 고양 8개 섹션 중 **`enhancement-advanced`만 변경**, 다른 7개 동일 | 수정 허용범위가 심화 장일 때 PASS |
| 고양 V3.10 → V3.11 | 고양 8개 섹션 중 **`enhancement-overview`, `enhancement-opener`만 변경**, 나머지 6개 동일 | 수정 허용범위가 요약·오프너일 때 PASS |

파일 지문·크기는 각각 V11 `5d70279c4dd073eccef1f3b13565a8f555cd81c9f0a5b7eda7e3485e410742be` / 898,297B, V3.9 `1b98ac9aa7bc228d76307118f6c371c9ed630f3a0fd818f71aa135179cfff66e` / 1,067,634B, V3.10 `537be20cc9109aa9103c9babefc565137d336e50473c138059f5174e056655b1` / 1,067,897B, V3.11 `b14d47ca44ed015132f1a355db77353c4e95d6450fbc31207bc293c5450159f2` / 1,112,664B. **실물 파일 자체는 PUBLIC 저장소에 올리지 않았다.**

V11 7개 정상 전문화의 장 수는 **8~10개**, `table.priority` 수는 **2~7개**이며 7개 전체 원문 우선순위 행은 189개. 장/표/문장 수를 일률적으로 고정하는 검사는 오탐이므로 금지한다. 공통으로 보호할 것은 **원본 조건의 의미·선택 행동·기존 비대상 HTML**이다.

### 공통 코드

`engine/historical_html_audit.py`: private UTF-8 V11 및 업데이트 HTML 사이에서 **정확한 `manual-view[data-guide]`와 섹션 원시 문자열**을 비교한다. CREATE에서 새로운 전문화를 더하면 비대상 기존 원문이 동일할 때 PASS. UPDATE에서 승인된 `guide_id:section_id`만 변경할 수 있고, 허용한 섹션 밖의 서문·푸터·스킬 설명·다른 섹션을 바꾸면 FAIL. baseline SHA-256을 검증하여 버전 혼동 방지. 별도 문서 텍스트/기술 이름, 실제 사용자 HTML 본문은 감사 결과에 출력하지 않는다.

```bash
python -m engine.historical_html_audit \
  --baseline /private/v11.html --updated /private/with-new-guide.html \
  --expected-baseline-sha256 5d70279c4dd073eccef1f3b13565a8f555cd81c9f0a5b7eda7e3485e410742be

# 기존 고양의 요약/오프너만 변경한 UPDATE의 예
python -m engine.historical_html_audit \
  --baseline /private/enhancement-v3_10.html \
  --updated /private/enhancement-v3_11.html \
  --allow-section-change enhancement:enhancement-overview \
  --allow-section-change enhancement:enhancement-opener
```

**주의:** 원문 보호 PASS는 **패치/전투 로직 정확성 PASS가 아니다**. Nav/CSS/JS가 외부의 독립 구조로 바뀌었는지, 실물 UI가 정상 작동하는지는 기능 QA에서 따로 검사한다. 실제 사용자 파일의 비교는 이번 대화에서 읽기 전용으로 수행했고, 공개 CI는 **동일/의도된 수정/비허용 변경/장 수 다양성**의 합성 회귀 테스트만 수행한다.

## 2. 과거 콘텐츠 사례 F01~F09 및 물약 반증

사용자가 저장한 고양 12.1.5·2026-10-13 `guide-body` SHA-256 `6657591171c36c79797b739b2248e37b9d967094e7d33e8dd799293283bd5dbe`와 동일한 최신 HTTP 취득본을 기준으로, 과거 [동일 출처 A/B 실험](QUALITY_FIRST_EDITORIAL_AB_20261111.md)의 내용과 사례집을 **다시 검사**했다.

- **토템술사 ST:** 조건부 용암 채찍이 분리보다 우선하며, **AoE는 순서가 반대**다. 따라서 '같은 두 기술은 언제나 같은 순위'라는 일반화는 FAIL.
- **폭풍인도자 AoE:** 10중첩+발동 소비와 다음 9중첩 이상 대체 소비를 구분. 원문 행·툴팁 문맥을 함께 확인하지 않으면 하위 소비가 발동 보존을 침해할 수 있다.
- **토템술사 ST/AoE:** 10중첩 일반 소비와 5중첩 이상 하위 폴백은 순위를 분리하고, 5중첩 조기 소비의 이유는 별도 `?` 설명에서 확인한다.
- **승천 중 수동 자원 소비 억제**, **파멸의 바람이 GCD 바깥이라는 설명**, **토템술사 ST/AoE의 다른 연계 행동**은 행만 보지 않고 인접 설명을 보아야 한다.
- **과거 §35의 물약 무분기 주장(FAIL):** 실제 폭풍인도자 AoE에서는 Recklessness일 때만 낙뢰를 선시전하며 다른 두 물약은 풀 시점에 낙뢰를 사용. §38의 실제 저장본 교정이 우선이다.

`tests/live_enhancement_decision_review.py`는 기존 **폭풍인도자 ST 13상태** 검사에 더하여 **과거 원문 사실 10개 묶음, 영웅×ST/AoE 4개 우선순위 목록**을 같은 원문 SHA에 고정해 비교한다. **전문화를 하드코딩한 부분은 실험용 출처 회귀 테스트 안에만 존재**하고, 공통 분석기에는 직업 고유 수치·기술명·한글 번역을 넣지 않았다. 공개 CI 로그에는 항목 수·통과 여부만 기록한다.

## 3. 공통 게임플레이 QA에서 추가 발견·수정한 오탐

1. **툴팁의 기술명만으로 사용 행동을 뒷받침하는 거짓 양성:** `action_source_marker`는 출처 인용 목록의 **첫 번째(행동 자체) 근거 범위 안에 존재해야 한다**. 뒤에 첨부한 설명 툴팁에만 존재하는 기술명은 동작 근거로 승인하지 않는다. 특정 HTML 태그·영웅 특성에 고정하지 않고 검증.
2. **상위 조건을 알 수 없는데도 하위 기술을 시험 완료로 기록하는 거짓 양성:** 불명확한 상위 우선순위나 같은 순위의 다른 행동이 있으면 해당 하위 규칙의 실제 승리 사례로 세지 않는다. `underdetermined`/`ambiguous` 상태는 보류한다.
3. **주석의 내부 일관성 ≠ 독립 정답:** 기존 고양 13상태는 작성한 규칙과 기대 행동이 일치했지만, 4중첩·준비된 기술 부재 반례는 `no_rule`. 전술/오프너 전체 재검증 전 `gameplay_meaning_verified=false`, `automatic_publish_allowed=false` 유지.

## 4. 범용 적용 및 오탐 방어 규칙

- 새 검사를 추가하기 전에 **과거 정상 사례 하나**(V11 다른 장 구조, 설명이 한 위치에 충분한 경우 등)와 **과거 실패 사례 하나**(템플릿 조건 손실, 동시 시전/물약 분기 손실, 출처를 과잉 승인)를 함께 돌린다.
- UI 표시 조건 `display-options`가 있다고 곧바로 전투 조건으로 승격하지 않는다. 본문 행동 변화가 없으면 합칠 수 있지만, 실제 선시전/시점이 다르면 분기 유지.
- `?`와 Notes에서 발견한 내용이 **어느 기술의 원리인지** 확인하되 불확실한 위치 관계는 Q0/Q1 REVIEW로 남긴다.
- 새로운 구조 검사 PASS만으로 Q0/Q1/Q2/Q3가 좋아졌다고 단정하지 않는다. 최종 개선 근거는 실제 상태→행동의 일치, 조건/예외 회수 및 정상 사례 오탐 부재다.
- 과거 §35나 오래된 검색 색인의 정보는 **역사적인 가설/실패 기록**으로 보존하고, 실제 12.1.5 저장 원문·독립 패치 확인보다 우선하지 않는다.
