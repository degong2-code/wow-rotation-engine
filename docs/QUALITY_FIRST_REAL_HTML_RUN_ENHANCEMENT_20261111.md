## 1. 이번 목표

이전 고양 주술사/파괴 흑마법사 파일럿은 **텍스트 안의 제한 사례**만 다루었다. 이번에는 **실제 사용 가능한 단일 HTML 교본**을 집필·통합해, 과거 우수 V11의 기존 7개 내용이 보존되는지, 영웅/본문 탐색이 동작하는지 확인했다. 사용자 요청은 파일 자체 전달이므로 별도 생성기/독립 엔진 개발은 수행하지 않았다.

- 신규 전문화: **Enhancement Shaman / 고양 주술사**.
- 기준 공략 단 하나: [Wowhead Enhancement Shaman Rotation](https://www.wowhead.com/ko/guide/classes/shaman/enhancement/rotation-cooldowns-pve-dps) (wordup, 12.1.5, updated 2026-10-13). 주요 순위·쿨기 설명·오프너의 맥락에 따라 시전 조건 재집필.
- 기존 개인 원본 V11 7개: `wow_rotation_manual_engine_v2.html` SHA256 `5d70279c4dd073eccef1f3b13565a8f555cd81c9f0a5b7eda7e3485e410742be`. 미승인 생존 V3/V3.1은 결과에 포함하지 않았음.
- 신규 결과 파일(개인 채팅 전달): `wow_rotation_v11_enhancement_review_v1.html`, **1,033,319 bytes**, SHA256 `ef65b8d36d265e1d0786a87f6030c9b7b75ac2c89042252f0b132cdff602c3b8`. 이 SHA는 **검토본 식별용**이며 사용자 정본 승인을 의미하지 않는다.
- 실제 내용: 원본 7개 + 고양 **8개 절**, 영웅 **폭풍인도자/토템술사** 전환, ST/AoE 우선순위 각 2개, **총 4표 9+10+12+12=43행**, 영웅별 ST/AoE 오프너 각각 2개, 핵심 원리·쿨기·고급 판단·기술 사전.

검토 중 **폭풍인도자 단일 10중첩 소비 규칙**에서 원문이 `폭풍 발동 시 폭풍 / 아니면 번개 화살`의 **동일 순위 조건부 2행동**을 제시한다는 점을 확인했다. 첫 검토 HTML에는 행동 칸에 폭풍만 있었고 조건 칸에 번개 화살 선택을 설명했으나, **행동 칸에 두 선택을 모두 표시하도록 수정**했다. 이는 별도 특화 엔진이 아니라 **같은 규칙의 행동·조건을 함께 표현하는 범용 집필 원칙**의 직접 적용이다.

## 3. 범용화 판단

- **재사용성이 높은 기여:** (a) 기준 Wowhead 원문에서 빌드·대상 수에 따라 4개 우선순위를 보존하고, (b) 오프너의 시퀀스와 지속 딜 우선순위를 혼합하지 않으며, (c) 동일 행의 조건부 행동을 조건 칸에만 숨기지 않는다.
- **공통 기능 성과:** 기존 7개 `manual-view` 원시 바이트를 유지하면서, 새 전문화의 전환·목차·팁·키보드 ESC 등 기존 V11 UI를 재사용했다.
- **일반화하면 안 되는 것:** 고양의 `10중첩/9중첩/5중첩` 로직, 승천/파멸의 바람 분기는 **고양·해당 빌드의 기술 사실**이고 다른 전문화의 필수 메커니즘이 아니다. **4개 표/43행/8개 장/중립 아이콘**도 범용 고정 형식이 아니다.
- **새 개발 불필요:** 이번 사용자 작업은 단일 HTML 직접 집필+검증으로 가능했다. 독립 앱·새 대형 JSON 생성기·정교한 경계조건 검증기 도입을 정당화하지 않는다.
- **여전히 미실증:** 특정 HTML 결과물 하나가 기존 V11 7개와 **사용자 평가상 동급 또는 더 우수**한지, 그리고 **여러 신규 전문화에 대해 반복 생산**했을 때 품질이 유지/개선되는지는 아직 확인되지 않았다.

## 4. 후속 우선순위

1. **이번 검토본을 사용자가 직접 열어 품질 평가**할 수 있게 제공(본 작업에서 채팅 파일로 전달). 최종 승인을 미리 추정하지 않음.
2. 기존 V11의 좋은 우선순위·팁·실전 정보 밀도와 신규 고양의 차이를 사용자가 지적한다면, **개별 오류 수정 후 범용 제작 원인**을 함께 분석한다.
3. 동적 오프너 선택 및 신규 중립 기호 대신 실제 주문 아이콘이 필요한 부분은 **확인 가능한 게임 원문/주문 이미지 근거**가 있을 때만 개선한다.
4. **반복된 근본 원인에만** 정책/도구를 보강하며, 소수 사례에 맞춘 포괄 새 시스템을 만들지 않는다.
